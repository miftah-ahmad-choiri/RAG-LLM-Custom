## Configuring bucket index resharding in multi-site deployments

Last Updated
: 2026-06-25

In multi-site deployments, each zone can have a different `index_pool`
setting to manage failover. To configure a consistent shard count for zones in one zone group, set
the `bucket_index_max_shards` parameter in the configuration for that zone
group.

The default value of `bucket_index_max_shards` parameter is 11.

You can set the parameter to one of the following values:

- `0` to disable bucket index sharding.
- A value greater than `0` to enable bucket sharding and to set the maximum number
of shards.

> 📝 **Note:** Note:
Mapping the index pool, for each zone, if applicable, to a CRUSH ruleset of SSD-based OSDs
might also help with bucket index performance. See
CRUSH performance domains

> 📝 **Note:** Important:
To prevent sync issues in multi-site deployments, a bucket should not have
more than three generation gaps.

### Prerequisites

- Two running IBM Storage Ceph clusters.
- A Ceph Object Gateway installed at a minimum of two sites.

### Procedure

1. Calculate the recommended number of shards:

```plaintext-ibm
number of objects expected in a bucket / 100,000
```

Copy to clipboard

> 📝 **Note:** Note:
The maximum number of bucket index shards currently supported is 65,521.
2. Extract the zone group configuration to the `zonegroup.json` file:

Example

```plaintext-ibm
[ceph: root@host01 /]# radosgw-admin zonegroup get > zonegroup.json
```

Copy to clipboard
3. In the `zonegroup.json` file, set the `bucket_index_max_shards`
parameter for each named zone:

Syntax

```plaintext-ibm
bucket_index_max_shards = VALUE
```

Copy to clipboard

Replace *VALUE* with the recommended number of shards calculated:

Example

```plaintext-ibm
bucket_index_max_shards = 12
```

Copy to clipboard
4. Reset the zone group:

Example

```plaintext-ibm
[ceph: root@host01 /]# radosgw-admin zonegroup set < zonegroup.json
```

Copy to clipboard
5. Update the period:

Example

```plaintext-ibm
[ceph: root@host01 /]# radosgw-admin period update --commit
```

Copy to clipboard
6. Check if resharding is complete:

Syntax

```plaintext-ibm
radosgw-admin reshard status --bucket BUCKET_NAME
```

Copy to clipboard

Example

```plaintext-ibm
[ceph: root@host01 /]# radosgw-admin reshard status --bucket data
```

Copy to clipboard

### Verification

- Check the sync status of the storage cluster:

Example

```plaintext-ibm
[ceph: root@host01 /]# radosgw-admin sync status
```

Copy to clipboard
