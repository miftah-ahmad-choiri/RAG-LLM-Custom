## Setting bi-directional policy for zonegroups

Last Updated
: 2026-06-25

Set the policy for zone groups bidirectionally with the sync policy engine.

### Before you begin

Before you begin setting bi-directional policies for zone groups, be sure to have at least two running
IBM Storage Ceph
clusters with Ceph Object Gateway configured on the same version.

### About this task

In the following example, create a group policy and define a data flow for the movement of data from one zonegroup to another. Configure a pipe for the zonegroups to define the buckets that can use this data flow. The system in the following examples includes 3 zones:
`us-east`
(the primary zone),
`us-west`
, and
`us-west-2`
.

Zonegroup sync policies are created with the new sync policy engine. Any change to the zonegroup sync policy requires a period update and a commit.

### Procedure

1. Create a sync group with the status set to
`allowed`
.

```plaintext-ibm
radosgw-admin sync group create --group-id=GROUP_ID --status=allowed
```

Copy to clipboard

For example,

```
ceph: root@host01 /]# radosgw-admin sync group create --group-id=group1 --status=allowed
```

> 📝 **Note:** Note:
Until a fully configured zonegroup replication policy is created, set the
`--status`
to
`allowed`
to prevent the replication from starting.
2. Create a flow policy for the newly created group with the
`--flow-type`
set as
`symmetrical`
to enable bidirectional replication.

```plaintext-ibm
radosgw-admin sync group flow create --group-id=GROUP_ID --flow-id=FLOW_ID --flow-type=symmetrical --zones=ZONE_NAMES
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# radosgw-admin sync group flow create --group-id=group1 --flow-id=flow-mirror --flow-type=symmetrical --zones=us-east,us-west
```
3. Create a pipe called
`pipe`
.

```plaintext-ibm
radosgw-admin sync group pipe create --group-id=GROUP_ID
                          --pipe-id=PIPE_ID --source-zones='*' \
                          --source-bucket='*' --dest-zones='*' \
                          --dest-bucket='*'
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# radosgw-admin sync group pipe create --group-id=group1 \
                          --pipe-id=pipe1 --source-zones='*' \
                          --source-bucket='*' --dest-zones='*' \
                          --dest-bucket='*'
```

> 📝 **Note:** Note:

Use the `*` wildcard for zones to include all zones set in the previous flow policy, and `*`for buckets to replicate all existing buckets in the zones.
4. Set the group policy
`--status`
to
`enabled`
.

```plaintext-ibm
radosgw-admin sync group modify --group-id=GROUP_ID --status=enabled
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# radosgw-admin sync group modify --group-id=group1 --status=enabled
```
5. Update and commit the new period.

```plaintext-ibm
radosgw-admin period update --commit
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# radosgw-admin period update --commit
```

> 📝 **Note:** Note:
Updating and committing the period is mandatory for a zonegroup policy.
6. **Optional:**
Check the sync source, and destination for a specific bucket. All buckets in
`us-east`
and
`us-west`
zones replicate bi-directionally.

```plaintext-ibm
radosgw-admin sync info --bucket=BUCKET_NAME
```

Copy to clipboard

The `id` field in the output reflects the pipe rule that generated that entry. A single rule can generate multiple sync entries as seen in the following example.
7. **Optional:**
Run the
sync info
command to retrieve information about the expected bucket sync sources and targets, as defined in the policy.

```plaintext-ibm
radosgw-admin sync info --bucket=BUCKET_NAME
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# radosgw-admin sync info --bucket=buck
{
    "sources": [
        {
            "id": "pipe1",
            "source": {
                "zone": "us-east",
                "bucket": "buck:115b12b3-....4409.1"
            },
            "dest": {
                "zone": "us-west",
                "bucket": "buck:115b12b3-....4409.1"
            },
            ...
        }
    ],
    "dests": [
        {
            "id": "pipe1",
            "source": {
                "zone": "us-west",
                "bucket": "buck:115b12b3-....4409.1"
            },
            "dest": {
                "zone": "us-east",
                "bucket": "buck:115b12b3-....4409.1"
            },
           ...
        }
    ],
    ...
}
```
