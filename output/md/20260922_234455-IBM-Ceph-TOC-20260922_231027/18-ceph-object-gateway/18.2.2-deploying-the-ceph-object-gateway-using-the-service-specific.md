## Deploying the Ceph Object Gateway using the service specification

Last Updated
: 2026-09-09

Deploy the Ceph Object Gateway using the service specification with either the default or the custom realms, zones, and zone groups.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph cluster.
- Root-level access to the bootstrapped host.
- Hosts are added to the cluster.
- All Ceph Manager, Ceph Monitor, and Object Storage Daemon (OSD) daemons are deployed.

### Procedure

1. Create a specification file.

```plaintext-ibm
touch rgw_spec.yaml
```

Copy to clipboard

For example,

```
[root@host01 ~]# touch rgw_spec.yaml
```
2. Configure S3 requests to wait for the duration defined in the
rgw_exit_timeout_secs
parameter for all outstanding requests to complete by setting
rgw_graceful_stop
to
`true`
during Ceph Object Gateway shutdown or restart.

```plaintext-ibm
ceph config set client.rgw rgw_graceful_stop true

ceph config set client.rgw rgw_exit_timeout_secs 120
```

Copy to clipboard

> 📝 **Note:** Important:
In containerized deployments, an additional
`extra_container_args`
configuration of
`--stop-timeout=120`
(or the value of the
rgw_exit_timeout_secs
configuration, if not default) is also necessary in order for it to work as expected with the
ceph orch stop
or
ceph orch restart
commands.
For example,

```
[root@host1 ~]$ cat rgw_spec.yaml
service_type: rgw
service_id: foo
placement:
  count_per_host: 1
  hosts:
    - rgw_node
spec:
  rgw_frontend_port: 8081
extra_container_args:
  - "--stop-timeout=120"
```
3. Edit the
rgw_spec.yaml
file to include the details for the default realm, zone, and zone group.

```plaintext-ibm
service_type: rgw
service_id: REALM_NAME.ZONE_NAME
placement:
  hosts:
  - HOST_NAME_1
  - HOST_NAME_2
  count_per_host: NUMBER_OF_DAEMONS
spec:
  rgw_realm: REALM_NAME
  rgw_zone: ZONE_NAME
  rgw_zonegroup: ZONE_GROUP_NAME
  rgw_frontend_port: FRONT_END_PORT

networks:
  -  NETWORK_CIDR
```

Copy to clipboard

The NUMBER_OF_DAEMONS parameter controls the number of Ceph Object Gateways deployed on each host. To achieve the highest performance without incurring an additional cost, set this value to `2`.

For example,

```
service_type: rgw
service_id: default
placement:
  hosts:
  - host01
  - host02
  - host03
  count_per_host: 2
spec:
  rgw_realm: default
  rgw_zone: default
  rgw_zonegroup: default
  rgw_frontend_port: 1234

networks:
  - 192.169.142.0/24
```
4. **Optional:**
Configure custom realm, zone, and zone group.

1. Create the custom realm, zone, and zone group.

```plaintext-ibm
radosgw-admin realm create --rgw-realm=test_realm --default
radosgw-admin zonegroup create --rgw-zonegroup=test_zonegroup --default
radosgw-admin zone create --rgw-zonegroup=test_zonegroup --rgw-zone=test_zone --default
radosgw-admin period update --rgw-realm=test_realm --commit
```

Copy to clipboard

For example,

```
[root@host01 ~]# radosgw-admin realm create --rgw-realm=test_realm --default
[root@host01 ~]# radosgw-admin zonegroup create --rgw-zonegroup=test_zonegroup --default
[root@host01 ~]# radosgw-admin zone create --rgw-zonegroup=test_zonegroup --rgw-zone=test_zone --default
[root@host01 ~]# radosgw-admin period update --rgw-realm=test_realm --commit
```
2. Create the
rgw_spec.yaml
file with the custom details.
For example,

```
service_type: rgw
service_id: test_realm.test_zone
placement:
  hosts:
  - host01
  - host02
  - host03
  count_per_host: 2
spec:
  rgw_realm: test_realm
  rgw_zone: test_zone
  rgw_zonegroup: test_zonegroup
  rgw_frontend_port: 1234
networks:
  - 192.169.142.0/24
```

  1. Create the custom realm, zone, and zone group.

  ```plaintext-ibm
  radosgw-admin realm create --rgw-realm=test_realm --default
  radosgw-admin zonegroup create --rgw-zonegroup=test_zonegroup --default
  radosgw-admin zone create --rgw-zonegroup=test_zonegroup --rgw-zone=test_zone --default
  radosgw-admin period update --rgw-realm=test_realm --commit
  ```



  Copy to clipboard

  For example,

  ```
  [root@host01 ~]# radosgw-admin realm create --rgw-realm=test_realm --default
  [root@host01 ~]# radosgw-admin zonegroup create --rgw-zonegroup=test_zonegroup --default
  [root@host01 ~]# radosgw-admin zone create --rgw-zonegroup=test_zonegroup --rgw-zone=test_zone --default
  [root@host01 ~]# radosgw-admin period update --rgw-realm=test_realm --commit
  ```
  2. Create the
  rgw_spec.yaml
  file with the custom details.
  For example,

  ```
  service_type: rgw
  service_id: test_realm.test_zone
  placement:
    hosts:
    - host01
    - host02
    - host03
    count_per_host: 2
  spec:
    rgw_realm: test_realm
    rgw_zone: test_zone
    rgw_zonegroup: test_zonegroup
    rgw_frontend_port: 1234
  networks:
    - 192.169.142.0/24
  ```
5. **Optional:**
Deploy the HAProxy concentrator for local Ceph Object Gateway load balancing.
To load balance requests across Ceph Object Gateway daemons on the same host, configure the service with a local HAProxy concentrator.

> 📝 **Note:** Note:
The HAProxy concentrator does not currently support SSL.

> 📝 **Note:** Note:
Use this configuration only when
`count_per_host > 1`
.

For example,

```
service_type: rgw
service_id: foo
service_name: rgw.foo
placement:
  count_per_host: 2
  hosts:
    - host1
    - host2
spec:
  concentrator: haproxy
  concentrator_frontend_port: 8080
  concentrator_monitor_port: 1967
  concentrator_monitor_user: admin
```
6. Mount the
rgw_spec.yaml
file under a directory in the container.

```plaintext-ibm
cephadm shell --mount rgw_spec.yaml:/var/lib/ceph/radosgw/rgw_spec.yaml
```

Copy to clipboard

For example,

```
[root@host01 ~]# cephadm shell --mount rgw_spec.yaml:/var/lib/ceph/radosgw/rgw_spec.yaml
```

> 📝 **Note:** Important:
Every time you exit the shell, you must mount the file in the container before deploying the daemon.
7. Deploy the Ceph Object Gateway by using the service specification.

```plaintext-ibm
ceph orch apply -i FILE_NAME.yaml
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph orch apply -i /var/lib/ceph/radosgw/rgw_spec.yaml
```

### Results

Verify that the Ceph Object Gateway service is deployed successfully:

- List the service:

```plaintext-ibm
ceph orch ls
```

Copy to clipboard
- List the hosts, daemons, and processes:

```plaintext-ibm
ceph orch ps --daemon_type=DAEMON_NAME
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph orch ps --daemon_type=rgw
```
