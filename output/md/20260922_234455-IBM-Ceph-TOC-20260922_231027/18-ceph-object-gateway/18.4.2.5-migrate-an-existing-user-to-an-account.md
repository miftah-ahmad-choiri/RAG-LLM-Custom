## Migrate an existing user to an account

Last Updated
: 2026-09-09

Migrate an existing IAM user to a Ceph Object Gateway account by using the radosgw-admin user modify command.

When you create a role associated with a Ceph Object Gateway account, you can list it by using the radosgw-admin role list command with the --account-id parameter.

To modify an existing user IAM account:

```plaintext-ibm
radosgw-admin user modify --uid=USER_ID --account-id=ACCOUNT_ID
```

Copy to clipboard

> 📝 **Note:** Important:

- The migration transfers ownership of all the user's buckets to the Ceph Object Gateway account.
- Account membership is permanent. Once added, you cannot remove users from their account.
- The migration does not transfer ownership of the user's notification topics to the account. Notifications continue to work, but the topics are no longer visible to SNS Topic APIs.

Because account users have no permissions by default, you must add an identity policy to restore the user's original permissions. Alternatively, you can create a new account for each existing user and use the --account-root parameter to make each user the root user of their account.

### Migrating notification topics

Account topics are supported only when the `notification_v2` feature is enabled.

Migration impact
When a non-account user is migrated to an account, the existing notification topics remain accessible through the Ceph Object Gateway admin API, but the user loses access to them through the SNS Topic API. Despite this, the topics remain functional, and bucket notifications will continue to be delivered as expected.
Re-creation of topics
The account user must re-create the topics using the same names. The old topics (now inaccessible) and the new account-owned topics coexist without interference.
Updating bucket notification configurations
Buckets that are subscribed to the old user-owned topics must be updated to use the new account-owned topics. To prevent duplicate notifications, maintain the same notification IDs.

For example, if a bucket's existing notification configuration is:

```
{"TopicConfigurations": [{ "Id": "ID1", "TopicArn": "arn:aws:sns:default::topic1", "Events": ["s3:ObjectCreated:*"]}]}
```

The updated configuration would be:

```
{"TopicConfigurations": [{ "Id": "ID1", "TopicArn": "arn:aws:sns:default:RGW00000000000000001:topic1", "Events": ["s3:ObjectCreated:*"]}]}
```

In this example, `RGW00000000000000001` is the account ID, `topic1` is the topic name, and `ID1` is the notification ID.

Removing old topics

Once no buckets are subscribed to the old user-owned topics, they can be removed by an administrator:

```plaintext-ibm
radosgw-admin topic rm --topic topic1
```

### Migrating users from non-account to Ceph Object Gateway accounts

When migrating a user from a non-account to a Ceph Object Gateway (`rgw`) account, use the following steps to ensure a seamless I/O migration and appropriate IAM configuration.

1. Assign the --account-root flag during user migration. Ensure that the --account-root flag is added when migrating the user to an account. This grants the user the necessary privileges for migration.

```plaintext-ibm
radosgw-admin user modify --uid USER_ID --account-id ACCOUNT_ID --account-root
```

Copy to clipboard
2. Attach S3 access policy. After migrating the user, attach the appropriate IAM policy to grant the user S3 access. In the following example, the `AmazonS3FullAccess` policy is assigned.

```plaintext-ibm
radosgw-admin user policy attach --uid USER_ID --policy-arn arn:aws:iam::aws:policy/AmazonS3FullAccess
```

Copy to clipboard
3. Remove the --account-root privilege. After the migration and granting necessary access, remove the --account-root privilege from the user to limit the scope of their permissions.

```plaintext-ibm
radosgw-admin user modify --uid USER_ID --account-root=0
```
