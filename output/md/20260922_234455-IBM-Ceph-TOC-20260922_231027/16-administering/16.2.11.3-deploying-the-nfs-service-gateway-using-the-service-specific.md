## Deploying the NFS service gateway using the service specification

Last Updated
: 2026-07-23

You can use the Ceph Orchestrator with `cephadm` in the backend to deploy the NFS service gateway using the service specification. In this case, you have to create a RADOS pool and create a namespace before deploying the gateway.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph cluster.
- Hosts are added to the cluster.

### Procedure

1. Create the
`nfs.yaml`
file.
For example,

```
[root@host01 ~]# touch nfs.yaml
```
2. Edit the
nfs.yaml
specification file.

```plaintext-ibm
service_type: nfs
service_id: SERVICE_ID
placement:
  hosts:
    - HOST_NAME_1
    - HOST_NAME_2
```

Copy to clipboard

For example,

```
service_type: nfs
service_id: foo
placement:
  hosts:
    - host01
    - host02
```

- Optional: Enable the NLM to support locking for NFS protocol v3 support by adding `enable_nlm: true` in the NFS.yaml specification file.

```plaintext-ibm
service_type: nfs
service_id: SERVICE_ID
placement:
  hosts:
    - HOST_NAME_1
    - HOST_NAME_2
spec:
    enable_nlm: true
```

3. Mount the YAML file under a directory in the container.

```plaintext-ibm
cephadm shell --mount nfs.yaml:/var/lib/ceph/nfs.yaml
```

Copy to clipboard

For example,

```
[root@host01 ~]# cephadm shell --mount nfs.yaml:/var/lib/ceph/nfs.yaml
```
4. Create the RADOS pool, namespace, and enable RBD.

```plaintext-ibm
ceph osd pool create POOL_NAME
ceph osd pool application enable POOL_NAME rbd
rbd pool init -p POOL_NAME
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph osd pool create nfs-pool
[ceph: root@host01 /]# ceph osd pool application enable nfs-pool rbd
[ceph: root@host01 /]# rbd pool init -p nfs-pool
```
5. Navigate to the directory.
For example,

```
[ceph: root@host01 /]# cd /var/lib/ceph/
```
6. Deploy NFS service gateway using service specification.

```plaintext-ibm
ceph orch apply -i FILE_NAME.yaml
```

Copy to clipboard

For example,

```
[ceph: root@host01 ceph]# ceph orch apply -i nfs.yaml
```

### What to do next

- List the service, by using the ceph orch ls command.

```

```
- List the hosts, daemons, and processes.

```plaintext-ibm
ceph orch ps --daemon_type=DAEMON_NAME
```

```

```

### Deploying NFS with idmap settings

#### About this task

idmap.conf settings can be updated manually under/var/lib/ceph/FSID/NFS-Daemon/etc/ganesha/idmap.conf but when the cluster is upgraded, the file contents get deleted.

Use this procedure to keep the NFS `idmap` settings persistent across upgrades.

#### Procedure

1. Edit the
nfs.yaml
specification file.
Add
`idmap_conf`
information to the specification file.

```plaintext-ibm
service_type: nfs
service_id: nfsganesha
placement:
  hosts:
    - example0
    - example1
    - example2
spec:
  idmap_conf:
    general:
      Domain: domain.org
    mapping:
      Nobody-Group: nfsnobody
      Nobody-User: nfsnobody
```

Copy to clipboard
2. Apply the specification file.

```plaintext-ibm
ceph orch apply -i FILE_NAME.yaml
```

Copy to clipboard
3. Redeploy the NFS daemons.

```plaintext-ibm
ceph orch redeploy nfs.nfsganesha
```
