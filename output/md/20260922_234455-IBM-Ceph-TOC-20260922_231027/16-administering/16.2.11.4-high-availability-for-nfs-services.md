## High availability for NFS services

Last Updated
: 2026-06-25

High availability for NFS service enables failover and recovery mechanisms that preserve the stateful nature of the NFS protocol and ensure continued access to file shares.

Network File System (NFS) is a stateful protocol. High availability configurations must maintain state information for every connected NFS client and support recovery in case of failures.

If an NFS server fails, the system attempts to recover the instance on the same node (if available) or on another node labeled for NFS service. Once the server restarts, client recovery is initiated using internal state tracking mechanisms.

> 📝 **Note:** Note:
I/O operations might be interrupted during server recovery, but clients do not receive I/O errors unless the server cannot restart.

### NFS server gateways

You can deploy NFS in two modes: multi-active (HA) and active-passive.
Active-passive
A single NFS server runs with ingress but only in Keepalived mode. This mode is suitable for simple or low-availability setups.
Multi-active (HA)
Multiple NFS servers run behind an ingress service for load balancing and failover. Specify a virtual IP address to deploy HAProxy and
`keepalived`
, which provide a high-availability NFS front end.

### Multi-active NFS servers

In multi-active configuration, multiple HAProxy/NFS instances are simultaneously active and serve client requests.

- Multiple NFS server instances run simultaneously across different nodes.
- Each server can independently serve client requests.
- Typically, one NFS server instance runs per node to ensure resource isolation and high availability.

> 📝 **Note:** Note:

- Ensure that NFS is configured with a placement count.
- For multi-active deployments, both the NFS service and the ingress service must be configured by using a specification file.

### Active-passive NFS server

In an active-passive configuration, only one gateway node is active, while another remains in standby and takes over during failure.

- Single active keepalived/NFS instance
- Standby node monitored via Keepalived
- VIP moves automatically to standby during failure
