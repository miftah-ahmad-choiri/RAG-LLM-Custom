## Replacing the OSDs

Last Updated
: 2026-06-25

When disks fail, you can replace the physical storage device and reuse the same OSD ID to avoid having to reconfigure the CRUSH map.

You can replace the OSDs from the cluster by preserving the OSD ID using the
ceph orch rm
command.

> 📝 **Note:** Note:
If you want to replace a single OSD,
Deploying Ceph OSDs on specific devices and hosts
. If you want to deploy OSDs on all available devices,
Deploying Ceph OSDs on all available devices
.

The OSD is not permanently removed from the CRUSH hierarchy, but is assigned the
`destroyed`
flag. This flag is used to determine the OSD IDs that can be reused in the next OSD deployment. The
`destroyed`
flag is used to determine which OSD id is reused in the next OSD deployment.

If you use OSD specification for deployment, your newly added disk is assigned the OSD ID of their replaced counterparts.

### Prerequisites

- A running IBM Storage Ceph cluster.
- Hosts are added to the cluster.
- Monitor, Manager, and OSD daemons are deployed on the storage cluster.

### Procedure

1. Log into the `cephadm` shell:

Example

```plaintext-ibm
[root@host01 ~]# cephadm shell
```

Copy to clipboard
2. Check the device and the node from which the OSD has to be replaced:

Example

```plaintext-ibm
[ceph: root@host01 /]# ceph osd tree
```

Copy to clipboard
3. Set the OSD service specification to
unmanaged
state:

> 📝 **Note:** Note:
Set the
unmanaged
parameter to
`true`
in the OSD service specification before removal. If you skip this step,
`cephadm `
may automatically redeploy OSDs, causing conflicts between orchestrator-driven deployment and OSD removal.

Example

```plaintext-ibm
service_type:osd
service_id:<service_id>
unmanaged:true
```

Copy to clipboard
4. Apply the updated specification:

```plaintext-ibm
ceph orch apply -i <osds.yaml>
```

Copy to clipboard
5. Run theorch ls cephcommand to confirm that the OSD service is set to the unmanaged state.
6. Replace the OSD:

> 📝 **Note:** Important:
If the storage cluster has
health_warn
or other errors associated with it, check and try to fix any errors before replacing the OSD to avoid data loss.

Syntax

```plaintext-ibm
ceph orch osd rm OSD_ID --replace
```

Copy to clipboard

Example

```plaintext-ibm
[ceph: root@host01 /]# ceph orch osd rm 0 --replace
```

Copy to clipboard
7. Check the status of the OSD replacement:

Example

```plaintext-ibm
[ceph: root@host01 /]# ceph orch osd rm status
```

Copy to clipboard
8. Set the OSD service specification back to managed state. After you replace the disk, set the OSD service back to a managedstate so that `cephadm` can resume orchestration.

1. Update the OSD service specification.

```plaintext-ibm
unmanaged: false
```

Copy to clipboard
2. Apply the updated specification. This step allows `cephadm` to redeploy the OSD on the new device while reusing the existing OSD ID.

```plaintext-ibm
ceph orch apply -i <osds.yaml>
```

Copy to clipboard

  1. Update the OSD service specification.

  ```plaintext-ibm
  unmanaged: false
  ```



  Copy to clipboard
  2. Apply the updated specification. This step allows `cephadm` to redeploy the OSD on the new device while reusing the existing OSD ID.

  ```plaintext-ibm
  ceph orch apply -i <osds.yaml>
  ```



  Copy to clipboard

### Verification

- Verify the details of the devices and the nodes from which the Ceph OSDs are replaced:

Example

```plaintext-ibm
[ceph: root@host01 /]# ceph osd tree
```

Copy to clipboard

You will see an OSD with the same id as the one you replaced running on the same host.
