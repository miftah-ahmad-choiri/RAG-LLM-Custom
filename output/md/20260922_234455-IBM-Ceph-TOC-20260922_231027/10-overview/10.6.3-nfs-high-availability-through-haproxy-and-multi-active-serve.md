## NFS high availability through HAProxy and multi-active servers

Last Updated
: 2026-09-06

Ceph supports high availability (HA) for Network File System (NFS) services by using HAProxy as a front-end load balancer for multiple-active NFS server instances.

HAProxy uses a virtual IP (VIP) to route client requests to healthy servers. Ceph ensures that each server runs on a separate host, but if no spare host is available, then it accommodates the failed server on one of the existing hosts. If a server fails, Ceph automatically restarts the failed service on a new/existing host using the same server identity. This approach allows connected clients to continue operations without disruption.

### NFS high availability architecture

IBM Storage Ceph achieves high availability for NFS services by combining HAProxy and Keepalived. HAProxy acts as a front-end load balancer that routes client requests to healthy NFS servers and maintains session persistence for the stateful NFS protocol. Keepalived provides high availability for HAProxy by managing a VIP, continuously monitoring HAProxy instances, and shifting the VIP between hosts when failures occur.

Figure 1.
NFS high availability architectural workflow

Ceph implements high availability for NFS services through VIP-based client access, HAProxy load balancing, and Keepalived failover.
Client access through VIP
Clients mount NFS shares using a single VIP instead of individual server IPs. Keepalived hosts the VIP and can move it between hosts during failover.
HAProxy load balancing
HAProxy receives client requests on the VIP and forwards them to backend NFS servers based on health checks and load-balancing algorithms.
Keepalived failover
If the active HAProxy instance fails, Keepalived detects the failure and transfers the VIP to a standby host. This ensures continuous service availability without client-side changes.

This architecture ensures uninterrupted client access to NFS shares even during host or service failures.

> 📝 **Note:** Note:

- HAProxy instances synchronize in-memory stick tables across the cluster to preserve client session state during failover.
- As NFS is a stateful protocol, HAProxy needs to maintain state information for every connected NFS client. If an NFS server fails, Ceph attempts to recover the instance on the same host, if available, or on another host labeled for NFS service.

### Fault tolerance and placement count

Fault tolerance is the ability of a system to continue operating correctly even when one or more components fail. The NFS high-availability mechanism relies on `cephadm` to start the failed NFS server on (new / existing host) to maintain service continuity.

With no spare host
The number of hosts equals the placement count.

For example, if you configure 3 hosts and set the placement count to 3, all hosts are active initially. If one host fails, there is no spare host. In this case `cephadm` starts the failed NFS server on one of the host where another NFS server is running.

With spare hosts
The number of hosts is higher than the placement count.

For example, if you configure 5 hosts and set the placement count to 3, three hosts run active NFS servers, and two hosts remain as spares. If one or two active hosts fail, the service can restart on the spare hosts, ensuring fault tolerance.

### Key features

Key features of NFS high availability include high availability and failover through HAProxy, virtual IP, and access management and security.

High availability and failover through HAProxy
HAProxy monitors the health of backend NFS servers and reroutes traffic to healthy instances in case of failure. VIP and heartbeat mechanisms enable seamless failover.
VIP
HAProxy uses a VIP to provide a consistent access point for clients. The VIP dynamically switches between active and standby nodes during failover, requiring no client-side changes.
Access management and security
HAProxy supports IP-based access control, authentication, rate limiting, and traffic filtering using Access Control Lists (ACLs) to enhance security.

### Use cases for HAProxy with NFS

Use cases for deploying HAProxy with NFS on CephFS include high availability for NFS shares and failover for storage services.

High availability for NFS shares
HAProxy ensures NFS clients always connect to an available NFS server, preventing service disruptions.
Failover for storage services
If a server fails, HAProxy detects the issue and reroutes traffic to a healthy instance.
