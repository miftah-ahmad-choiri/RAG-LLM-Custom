## Configuring the NVMe-oF initiator for VMware ESXi

Last Updated
: 2026-06-25

Configure the NVMe-oF initiator for VMware vSphere Hypervisor (ESXi). You can set up a VMware ESXi host as a NVMe/TCP initiator.

### Before you begin

- A VMware ESXi host that is running VMware vSphere Hypervisor (ESXi) 7.0U3 version or later.
- Ceph NVMe-oF gateway deployed.
- IBM Storage Ceph cluster and `ceph-nvmeof` configurations are ready and working correctly.
- A subsystem defined within the gateway. For more information, see Defining an NVMe-oF subsystem with nvmeof-cli.
- NVMe/TCP adapter is configured.

- Enabled NVMe/TCP on a physical network interface controller (NIC).

```plaintext-ibm
esxcli nvme fabrics enable --protocol TCP --device vmnicN
```

Copy to clipboard

              Replace N with the number of NIC.
- Tag a VMkernel NIC to allow NVMe/TCP traffic.

```plaintext-ibm
esxcli network ip interface tag add --interface-name vmkN --tagname NVMeTCP
```

              Replace N with the ID of the VMkernel.

### About this task

NVMe/TCP supports VMware vSphere Hypervisor (ESXi) 7.0U3 or later.

> 📝 **Note:** Note:
The NVMe-oF gateway supports VMware vSphere APIs (VAAI).

### Procedure

Configuring the VMware ESXi host for NVMe/TCP transport includes discovering the NVMe/TCP targets and connecting to them.

1. List the NVMe-oF adapter.

```plaintext-ibm
esxcli nvme adapter list
```

Copy to clipboard

For example,

```
[root@host01:~] esxcli nvme adapter list
Adapter  Adapter Qualified Name           Transport Type  Driver     Associated Devices
-------  -------------------------------- --------------  ---------  ------------------
vmhba64  aqn:nvmetcp:ac-1f-6b-0a-18-74-T  TCP             nvmetcp    vmnic0
```
2. **Optional:**
Discover any NVMe-oF-gateway subsystems.

> 📝 **Note:** Note:
Use this command to discover a subsystem without connecting. To discover and connect, go to step
3
.

```plaintext-ibm
esxcli nvme fabrics discover -a NVME_TCP_ADAPTER -i GATEWAY_IP -p 8009
```

Copy to clipboard

For example,

```
[root@host01:~] esxcli nvme fabrics discover -a vmhba64 -i 10.0.211.196 -p 8009

Transport Type Address Family Subsystem Type Controller ID Admin Queue Max Size Transport Address Transport Service ID Subsystem NQN              Connected
-------------- -------------- -------------- ------------- -------------------- ----------------- -------------------- -------------------------- ---------
TCP            IPv4           NVM            65535         128                   10.0.211.196     8009                 nqn.2016-06.io.spdk:cnode1.group1   false
```
3. Connect to the NVMe-oF gateway subsystem.
This command discovers the NVMe-oF gateways in the gateway group and then connects to the gateways.

```plaintext-ibm
esxcli nvme fabrics discover -a NVME_TCP_ADAPTER -i GATEWAY_IP -p 8009 -c
```

Copy to clipboard

> 📝 **Note:** Note:
In cases that a specific connection is required without discovering all of the available gateways, run the
nvme fabrics connect
command.

```plaintext-ibm
esxcli nvme fabrics connect -a NVME_TCP_ADAPTER -i GATEWAY_IP -s SUBSYSTEM_NQN -p 8009
```

Copy to clipboard

```
[root@host01:~] esxcli nvme fabrics connect -a vmhba64 -i 10.0.211.196 -s nqn.2016-06.io.spdk:cnode1.group1  -p 8009
```

To verify, use the
nvme controller list
command.

```plaintext-ibm
esxcli nvme controller list |grep TCP
```

Copy to clipboard

Check that the new connection is listed and marked as
true
.

For example,

```
[root@host01:~] esxcli nvme fabrics discover -a vmhba64 -i 10.0.211.196 -p 8009 -c

Transport Type Address Family Subsystem Type Controller ID Admin Queue Max Size Transport Address Transport Service ID Subsystem NQN              Connected
-------------- -------------- -------------- ------------- -------------------- ----------------- -------------------- -------------------------- ---------
TCP            IPv4           NVM            65535         128                   10.0.211.196     8009                 nqn.2016-06.io.spdk:cnode1.group1   true
```
4. List NVMe/TCP controller list.

```plaintext-ibm
esxcli nvme controller list
```

Copy to clipboard

```
[root@host01:~] esxcli nvme controller list
Name                                                            Controller Number  Adapter  Transport Type  Is Online  Is VVOL
--------------------------------------------------------------  -----------------  -------  --------------  ---------  -------
nqn.2014-08.org.nvmexpress.discovery#vmhba65#10.0.211.196:8009                257  vmhba65  TCP                  true    false
nqn.2016-06.io.spdk:cnode1.group1 #vmhba65#10.0.211.196:4420                          258  vmhba65  TCP                  true    false                                                      301  vmhba64  TCP                  true
```
5. List NVMe-oF namespaces in the subsystem.

```plaintext-ibm
esxcli nvme namespace list
```

Copy to clipboard

For example,

```
[root@host01:~] esxcli nvme namespace list
Name                                Controller Number  Namespace ID  Block Size  Capacity in MB
------------------                  -----------------  ------------  ----------  --------------
eui.0100000001000000e4d25c00001ae214               256             1         512          953869
eui.01abc123def456g7e4d25c00001ae214               301             1         512             500
eui.02abc123def456g7e4d25c00001ae215               301             2         512             500
eui.03abc123def456g7e4d25c00001ae216               301             3         512             500
```

> 📝 **Note:** Important:
Namespaces might not be visible if an initiator is connected to two different gateway groups with the same NQN.

### What to do next

Verify that the initiator is set up correctly.

1. From the vSphere Client, go to the ESXi host.
2. On the Storage page, go to the Devices tab.
3. Verify that the NVMe/TCP disks are listed in the table.

For information about using NVMe namespaces in ESX, such as creating and managing datastores, see [IBM Storage Ceph Plugin for vSphere documentation](http://www.ibm.com/docs/ceph-plugin-vsphere).
