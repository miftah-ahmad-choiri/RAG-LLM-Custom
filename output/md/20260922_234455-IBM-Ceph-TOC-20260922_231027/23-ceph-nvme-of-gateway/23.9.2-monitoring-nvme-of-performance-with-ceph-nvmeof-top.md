## Monitoring NVMe-oF performance with ceph nvmeof top

Last Updated
: 2026-06-25

Monitor real-time CPU utilization and I/O performance for NVMe-oF gateways, subsystems, and namespaces.

The `ceph nvmeof top` commands provide a “
top
”-style, refresh-based view of NVMe-oF gateway performance. Use these commands to observe CPU usage on gateway nodes and I/O activity at the subsystem and namespace level.

The following are the current available ceph nvmeof top commands to use for monitoring.

`ceph nvmeof top cpu`
Monitors CPU utilization for NVMe-oF gateway threads. For more information, see
Monitoring gateway CPU utilization
.
`ceph nvmeof top io`
Monitors I/O performance for namespaces within an NVMe-oF subsystem. For more information, see
Monitoring subsystem and namespace I/O performance
.

### Monitoring gateway CPU utilization

Use the `ceph nvmeof top cpu` command to monitor CPU usage across NVMe-oF gateway nodes. By default, the command displays CPU statistics for all gateways in the service. Table 1 details the different available syntax options.

```plaintext-ibm
ceph nvmeof top cpu [--server-address ADDRESS]
                    [--server-port PORT]
                    [--gw-group GROUP]
                    [--sort-by COLUMN]
                    [--descending]
                    [--period SECONDS]
                    [--with-timestamp]
                    [--no-header]
```

Copy to clipboard

| Parameter | Value | Default | Description |
| --- | --- | --- | --- |
| --server-address | IP address | All gateways | Limits the output to CPU statistics reported by a single NVMe-oF gateway. If not specified, CPU statistics are shown for all gateways in the service. |
| --server-port | Port number | 5500 | Specifies the management port used to communicate with the NVMe-oF gateway. |
| --gw-group | Gateway group name | Current group | Specifies the gateway group to monitor. This parameter is required when multiple NVMe-oF gateway groups exist. |
| --sort-by | Column name | Thread name | Sorts the output by the specified column. Valid values correspond to the output column headers, such as Busy rate (%) or Idle rate (%). |
| --descending | Flag - none | Ascending order | Sorts the output in descending order based on the selected sort-by column. |
| --period | Seconds (1–3600) | 1 | Specifies the refresh interval, in seconds, between successive samples of CPU statistics. |
| --with-timestamp | Flag - none | Disabled | Prefixes each refresh of the output with a timestamp and the elapsed time since the previous sample. |
| --no-header | Flag - none | Headers shown | Suppresses the column headers in the output. This option is useful when the output is redirected to a file or processed by scripts. |

### Monitoring subsystem and namespace I/O performance

Use the `ceph nvmeof top io` command to monitor I/O statistics for namespaces within an NVMe-oF subsystem. The subsystem NQN is required. Table 3 details the different available syntax options.

```plaintext-ibm
ceph nvmeof top io --nqn SUBSYSTEM_NQN
                   [--server-address ADDRESS]
                   [--server-port PORT]
                   [--gw-group GROUP]
                   [--sort-by COLUMN]
                   [-descending]
                   [--summary]
                   [--period SECONDS]
                   [--with-timestamp]
                   [--no-header]
```

Copy to clipboard

| Parameter | Value | Default | Description |
| --- | --- | --- | --- |
| --nqn | Subsystem NQN | None | Specifies the NVMe-oF subsystem for which namespace I/O statistics are displayed. This parameter is required. |
| --server-address | IP address | All gateways | Limits the output to namespaces optimized on the specified NVMe-oF gateway. If not specified, namespace statistics are aggregated across gateways. |
| --server-port | Port number | 5500 | Specifies the management port used to communicate with the NVMe-oF gateway. |
| --gw-group | Gateway group name | Current group | Specifies the gateway group that hosts the subsystem. This parameter is required when multiple NVMe-oF gateway groups exist. |
| --sort-by | Column name | NSID | Sorts the output by the specified column. Valid values correspond to the output column headers, such as IOPS or rMB/s. |
| --descending | Flag - none | Ascending order | Sorts the output in descending order based on the selected sort-by column. |
| --summary | Flag - none | Disabled | Displays aggregated I/O statistics for the subsystem. When combined with a server address, the output reflects gateway- level aggregation. |
| --period | Seconds (1–3600) | 1 | Specifies the refresh interval, in seconds, between successive samples of namespace I/O statistics. |
| --with-timestamp | Flag - none | Disabled | Prefixes each refresh of the output with a timestamp and the elapsed time since the previous sample. |
| --no-header | Flag - none | Headers shown | Suppresses the column headers in the output. This option is useful when the output is redirected to a file or processed by scripts. |

The following is an example output. Table 4 describes the available output fields.

```
[root@host01 ~]# ceph nvmeof top io --nqn nqn.2016-06.io.spdk:cnode1.mygroup1

NSID  RBD Image        IOPS r/s rMB/s r_await rareq-sz w/s wMB/s w_await wareq-sz LBGrp QoS
   1  nvmeof/myimage1  61   61  0.72  0.65    12.17    0   0.00  0.00    0.00     1     No
   2  nvmeof/myimage2  61   61  0.72  0.67    12.17    0   0.00  0.00    0.00     2     No
   3  nvmeof/myimage3  61   61  0.72  0.53    12.17    0   0.00  0.00    0.00     1     No
```

| Field | Description |
| --- | --- |
| NSID | Namespace identifier within the subsystem. |
| RBD Image | Ceph Block Device image backing the namespace. |
| IOPS | Total input/output operations per second. |
| r/s, w/s | Read and write operations per second. |
| rMB/s, wMB/s | Read and write throughput in megabytes per second. |
| r_await, w_await | Average read and write latency. |
| rareq-sz, wareq-sz | Average size of read and write requests in KB. |
| LBGrp | Load-balancing group currently serving the namespace. |
| QoS | Indicates whether Quality of Service limits are applied. |
