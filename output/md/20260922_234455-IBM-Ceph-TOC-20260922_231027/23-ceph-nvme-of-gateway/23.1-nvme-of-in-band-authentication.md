## NVMe‑oF in‑band authentication

Last Updated
: 2026-09-06

Understand how the NVMe‑oF gateway uses DH‑HMAC‑CHAP in‑band authentication to control access between hosts and NVMe‑oF subsystems.

> 📝 **Note:** Note:
DH-HMAC-CHAP authentication requires Linux kernel version 6.0.0 or later. Earlier kernel versions, such as Ubuntu 5.15.0-82-generic do not support the required
dhchap_secret
option.

The Ceph NVMe‑oF gateway uses in‑band authentication to prevent unauthorized access from unknown initiators. Authentication is performed by using DH‑HMAC‑CHAP and supports both unidirectional and bidirectional authentication models.

In unidirectional authentication, the target verifies the initiator. In bidirectional authentication, both the initiator and the target verify each other by using authentication keys.

> 📝 **Note:** Important:
Subsystem‑level and controller‑level DH‑HMAC‑CHAP keys are mutually exclusive. If a subsystem has a DHCHAP key defined, controller‑level keys cannot be defined for hosts in that subsystem. If one or more hosts have controller‑level keys defined, defining or changing a subsystem‑level key is not allowed. Operations that violate these constraints fail.

### Authentication key scope

DH‑HMAC‑CHAP authentication keys define how authentication is applied for hosts accessing a subsystem.

Authentication keys can be defined at different scopes, allowing administrators to choose between simplified configuration and per‑host isolation.

Subsystem scope
A key defined on a subsystem applies to all controllers created for hosts that access the subsystem.
Controller (host) scope
A key defined for a specific host applies only to the controller created for that host, enabling unique authentication per host connection.
