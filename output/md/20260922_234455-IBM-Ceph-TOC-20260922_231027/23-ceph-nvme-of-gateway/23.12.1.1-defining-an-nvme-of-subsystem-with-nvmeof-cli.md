## Defining an NVMe-oF subsystem with nvmeof-cli

Last Updated
: 2026-06-25

Define an NVMe-oF subsystem. Defining the NVMe subsystem includes creating an NVMe subsystem, configuring the IP port for communication, and enabling hosts to use the subsystem.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- (Optional) You can download the `nvmeof-cli` container before first use.

> 📝 **Note:** Note:
The gateway
`nvmeof-cli`
container automatically downloads during initial container use on the host.

To download the gateway
`nvmeof-cli`
container, use the following command:

```plaintext-ibm
podman pull cp.icr.io/cp/ibm-ceph/nvmeof-cli-rhel9:v9.9.1
```

Copy to clipboard

> 📝 **Note:** Note:
These commands can be run on either
`podman`
or
`docker`
.
- To use in-band authentication, an RSA encryption key must be created and placed in the specification file.

For more information, see Deploying by using a service specification file.
- Generate a DH-HMAC-CHAP key with the Linux command line.

> 📝 **Note:** Important:
In-band authentication is supported on an initiator with Red Hat Enterprise Linux 9.5 or later. ESX is not supported.

This is required for using both bidirectional and unidirectional in-band authentication.

```plaintext-ibm
nvme gen-dhchap-key
```

Copy to clipboard

For example,

```
$ nvme gen-dhchap-key
DHHC-1:00:abEcb12F100FNlZkIOkv37idpu/notvalid!!si1VQ09KhKv2g:
```

> 📝 **Note:** Note:
This prerequisite is only required if defining in-band authentication during the subsystem creation or while adding a host to a subsystem. The in-band authentication can also be defined later.

- For more information about in-band authentication, see NVMe-oF gateway in-band authentication.
- For more information about adding in-band authentication to a subsystem after creation, see Changing a subsystem authentication key.

  - For more information about in-band authentication, see NVMe-oF gateway in-band authentication.
  - For more information about adding in-band authentication to a subsystem after creation, see Changing a subsystem authentication key.

### About this task

Configure the Ceph NVMe-oF gateway by using the gateway `nvmeof-cli` utility. To configure the gateway with the dashboard, see Managing NVMe-oF subsystems.

2. Create an NVMe subsystem.
The
SUBSYSTEM_NQN
is a required parameter when creating a subsystem.
SUBSYSTEM_NQN
is a user-defined string. By default, the gateway appends a group name to the NQN and the subsystem includes the group name. The group name is automatically appended to prevent one or more subsystems from being created with the same NQN in different groups.

> 📝 **Note:** Note:
A group name is not appended if the
--no-group-append
parameter is used when adding the subsystem.

In this example, SUBSYSTEM_NQN is defined as nqn.2016-06.io.spdk:cnode1 and `group1` is appended after the subsystem add command. .

> 📝 **Note:** Note:

- The actual created subsystem name is returned with the subsystem add command. Use the returned subsystem name for all subsequent subsystem operations.
- Up to 128 subsystems are supported.

```plaintext-ibm
nvmeof-cli --server-address GATEWAY_IP --server-port 5500 subsystem add --subsystem SUBSYSTEM_NQN [--serial-number SERIAL_NUMBER] [--max-namespaces MAX_NAMESPACES]   [--dhchap-key KEY_VALUE]
```

Copy to clipboard

> 📝 **Note:** Important:

- NQN and gateway name values must not contain an underscore character.
- Do not use the same NQN for two different gateway groups. Namespaces might not be visible if an initiator is connected to two different gateway groups with the same NQN.

The default --server-port value is 5500.

For extra input, the following parameters can be added to the command:
--serial-number
If the serial number is not specified, the number is randomly generated.

Input type: String

--max-namespaces
The maximum namespaces per subsystem default is 256.

Input type: Number

--no-group-append
Use this flag to not append a group name to the subsystem NQN.

> 📝 **Note:** Important:
Use this flag with extreme caution. When using this flag, if an initiator is connected to two different gateway groups with the same subsystem NQNs, not all NVMe-oF devices are listed with the
nvme list
command.

> 📝 **Note:** Note:
A group name is not appended to the subsystem NQN only if this option is not used.

Input type: Boolean

--dhchap-key
Use this flag to add a generated DH-HMAC-CHAP key for use with bidirectional in-band authentication.

> 📝 **Note:** Note:
Use this flag to define in-band authentication during the subsystem creation. The in-band authentication can also be defined later. For more information, see
Changing a subsystem authentication key
.

Input type: String

For example,

```
[root@host01 ~]# nvmeof-cli --server-address 10.172.19.21 --server-port 5500 subsystem add --subsystem nqn.2016-06.io.spdk:cnode1 --dhchap-key DHHC-1:00:abEcb12F100FNlZkIOkv37idpu/notvalid!!si1VQ09KhKv2g:
Adding subsystem nqn.2016-06.io.spdk:cnode1.group1: Successful
```

  - The actual created subsystem name is returned with the subsystem add command. Use the returned subsystem name for all subsequent subsystem operations.
  - Up to 128 subsystems are supported.
3. Add a listener to define the IP port on the gateway that is to process NVMe/TCP commands and I/O operations.

> 📝 **Note:** Important:

- Listeners must be added to all subsystems for all gateways in the gateway group for High Availability and auto load balancing of namespaces.
- NQN and gateway name values must not contain an underscore character.

```plaintext-ibm
nvmeof-cli --server-address GATEWAY_IP --server-port SERVER_PORT listener add --subsystem SUBSYSTEM_NQN --host-name HOST_NAME --traddr GATEWAY_IP
```

Copy to clipboard

For example,

```
[root@host01 ~]# nvmeof-cli --server-address 10.172.19.01 --server-port 5500 listener add --subsystem nqn.2016-06.io.spdk:cnode1.group1 --host-name host02 --traddr 10.172.19.01
```

To define the IP port on the gateway, be sure to include the
--host-name
and
--traddr
parameters.
For extra input, the following parameters can optionally be added to the command:
--trsvcid
Enter the port number. The default port is 4420.
--adrfam
Enter the
IP_TYPE
. The supported value is IPv4 and the input can be written as either
ipv4
or
IPV4
.
--server-port
Enter the
SERVER_PORT
number. The default port is 5500.

  - Listeners must be added to all subsystems for all gateways in the gateway group for High Availability and auto load balancing of namespaces.
  - NQN and gateway name values must not contain an underscore character.

5. Allow the NVMe initiator host to run NVMe/TCP commands to the newly created NVMe subsystem.

1. Add the host.

> 📝 **Note:** Important:
To add a secured DH-HMAC-CHAP host, use the
--dhchap-key
parameter to add the
DHCHAP_KEY
to the host.

`--host-nqn "*"` is not supported with DH-HMAC-CHAP host.

> 📝 **Note:** Note:
A specific host can be selected, as in the following example. To specify all hosts, use
`--host-nqn "*"`
.

To add multiple specific hosts, separate them by using a space. Do not use commas between host NQNs or quotes (") around the multiple host NQNs. Use the following example format:

--host-nqn
HOST01_NQN
HOST02_NQN

```plaintext-ibm
nvmeof-cli --server-address GATEWAY_IP --server-port SERVER_PORT host add --subsystem SUBSYSTEM_NQN --host-nqn HOST01_NQN HOST02_NQN [--dhchap-key KEY_VALUE]
```

Copy to clipboard
