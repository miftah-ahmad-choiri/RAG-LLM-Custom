## Configuring the NVMe-oF initiator for Red Hat Enterprise Linux

Last Updated
: 2026-09-06

Configure the NVMe-oF initiator for Red Hat Enterprise Linux.

### Before you begin

Before you begin, make sure that you have Red Hat Enterprise Linux 9.2 or later.

### Procedure

1. Install the
`nvme-cli`
.

```plaintext-ibm
yum install nvme-cli
```

Copy to clipboard
2. Load the
`nvme-fabrics`
module using
`modprobe`
.

```plaintext-ibm
modprobe nvme-fabrics
```

Copy to clipboard
3. Verify that the target is reachable from the initiator.

```plaintext-ibm
nvme discover -t tcp -a GATEWAY_IP -s 8009
```

Copy to clipboard

The output provides the IP address of the NVMe-oF subsystems that can be connected from this initiator.

4. Connect to the NVMe-oF target.
Use either the
nvme connect-all
or
nvme connect
command to connect to all gateways in the group, establishing multipath connections.

> 📝 **Note:** Note:
When using bidirectional in-band authentication, use the
nvme connect
command instead of
nvme connect-all
. The
nvme connect
command must be run on each gateway for all namespaces to be visible with DH-HMAC-CHAP keys.

> 📝 **Note:** Important:
Namespaces might not be visible if an initiator is connected to two different gateway groups with the same NQN.

> 📝 **Note:** Note:
Use the
`-l`
flag to enable the initiator to automatically reconnect when a gateway becomes temporarily unavailable.

- Running the nvme connect-all command.

```plaintext-ibm
nvme connect-all --traddr GATEWAY_IP --transport tcp -l 1800 -s 8009
```

Copy to clipboard
- Running the nvme connect command, to connect to a specific subsystem.

```plaintext-ibm
nvme connect --traddr GATEWAY_IP --transport tcp --nqn SUBSYSTEM_NQN --trsvcid PORT
```

Copy to clipboard

Use the following values from the previous step:

- subnqn value as the SUBSYSTEM_NQN
- The trsvcid port value

  - The trsvcid port value
- Running the nvme connect command, when bidirectional in-band authentication is enabled.

### Automatically reconnecting to NVMe-oF gateways after a reboot

Configure the Red Hat Enterprise Linux initiator to automatically reconnect to NVMe-oF gateways after the host reboots.

#### About this task

This configuration is optional but recommended. It enables Red Hat Enterprise Linux initiators to automatically reconnect to NVMe-oF gateways after a reboot without requiring manual discovery or connection commands. Configure discovery entries for all gateways in the gateway group to maintain connectivity if a gateway becomes unavailable.

#### Procedure

Run the following steps on each NVMe-oF initiator.

1. Configure the
`nvme-fabrics`
module to load automatically during system startup.

```plaintext-ibm
echo nvme-fabrics | sudo tee /etc/modules-load.d/nvme-fabrics.conf
```

Copy to clipboard
2. Save the transport address and service port for each gateway in the gateway group in the discovery configuration file.

```plaintext-ibm
cat >> /etc/nvme/discovery.conf
--transport=tcp --traddr=10.0.66.9 --trsvcid=8009
--transport=tcp --traddr=10.0.67.10 --trsvcid=8009
```

Copy to clipboard

> 📝 **Note:** Note:
Add one entry for each gateway in the gateway group. Replace the
--traddr
values with the gateway IP addresses for your environment. Configuring multiple gateway entries helps ensure that namespaces automatically reconnect after a reboot even if one gateway is unavailable.
3. Enable the automatic NVMe-oF connection service.

```plaintext-ibm
systemctl enable nvmf-autoconnect.service
```

Copy to clipboard
4. Verify that the service is enabled.

```plaintext-ibm
systemctl status nvmf-autoconnect.service
```

Copy to clipboard

For example,

```
systemctl status nvmf-autoconnect.service
○ nvmf-autoconnect.service - Connect NVMe-oF subsystems automatically during boot
     Loaded: loaded (/usr/lib/systemd/system/nvmf-autoconnect.service; enabled; preset: disabled)
     Active: inactive (dead) since Sat 2026-07-25 05:29:53 UTC; 17s ago
```

#### Results

After the initiator reboots, the NVMe-oF subsystems automatically reconnect without requiring manual discovery or connection commands. When discovery entries are configured for all gateways in the gateway group, namespaces remain accessible even if one gateway is unavailable.
