## Configuring TLS-PSK authentication for NVMe-oF

Last Updated
: 2026-07-23

Configure TLS pre-shared key (TLS-PSK) authentication to secure NVMe-oF connections between initiators and gateways.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- Linux initiator based on RHEL 9.7 or later.
- `nvme-cli` version 2.16 or later.
- `libnvme` version 1.16.1 or later.
- Required network ports are open between the initiator and NVMe-oF gateway nodes.

### Procedure

1. Install and configure the TLS daemon on the initiator.

1. Install the TLS daemon.

```plaintext-ibm
dnf install ktls-utils -y
```

Copy to clipboard
2. Configure the TLS daemon, by editing the
/etc/tlshd.conf
configuration file.
Set the following values:

```plaintext-ibm
[authenticate]
keyrings = .nvme
```

Copy to clipboard
3. Enable the TLS daemon with the new configuration.

```plaintext-ibm
systemctl enable --now tlshd
```

2. Generate and register the TLS key on the initiator.

1. **Required:**
Retrieve the host NQN for the initiator.

```plaintext-ibm
cat /etc/nvme/hostnqn
```

Copy to clipboard

The host NQN uniquely identifies the initiator.
2. Generate a TLS pre-shared key.

```plaintext-ibm
nvme gen-tls-key
```

Copy to clipboard

The TLS key used for secure authentication between the initiator and the NVMe-oF gateway is generated.
3. Load the NVMe over TCP kernel module to enable NVMe over TCP communication on the initiator.

```plaintext-ibm
modprobe nvme-tcp
```

Copy to clipboard
4. Insert the TLS key into the kernel keyring.

```plaintext-ibm
nvme check-tls-key --insert --hostnqn=HOST_NQN --subsysnqn=SUBSYSTEM_NQN --keydata=KEY_DATA --identity=0
```

Copy to clipboard

For example,

```
nvme check-tls-key --insert --hostnqn=nqn.example --subsysnqn=nqn.target --keydata=abc123 --identity=0
```

The TLS key is registered for the specified host and subsystem so that secure connections can be established.

3. Configure the NVMe-oF subsystem and enable secure listeners.

1. Create a secure NVMe-oF subsystem.

```plaintext-ibm
ceph nvmeof subsystem add SUBSYSTEM_NQN --secure_listeners
```

Copy to clipboard

A subsystem is created with TLS-secure listeners enabled.
2. Add a namespace to the subsystem.

```plaintext-ibm
ceph nvmeof namespace add --nqn SUBSYSTEM_NQN --rbd_pool POOL --rbd_image_name IMAGE --size SIZE --create_image
```

Copy to clipboard
3. Add a secure listener to the subsystem.

```plaintext-ibm
ceph nvmeof listener add --nqn SUBSYSTEM_NQN --secure
```

Copy to clipboard

This command enables the subsystem to accept TLS-secured connections from initiators.

4. Add a host with TLS-PSK authentication enabled.

Register the initiator with the subsystem and assign the TLS key.

```plaintext-ibm
ceph nvmeof host add --nqn SUBSYSTEM_NQN --host_nqn HOST_NQN --psk TLS_PSK_KEY
```

Copy to clipboard

For example,

```
[ceph: root@host01 ~]# ceph nvmeof host add --nqn nqn.2016-06.io.spdk:cnode1.mygroup1 --host_nqn nqn.host.example --psk secret123
```

This command associates the TLS pre-shared key with the initiator for secure authentication.
         For more information, see Managing host access.
5. Connect to the NVMe-oF target from the initiator using TLS.

```plaintext-ibm
nvme connect --transport tcp --traddr GATEWAY_IP --trsvcid 4420 --nqn SUBSYSTEM_NQN --tls
```

Copy to clipboard

For example,

```
[ceph: root@host01 ~]# nvme connect --transport tcp --traddr 10.0.0.10 --trsvcid 4420 --nqn nqn.2016-06.io.spdk:cnode1.mygroup1 --tls
```

If the connection does not succeed on the first attempt, redeploying the gateway might resolve the issue.
