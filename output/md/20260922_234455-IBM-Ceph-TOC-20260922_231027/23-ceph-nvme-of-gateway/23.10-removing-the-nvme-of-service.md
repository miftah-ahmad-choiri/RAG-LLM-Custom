## Removing the NVMe-oF service

Last Updated
: 2026-07-23

Remove the NVMe-oF service if you no longer use the NVMe-oF gateway or before running a fresh installation.

### Before you begin

Verify that the volumes are stopped before the service is removed.
When disconnecting from an VMware ESX initiator, use the
esxcli nvme controller list
command to get the NQN name, controller number, and adapter values for step
1
. For example,

```
esxcli nvme controller list
Name                                                                                        Controller Number  Adapter  Transport Type  Is Online
------------------------------------------------------------------------------------------  -----------------  -------  --------------  ---------
nqn.2014-08.org.nvmexpress_8086_INTEL_SSDPE2KX010T7_____________________PHLF733300LH1P0GGN                256  vmhba2   PCIe                 true
nqn.2016-06.io.spdk:cnode2#vmhba64#10.0.210.14:4420                                                       282  vmhba64  TCP                 false
nqn.2016-06.io.spdk:cnode1.group1 #vmhba64#10.0.210.14:4420                                                       278  vmhba64  TCP                 false
```

### About this task

The following steps provide a high-level overview of the process for removing the NVMe-oF service:

1. Disconnect the gateway initiator.
2. Remove the gateway target.
3. Remove the NVMe-oF service.

### Procedure

1. Disconnect the NVMe-oF initiator from NVMe-oF target.
Red Hat Enterprise Linux

```plaintext-ibm
nvme disconnect-all
```

Copy to clipboard

VMware ESX initiator

```plaintext-ibm
esxcli nvme fabrics disconnect -n CONTROLLER_NUMBER -a ADAPTER -s SUBSYSTEM_NQN
```

Copy to clipboard

Replace the
CONTROLLER_NUMBER
,
NVME_TCP_ADAPTER
, and
SUBSYSTEM_NQN
values with the values retrieved from the
esxcli nvme controller list
command. The
SUBSYSTEM_NQN
is listed as
`Name`
in the system output.
For example,

```
esxcli nvme fabrics disconnect -n 282 -a vmhba64 -s nqn.2016-06.io.spdk:cnode2.group1
```
2. Remove the NVMe-oF Gateway target for each subsystem.

> 📝 **Note:** Note:
Use the
`--force`
flag to delete subsystems that contain namespaces.

```plaintext-ibm
ceph nvmeof subsystem del --nqn NQN --force
```

Copy to clipboard

For example,

```plaintext-ibm
[root@host01 ~]# ceph nvmeof subsystem del --nqn nqn.2016-06.io.spdk:cnode1.group1 --force
```

Copy to clipboard
3. Remove the NVMe-oF service.

1. On the Ceph admin node, remove the NVMe-oF service.

```plaintext-ibm
ceph orch rm nvmeof.NVME-OF_POOL_NAME.GW_GROUP
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph orch rm nvmeof.nvmeof.pool1
```
2. Check that the
mon_allow_pool_delete
parameter is set to
`true`

```plaintext-ibm
ceph config set mon mon_allow_pool_delete true
```

Copy to clipboard
3. On the Ceph admin node, remove the
NVME-OF_POOL
created to host NVMe-oF service.

```plaintext-ibm
ceph osd pool rm NVME-OF_POOL_NAME NVME-OF_POOL_NAME --yes-i-really-really-mean-it
```

Copy to clipboard

> 📝 **Note:** Note:
The pool name (
NVME-OF_POOL_NAME
) must be used twice in the command to remove the pool.

For example,

```
[ceph: root@host01 /]# ceph osd pool rm nvmeof_pool01 nvmeof_pool01 --yes-i-really-really-mean-it
```
