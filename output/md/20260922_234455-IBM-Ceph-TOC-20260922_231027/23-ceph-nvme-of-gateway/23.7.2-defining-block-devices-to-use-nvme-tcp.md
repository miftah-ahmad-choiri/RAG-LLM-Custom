## Defining block devices to use NVMe/TCP

Last Updated
: 2026-09-06

Define storage block devices to be used with NVMe/TCP by using `ceph nvmeof` commands.

### About this task

> 📝 **Note:** Note:
Run this procedure only one time per block device, even if multiple gateways exist.

### Procedure

To define block devices and add namespaces on existing
`rbd`
images in a Ceph cluster, start directly with step
3
.

1. Create an
`rbd`
pool.

```plaintext-ibm
ceph osd pool create POOL_NAME PG_NUM

ceph osd pool application enable POOL_NAME rbd
rbd pool init -p POOL_NAME
```

Copy to clipboard

For example,

```
[root@rbd-client ~]# ceph osd pool create pool1
[root@rbd-client ~]# ceph osd pool application enable pool1 rbd
[root@rbd-client ~]# rbd pool init -p pool1
```
2. **Optional:**
Create an image within any Ceph Block Device (RBD) application-enabled pool.

> 📝 **Note:** Note:
An image can be created separately, by using this step, or while adding a namespace. To create an image directly during the namespace creation, skip this step and go to step
3
. Be sure to add the
--rbd-create-image
and
--size
parameters.

```plaintext-ibm
rbd create IMAGE_NAME --size=MEGABYTES --pool=POOL_NAME
```

Copy to clipboard

For example,

```
[root@host01 ~]# rbd create image1 --size=1024 --pool=pool1
```

For more information about creating an image, see
Creating images
.
3. Add a namespace to any subsystem that was created in
Defining an NVMe-oF subsystem
.
To create an image within an RBD application-enabled pool, use the
--rbd-create-image
and
--size
parameters.

> 📝 **Note:** Note:
Create an image within an RBD application-enabled pool when step
2
was skipped.

Automatic load-balancing makes sure that each namespace receives an assigned load-balancing group. For more information about load balancing, see Using load balancing with scale-up and scale-down.

During a namespace addition, a load-balancing group is automatically assigned to the NVMe-oF namespace with any available NVMe-oF gateway load-balancing group.

It is recommended to allow the NVMe-oF gateway to set the active gateway automatically, and not to force the namespace. The gateway load-balancing group ID of a gateway can be retrieved at any time by running the
gateway info
command. For example:

```plaintext-ibm
ceph nvmeof gateway info [--gw_group GW_GROUP]
```

Copy to clipboard

```plaintext-ibm
ceph nvmeof namespace add --nqn NQN [--rbd_image_name RBD_IMAGE_NAME] [--rbd_pool RBD_POOL] [--create-image] [--size POOL_SIZE] [--rbd_image_size IMAGE_SIZE]
```

Copy to clipboard

The image size can be expanded at any time. For more information see, Expanding a block device image.

- Example of adding a namespace to a block device with a previously created image.

```
[root@host01 ~]# ceph nvmeof namespace add nqn.2016-06.io.spdk:cnode1.group1 rbd_image_name image1 --rbd_pool pool1
```
- Example of creating an image and adding a namespace within the same command.

```
[root@host01 ~]# ceph nvmeof namespace add nqn.2016-06.io.spdk:cnode1.group1 --rbd_image_name image1 pool1 --create-image --size SIZE --rbd_image_size 1024
```

  - Example of adding a namespace to a block device with a previously created image.

  ```
  [root@host01 ~]# ceph nvmeof namespace add nqn.2016-06.io.spdk:cnode1.group1 rbd_image_name image1 --rbd_pool pool1
  ```
  - Example of creating an image and adding a namespace within the same command.

  ```
  [root@host01 ~]# ceph nvmeof namespace add nqn.2016-06.io.spdk:cnode1.group1 --rbd_image_name image1 pool1 --create-image --size SIZE --rbd_image_size 1024
  ```

### What to do next

Verify the block device configuration.

1. If an image was created when adding the namespace, verify the image that was create on the node that has IBM Storage Ceph CLI, such as the admin node or the client.

```plaintext-ibm
rbd ls -p pool1
```

Copy to clipboard
2. List all namespaces configured on a subsystem.


```plaintext-ibm
ceph nvmeof namespace list --nqn NQN --gw_group GW_GROUP [--server-address SERVER_ADDRESS]
```

Copy to clipboard
