## CRUSH failure domain

Last Updated
: 2026-06-25

Having multiple object replicas or `M` erasure coding chunks helps prevent
data loss, but it is not sufficient to address high availability. By reflecting the underlying
physical organization of the Ceph Storage Cluster, CRUSH can model, and thereby address, potential
sources of correlated device failures. By encoding the cluster’s topology into the cluster map,
CRUSH placement policies can separate object replicas or erasure coding chunks across different
failure domains while still maintaining the desired pseudo-random distribution.

For example, to address the possibility of concurrent failures, it might be desirable to ensure
that data replicas or erasure coding chunks are on devices using different shelves, racks, power
supplies, controllers or physical locations. This helps to prevent data loss and allows the cluster
to operate in a degraded state.
