## Configure snapshot (.snap) visibility for CephFS NFS shares

Last Updated
: 2026-06-25

Control whether the CephFS .snap directory is visible and accessible for NFS clients on a per-share basis. This setting works with subvolume-level visibility flags and client-side configuration.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- Ensure a CephFS cluster with snapshots enabled.
- Configure an NFS cluster through the Ceph MGR NFS module or Ceph Dashboard.
- Have Ceph CLI access and valid CephX credentials for NFS clients.

### About this task

The .snap directory is visible by default. You can control visibility based on the following:

- Subvolume-level flag: Indicates whether snapshots are visible for a specific subvolume.
- client-level flag: Determines whether the client enforces the subvolume and share snapshot visibility settings when accessing the .snap directory.
- Share-level toggle: Determines whether NFS shares expose the .snap directory.
- Whether the NFS client respects visibility settings.

The setting takes effect only when clients respect the subvolume visibility flag by enabling client_respect_subvolume_snapshot_visibility.

> 📝 **Note:** Note:
This documentation uses
*NFS share*
instead of the earlier term
*NFS export*
. In the Ceph Dashboard, labels and controls may still refer to NFS export.

### Procedure

Enable at subvolume-level

1. Set snapshot visibility for a subvolume.

```plaintext-ibm
ceph fs subvolume snap snapshot visibility set <fs_name> <subvolume_name> <subvolume_group> <true|false>
```

Copy to clipboard

For example,

```
ceph fs subvolume snap snapshot visibility set cephfs sv1 appgrp false
```
2. (Optional) run the below command to set the extended attribute manually.

```plaintext-ibm
setfattr -n ceph.subvolume.snaps.visible -v 0 /cephfs/path/to/subvolume
```

Copy to clipboard

Enable at client-level

1. Retrieve CephX identity.

```plaintext-ibm
ceph nfs export info <nfs-cluster-name> <export-pseudo-path>
```

Copy to clipboard
2. Configure client-side respect for visibility flags.

```plaintext-ibm
ceph config set client.<cephx_entity> client_respect_subvolume_snapshot_visibility true
```

Copy to clipboard

For example,

```
ceph config set client.nfs-cephx-user client_respect_subvolume_snapshot_visibility true
```
3. Verify if the flag visibility is configured.

```plaintext-ibm
ceph config get client.<cephx_entity> client_respect_subvolume_snapshot_visibility
```

Copy to clipboard

Configure the share-level toggle.

1. In the Ceph Dashboard, click
**NFS**
>
**Exports**
, then click
**Create**
or
**Edit**
. Toggle Snapshot (.snap) visibility, and click Save.
API example,

```
{
  "exportId": "exp-56789",
  "path": "/cephfs/subvolumes/teamB",
  "access": false
}
```
2. Verify on the NFS client.

```plaintext-ibm
mount -t nfs <nfs_server>:/exports/sv1 /mnt/sv1
ls -la /mnt/sv1
# access=true  → .snap is visible
# access=false → .snap is hidden
```

Copy to clipboard

> 📝 **Note:** Note:
Attempting access if disabled returns EPERM.

### Results

Visibility of the .snap directory matches your configuration across subvolume, client, and share settings. Snapshot operations are blocked if visibility is disabled and clients enforce the visibility flag.
