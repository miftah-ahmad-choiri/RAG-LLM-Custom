## Software-related questions

Last Updated
: 2026-06-25

Find answers to frequently asked questions about Ceph software.

Following are the primary use cases for
IBM Storage Ceph
:

- Ceph Block Devices for VMs or containers.
- File storage (CephFS) for Linux/NFS/SMB clients.
- Ceph Object Gateway compatible with AWS S3 and OpenStack Swift.

### Can a single Ceph cluster support block, file, and object storage together?

Yes. A single cluster can support any combination of Ceph Block Device, CephFS, and Ceph Object Gateway workloads simultaneously.

### How large can a Ceph cluster be?

IBM Storage Ceph can scale to tens of petabytes per cluster. Plan for future growth due to long lead times for hardware procurement.

### What are the performance tradeoffs between storage types?

The following are the performance tradeoffs between storage types:

- Ceph Block Devices are latency-sensitive. SSD-backed pools are ideal.
- Ceph Object Gateway is throughput-oriented. HDDs can work well for large objects.
- CephFS needs SSDs for metadata, but bulk data can be on HDDs or Quad-Level Cell (QLC) SSDs.

### What storage media are required for CephFS and Ceph Object Gateway metadata?

SSDs are required for CephFS metadata and Ceph Object Gateway bucket index pools.

### What is the best data protection strategy: replication or erasure coding (EC)?

- Replication (R3) stores 3 copies and is required for some pools.
- EC (for example, 4+2, 8+3) is more storage-efficient but incurs write/recovery latency.

Choose based on performance versus efficiency needs.

### Can I mix replication and EC within the same cluster?

Yes. Different pools (such as Ceph Block Device, Ceph Object Gateway, and CephFS) can use different protection strategies, sharing the same physical drives.

### How many nodes are recommended for erasure coding?

Ideally, one more node than the sum of EC data + parity chunks. For example, a 4+2 profile needs at least 7 nodes.

### How flexible is IBM Storage Ceph with server hardware?

IBM Storage Ceph with server hardware is very flexible. You can mix server types and storage media. However, consider the role that each node plays and the performance impact of heterogeneity.
