## Cloning block device group snapshot

Last Updated
: 2026-06-25

You can clone new groups from group snapshots created with the rbd group snap
create command with the latest --snap-id option for the rbd
clone command.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph cluster.
- Root-level access to the node.
- A group snapshot.

### About this task

Cloning from group snapshots is supported only with clone v2 `--rbd-default-clone-format
2`.

```plaintext-ibm
[root@rbd-client]# ] rbd clone --snap-id 4 pool1/image1 pool1/i1clone1 --rbd-default-clone-format 2
```

Copy to clipboard

### Procedure

1. Get the snap ID of the group snapshot.
```plaintext-ibm
rbd snap ls --all POOL_NAME/PARENT_IMAGE_NAME
```

Copy to clipboard

The following example has a group snapshot, indicated with `SNAPID` listed as
**4** and the `NAMESPACE` as `group`.

```plaintext-ibm
[root@rbd-client] # rbd snap ls --all pool1/image1
SNAPID     NAME             SIZE     PROTECTED   TIMESTAMP                    NAMESPACE
3          snap1            10 GiB   yes         Thu Jul 25 06:21:33 2024     user
4          .group.2_39d     10 GiB               Wed Jul 31 02:28:49 2024     group (pool1/group1@p1g1snap1)
```

Copy to clipboard
2. Create a clone of the group snapshot using the
--snap-id
option.
```plaintext-ibm
rbd clone --snap-id <SNAP_ID> POOL_NAME/IMAGE_NAME POOL_NAME/CLONE_IMAGE_NAME --rbd-default-clone-format 2
```

Copy to clipboard

```plaintext-ibm
[root@rbd-client]# rbd clone --snap-id 4 pool1/image1 pool2/clone2 --rbd-default-clone-format 2
```

Copy to clipboard

### What to do next

Use the rbd ls command to verify the clone image of the group snapshot is
created successfully.

```plaintext-ibm

[root@rbd-client]# rbd ls -p pool2
clone2
```

Copy to clipboard
