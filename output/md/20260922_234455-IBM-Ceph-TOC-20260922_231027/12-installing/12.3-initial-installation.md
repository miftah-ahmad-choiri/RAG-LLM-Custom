## Initial installation

Last Updated
: 2026-09-06

Use the `cephadm` utility to deploy new IBM Storage Ceph clusters.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- Operating System swap must not be enabled.
- At least one running virtual machine (VM) or bare-metal server with an active internet connection.
- Red Hat Enterprise Linux
9.8 or 10.2
with
`ansible-core`
2.16.18 bundled into AppStream.
- A valid IBM subscription with the appropriate entitlements.

> 📝 **Note:** Note:
If you purchased an
IBM Storage Ceph
Premium license, complete the Red Hat entitlement activation process before beginning deployment.

For more information, see Accessing Red Hat entitlements from IBM Storage Ceph.
- Root-level access to all nodes.
- An active IBM Network or service account to access the IBM Registry.
- Remove troubling configurations in iptables so that refresh of iptables services does not cause issues to the cluster. For an example, see Verifying firewall rules are configured for default Ceph ports.

For the latest supported Red Hat Enterprise Linux versions, see
Compatibility matrix
.

### About this task

The
`cephadm`
utility manages the entire life cycle of a Ceph cluster. Installation and management tasks comprise two types of operations:

- Day One operations involve installing and bootstrapping a bare-minimum, containerized Ceph storage cluster, running on a single node. Day One also includes deploying the Monitor and Manager daemons and adding Ceph OSDs.
- Day Two operations use the Ceph orchestration interface, `cephadm orch`, or the IBM Storage Ceph Dashboard to expand the storage cluster by adding other Ceph services to the storage cluster.

> 📝 **Note:** Important:
Operating System swap must not be enabled. Configuring the operating system to use swap to provide additional virtual memory for daemons is not recommended for modern systems and can result in degraded performance.
