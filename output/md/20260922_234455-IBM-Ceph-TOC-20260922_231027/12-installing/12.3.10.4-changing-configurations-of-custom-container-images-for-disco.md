## Changing configurations of custom container images for disconnected installations

Last Updated
: 2026-06-25

After you perform the initial bootstrap for disconnected nodes, you must specify custom container images for monitoring stack daemons. You can override the default container images for monitoring stack daemons, since the nodes do not have access to the default container registry in air-gapped environments.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- At least one running virtual machine (VM) or server.
- Red Hat Enterprise Linux
9.8 or 10.2
with
`ansible-core`
2.16.18 bundled into AppStream.
- Root-level access to all nodes.
- Passwordless `ssh` is set up on all hosts in the storage cluster.

For the latest supported Red Hat Enterprise Linux versions, see
Compatibility matrix
.

### About this task

> 📝 **Note:** Note:
Make sure that the bootstrap process on the initial host is complete before making any configuration changes.

By default, the monitoring stack components are deployed based on the primary Ceph image. For disconnected environment of the storage cluster, you can use the latest available monitoring stack component images.

> 📝 **Note:** Note:
When using a custom registry, be sure to log in to the custom registry on newly added nodes before adding any Ceph daemons.

```plaintext-ibm
ceph cephadm registry-login --registry-url CUSTOM_REGISTRY_NAME --registry_username REGISTRY_USERNAME --registry_password REGISTRY_PASSWORD
```

Copy to clipboard

For example,

```
# ceph cephadm registry-login --registry-url myregistry --registry_username myregistryusername --registry_password myregistrypassword1
```

For more information, see Performing a disconnected installation.

### Procedure

1. Set the custom container images with the
ceph config
command.

```plaintext-ibm
ceph config set mgr mgr/cephadm/OPTION_NAME
CUSTOM_REGISTRY_NAME/IMAGE_NAME
```

Copy to clipboard

Use the following options for
OPTION_NAME
:

```plaintext-ibm
container_image_prometheus
container_image_grafana
container_image_alertmanager
container_image_node_exporter
```

Copy to clipboard

For example,

```
[root@host01 ~]# ceph config set mgr mgr/cephadm/container_image_prometheus private_registry/prometheus
[root@host01 ~]# ceph config set mgr mgr/cephadm/container_image_grafana private_registry/grafana
[root@host01 ~]# ceph config set mgr mgr/cephadm/container_image_alertmanager private_registry/alertmanager
[root@host01 ~]# ceph config set mgr mgr/cephadm/container_image_node_exporter private_registry/node_exporter
```
2. Redeploy
`node-exporter`
.

```plaintext-ibm
ceph orch redeploy node-exporter
```

Copy to clipboard

> 📝 **Note:** Note:

- If any of the services do not deploy, you can redeploy them with the ceph orch redeploy command.
- By setting a custom image, the default values for the configuration image name and tag will be overridden, but not overwritten. The default values change when updates become available. By setting a custom image, you will not be able to configure the component for which you have set the custom image for automatic updates. You will need to manually update the configuration image name and tag to be able to install updates.

### What to do next

To revert to the default configuration, reset the customer container image. This can be done at any time. Use the
ceph config rm
to reset the configuration option.

```plaintext-ibm
ceph config rm mgr mgr/cephadm/OPTION_NAME
```

Copy to clipboard

For example,

```
[root@host01 ~]# ceph config rm mgr mgr/cephadm/container_image_prometheus
```
