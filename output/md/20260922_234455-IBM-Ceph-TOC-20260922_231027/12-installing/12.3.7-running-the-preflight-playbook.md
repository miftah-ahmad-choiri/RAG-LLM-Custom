## Running the preflight playbook

Last Updated
: 2026-07-23

The Ansible playbook configures the Ceph repository and prepares the storage cluster for bootstrapping. It also installs some prerequisites, such as
`podman`
,
`lvm2`
,
`chrony`
, and
`cephadm`
packages. The default location for
`cephadm-ansible`
and
cephadm-preflight.yml
is
/usr/share/cephadm-ansible
.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- `cephadm-ansible` package installed using the dnf install cephadm-ansible command.
- Root-level access to the Ansible administration node.
- Ansible user with sudo and password-less `ssh` access to all nodes in the storage cluster.
- The IBM license installed on all the nodes.

### About this task

> 📝 **Note:** Important:
Run the preflight playbook before you bootstrap the initial host.

The preflight playbook uses the `cephadm-ansible` inventory file to identify the admin node and all other nodes in the storage cluster.

The default location for the inventory file is /usr/share/cephadm-ansible/hosts.

The following example shows the structure of a typical inventory file:

```plaintext-ibm
host02
host03
host04

[admin]
host01
```

Copy to clipboard

The `[admin]` group in the inventory file contains the name of the node where the admin keyring is stored. On a new storage cluster, the node in the `[admin]` group will be the bootstrap node. To add additional admin hosts after bootstrapping the cluster see Setting up the admin node.

The preflight playbook provides a comprehensive set of checks and tasks to ensure optimal system configuration for IBM Storage Ceph deployments.

The playbook checks and tasks include the following:

- Correct operating system configurations.

- Red Hat Enterprise Linux version.
- The correct software profile.
- All mandatory packages are installed. If any packages are missing, the playbook installs the mandatory missing packages.

  - Red Hat Enterprise Linux version.
  - The correct software profile.
  - All mandatory packages are installed. If any packages are missing, the playbook installs the mandatory missing packages.
- Correct hardware configurations.

- CPU configuration
- RAM configuration
- Memory swap space
- Network Interface Card (NIC) configurations

  - CPU configuration
  - RAM configuration
  - Memory swap space
  - Network Interface Card (NIC) configurations
- The separation of root-filesystem and /var.

> 📝 **Note:** Important:
If you are performing a disconnected installation, see
Running the preflight playbook for a disconnected installation
.

When running the preflight playbook, `cephadm-ansible` automatically installs `chrony` and `ceph-common` packages on the client nodes.

The Ansible Preflight performs a check to detect whether swap space is configured on the host. This check is informational only and does not block deployment. Operational practices vary across environments:

- Some deployments disable swap on OSD nodes to avoid increased latency under memory pressure.
- Other deployments keep swap enabled but configure a very low `vm.swappiness` value (for example, 0 or 1) to minimize swapping activity.

> 📝 **Note:** Note:
Specific swap configurations are not enforced. Follow the appropriate guidance for your specific environment.

To configure multiple sources or if you have a disconnected environment, see the following documentation for more information:

- Running the preflight playbook for a disconnected installation
- Basic chrony NTP troubleshooting

### Procedure

> 📝 **Note:** Note:
In the following procedure,
`host01`
is the bootstrap node.

1. Navigate to the
/usr/share/cephadm-ansible
directory.
2. Open and edit the
`hosts`
file and add your nodes.
For example,

```
host02
host03
host04

[admin]
host01
```
3. Run the following command on each node.

```plaintext-ibm
rm -rf '/etc/yum.repos.d/ceph_stable_$basearch.repo'
```

Copy to clipboard
4. Run the preflight playbook.
Run the preflight playbook either by running the playbook for all hosts in the cluster or for a selected set of hosts in the cluster.

> 📝 **Note:** Note:
When running the preflight playbook,
`cephadm-ansible`
automatically installs
`chrony`
and
`ceph-common`
packages on the client nodes.

After installation is complete, `cephadm` resides in the /usr/sbin/ directory.

1. Run the playbook for all hosts in the cluster.

```plaintext-ibm
ansible-playbook -i INVENTORY_FILE cephadm-preflight.yml --extra-vars "ceph_origin=ibm"
```

Copy to clipboard

Table 1
to understand the report.

> 📝 **Note:** Important:
All checks are information only. Failures do not stop the check from running.

| Report type | Corresponding icon | Description |
| --- | --- | --- |
| Passed |  | Meets baseline or recommended values. |
| INFO |  | General system or environment information details. |
| Failed |  | Does not meet recommended values. This is informational only. |

At the end of the report a
Summary
section is provided. The
Summary
provides information of failed checks.

> 📝 **Note:** Note:
The report is saved in the current working directory, from where the playbook was run as
./preflight_report.txt
. The path to the report is displayed after the summary report.
2. Run the preflight playbook on a selected set of hosts in a storage cluster by using the
--limit
option.

```plaintext-ibm
ansible-playbook -i INVENTORY_FILE cephadm-preflight.yml --extra-vars "ceph_origin=custom" -e "custom_repo_url=URL" --limit GROUP_NAME|NODE_NAME
```

Copy to clipboard

Replace
GROUP_NAME
with a group name from your inventory file and
NODE_NAME
with a specific node name from your inventory file.

> 📝 **Note:** Note:
Optionally, you can group your nodes in your inventory file by group name such as
`[mons]`
,
`[osds]`
, and
`[mgrs]`
. However, admin nodes must be added to the
`[admin]`
group and clients must be added to the
`[clients]`
group.

For example,

```
[ansible@admin cephadm-ansible]$ ansible-playbook -i hosts cephadm-preflight.yml --extra-vars "ceph_origin=custom" -e "custom_repo_url=http://mycustomrepo.lab.ibm.com/x86_64/os/" --limit clients
[ansible@admin cephadm-ansible]$ ansible-playbook -i hosts cephadm-preflight.yml --extra-vars "ceph_origin=custom" -e "custom_repo_url=http://mycustomrepo.lab.ibm.com/x86_64/os/" --limit host02
```

### What to do next

1. Update or fix any issues that were flagged during the preflight check.
2. Verify that the packages were installed successfully.
          For example,

```
[ansible@admin cephadm-ansible]$ rpm -q chrony ceph-common
```
