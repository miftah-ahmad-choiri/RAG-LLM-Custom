## Enabling input/output operations rate-limiting for NFS share

Last Updated
: 2026-06-25

Learn how to enable input/output operations (IOPS) rate-limiting for NFS share by using the command line.

### About this task

Enabling IOPS rate-limiting for NFS shares helps control the number of input/output operations per second that clients can perform, preventing resource contention and ensuring fair usage.

To enable share-level IOPS control, you must enable cluster-level IOPS control with qos_type ,PerShare, or PerShare_PerClient.

> 📝 **Note:** Note:
You cannot enable export-level IOPS control if the cluster-level
qos_type
is
PerClient
.

**Understanding cluster-wide enforcement of bandwidth and IOPS limits**

When you enable bandwidth or input/output operations (IOPS) control on an NFS cluster, the configured limits apply cumulatively across all hosts in the cluster, rather than per individual host.

To enforce these cumulative limits, NFS services coordinate with NFS daemons running on other hosts in the cluster. This coordination ensures that bandwidth and IOPS limits are enforced consistently, even when multiple NFS servers handle client requests at the same time.

> 📝 **Note:** Note:
You can configure the port used for this inter-node communication by using the cluster_qos_port field in the NFS specification. The default port is 31311.

You can control how frequently NFS daemons exchange coordination messages by using the cqos_msg_interval field in the NFS specification. The default interval is 100 ms.

Alternatively, you can update the message interval by using the command-line interface.

```plaintext-ibm
ceph nfs cluster qos set <cluster_id> <msg_interval>
```

This inter-node coordination ensures accurate enforcement of bandwidth and IOPS limits across the NFS cluster.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A healthy and running IBM Storage Ceph cluster.
- An NFS cluster.
- NFS shares.

### Procedure

You can use the following command to enable IOPS rate-limiting to NFS shares. This command enables IOPS control for a specified share. You can also use this command to update the operations count.

```plaintext-ibm
nfs export qos enable ops_control CLUSTER_ID PSEUDO_PATH [max_export_iops:INT] [max_client_iops:INT]
```

Copy to clipboard

Where,

- CLUSTER_ID is the NFS cluster ID.
- PSEUDO_PATH is the pseudo root path. The path must be an absolute path.
- max_export_iops is the count of IOPS operations for share.
- max_client_iops is the count of IOPS operations for a client of the share.

IOPS rate-limiting for
PerShare

```
[ceph: root@ceph-node-0 /]# ceph nfs export qos enable ops_control clust_nfs /export1 --max_export_iops 2000
[ceph: root@ceph-node-0 /]# ceph nfs export qos get clust_nfs /export1
{
"cluster_enable_bw_control": false,
"cluster_enable_iops_control": true,
"cluster_enable_qos": true,
"combined_rw_bw_control": false,
"enable_bw_control": false,
"enable_iops_control": true,
"enable_qos": true,
"max_export_iops": 2000
}
```

IOPS rate-limiting for
PerShare_Per Client

```
[ceph: root@ceph-node-0 /]# ceph nfs export qos enable ops_control clust_nfs /export1 --max_export_iops 2000 --max_client_iops 1000
[ceph: root@ceph-node-0 /]# ceph nfs export qos get clust_nfs /export1
{
"cluster_enable_bw_control": false,
"cluster_enable_iops_control": true,
"cluster_enable_qos": true,
"combined_rw_bw_control": false,
"enable_bw_control": false,
"enable_iops_control": true,
"enable_qos": true,
"max_client_iops": 1000,
"max_export_iops": 2000
}
```
