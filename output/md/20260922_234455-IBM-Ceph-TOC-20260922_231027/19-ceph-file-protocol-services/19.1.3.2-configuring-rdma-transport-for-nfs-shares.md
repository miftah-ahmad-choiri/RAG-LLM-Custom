## Configuring RDMA transport for NFS shares

Last Updated
: 2026-06-25

Configure NFS shares to allow access over RDMA.

### About this task

When an NFS cluster is created with
`--enable-rdma`
, all new exports created on that cluster automatically include both TCP and RDMA in their transport configuration. No additional export-level configuration is required for new exports. Existing exports that were created before RDMA was enabled on the cluster retain their original TCP-only transport. These must be updated manually to add RDMA transport.

### Enabling RDMA transport on an existing export

#### Procedure

1. Export the current configuration to a file:

```plaintext-ibm
ceph nfs export get <cluster_name> <pseudo_path> > export.json
```

Copy to clipboard
2. Edit the exported file and add
`RDMA`
to the
`transports`
list:

```plaintext-ibm
{
  "export_id": 2,
  "path": "/volumes/_nogroup/subvol-r2/...",
  "pseudo": "/export-r2",
  "transports": ["TCP", "RDMA"]
}
```

Copy to clipboard
3. Apply the updated export configuration:

```plaintext-ibm
ceph nfs export apply <cluster_name> -i export.json
```

Copy to clipboard
4. Verify the updated configuration:

```plaintext-ibm
ceph nfs export get <cluster_name> <pseudo_path>
```

Copy to clipboard

Confirm that the
`transports`
field includes:

- Standard TCP transport
- RDMA transport

> 📝 **Note:** Note:
The NFS cluster itself must already have RDMA enabled at the cluster level (`enable_rdma: true` in the service spec) before exports can use RDMA transport. For more information, see
Configuring RDMA support in NFS

  - Standard TCP transport
  - RDMA transport

#### What to do next

The export will be accessible over both transports. Existing TCP-mounted clients are not affected. New clients can mount using RDMA.

### Verify RDMA transport on an export

#### Procedure

Run the following command to check the transport configuration:

```plaintext-ibm
ceph nfs export get <cluster_name> <pseudo_path>
```

Copy to clipboard

For example, export with RDMA enabled

```
{
"export_id": 1,
"path": "/volumes/_nogroup/subvol-r1/...",
"pseudo": "/export-r1",
"transports": ["TCP", "RDMA"],
...
}
```

For example, export without RDMA (TCP only)

```
{
"export_id": 2,
"path": "/volumes/_nogroup/subvol-r2/...",
"pseudo": "/export-r2",
"transports": ["TCP"],
...
}
```
