## Modifying NFS shares

Last Updated
: 2026-06-25

Modify Ceph File System share parameters with a configuration file.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running, and healthy IBM Storage Ceph cluster.
- An NFS share created.

### About this task

You can modify the following parameters in a share with a configuration file:
access_type
This can be
`RW`
,
`RO`
, or
`NONE`
.
squash
This can be
`No_Root_Squash`
,
`None`
, or
`Root_Squash`
.
security_label
This can be
`true`
or
`false`
.

> 📝 **Note:** Note:
This documentation uses
*NFS share*
instead of the earlier term
*NFS export*
. In the Ceph Dashboard, labels and controls may still refer to NFS export.

### Procedure

1. View the share block based on the pseudo-root name.

```plaintext-ibm
ceph nfs export get CLUSTER_NAME BINDING
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph nfs export get nfs-cephfs /ceph
{
"access_type": "RW",
"clients": [],
"cluster_id": "nfsservice",
"export_id": 1,
"fsal": {
"cmount_path": "/", "fs_name": "cephfs", "name": "CEPH", "user_id": "nfs.nfsservice.cephfs"
},
"path": "/",
"protocols": [
3, 4
],
"pseudo": "/ganesha1",
"security_label": true,
"squash": "none",
"transports": [
"TCP"
]
}
```
2. Share the configuration file.

```plaintext-ibm
ceph nfs export get nfs-cephfs /ceph > export.conf
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph nfs export get nfs-cephfs /ceph > export.conf
```
3. Edit the share information.

> 📝 **Note:** Note:
For NFSv3 mounts (NFS version 3), use
protocols
=
3
.

```plaintext-ibm
{
  "export_id": EXPORT_ID,
  "path": "PATH",
  "cluster_id": "CLUSTER_NAME",
  "pseudo": "CLUSTER_PSEUDO_PATH",
  "access_type": "RW/RO",
  "squash": "SQUASH",
  "security_label": SECURITY_LABEL,
  "protocols": [
    PROTOCOL_ID
  ],
  "transports": [
    "TCP"
  ],
  "fsal": {
    "name": "NAME",
    "user_id": "USER_ID",
    "fs_name": "FILE_SYSTEM_NAME",
    "sec_label_xattr": ""
  },
  "clients": []
}
```

Copy to clipboard

In the following example, the
`access_type`
is modified from
`RO`
to
`RW`
.

```
[ceph: root@host01 /]# vi export.conf

{
"access_type": "RW",
"clients": [],
"cluster_id": "nfservice",
"export_id": 1,
"fsal": {
"cmount_path": "/", "fs_name": "cephfs", "name": "CEPH", "user_id": "nfs.nfsservice.cephfs"
},
"path": "/",
"protocols": [
3, 4
],
"pseudo": "/ganesha1",
"security_label": true,
"squash": "none",
"transports": [
"TCP"
]
}
```
4. Apply the specification.

```plaintext-ibm
ceph nfs export apply CLUSTER_NAME PATH_TO_EXPORT_FILE
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph nfs export apply nfs-cephfs -i export.conf
Added export /ceph
```
5. Get the updated share information.

```plaintext-ibm
ceph nfs export get CLUSTER_NAME BINDING
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph nfs export get nfs-cephfs /ceph
{
"access_type": "RW",
"clients": [],
"cluster_id": "nfsservice",
"export_id": 1,
"fsal": {
"cmount_path": "/", "fs_name": "cephfs", "name": "CEPH", "user_id": "nfs.nfsganesha.cephfs"
},
"path": "/",
"protocols": [
3, 4
],
"pseudo": "/ganesha1",
"security_label": true,
"squash": "none",
"transports": [
"TCP"
]
}
```
