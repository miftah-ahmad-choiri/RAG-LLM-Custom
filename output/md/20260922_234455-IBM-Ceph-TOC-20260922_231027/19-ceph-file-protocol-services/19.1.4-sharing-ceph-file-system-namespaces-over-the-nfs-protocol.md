## Sharing Ceph File System namespaces over the NFS protocol

Last Updated
: 2026-06-25

Ceph File Systems (CephFS) namespaces can be shares over the NFS protocol using a NFS service file server. To share a CephFS namespace, you must first have a running NFS service cluster.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running, and healthy IBM Storage Ceph cluster.
- An NFS cluster created using the ceph nfs cluster create command.

### About this task

> 📝 **Note:** Important:

- NFSv3 (version 3) is supported and enabled for clients that do not yet support NFSv4 mounts for CephFS file shares.

Use NFSv4 for clients and servers that support NFSv4.2 or later.
- NFS clients are unable to create CephFS snapshots through their native NFS mount. They must use server-side operator tooling for their snapshot needs.

### Procedure

1. Create a CephFS share.

> 📝 **Note:** Important:
Due to a known issue, do not use the
cmount_path
option when creating an NFS share. If a value other than
/
is used, NFS shares that were previously defined with the
/
path become inaccessible.

```plaintext-ibm
ceph nfs export create cephfs CLUSTER_NAME BINDING FILE_SYSTEM_NAME [--readonly] [--path=PATH_WITHIN_CEPHFS]
```

Copy to clipboard

In the following example, the
BINDING
(
`/ceph`
) is the pseudo root path, which must be unique, and an absolute path.

```
[ceph: root@host01 /]# ceph nfs export create cephfs nfs-cephfs /ceph cephfs01 --path=/
{
"bind": "/ceph",
"cluster": "nfs-cephfs",
"fs": "cephfs01",
"mode": "RW",
"path": "/"
}
```

> 📝 **Note:** Note:

- The --readonly option shares a path with the read-only permission, the default being read, and write permissions.
- The PATH_WITHIN_CEPHFS can be a subvolume. You can get the absolute subvolume path by using the subvolume getpath command.

```plaintext-ibm
ceph fs subvolume getpath VOLUME_NAME SUBVOLUME_NAME [--group_name SUBVOLUME_GROUP_NAME]
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph fs subvolume getpath cephfs sub0
```

5. On a client host, mount the shared Ceph File System.

```plaintext-ibm
mount -t nfs -o port=GANESHA_PORT HOST_NAME:BINDING LOCAL_MOUNT_POINT
```

Copy to clipboard

For example,

```
[root@client01 ~]# mount -t nfs -o port=2049 host01:/ceph/ /mnt/nfs-cephfs
```

1. To automatically mount on boot, open and edit the
`/etc/fstab`
file by adding a new line.

```plaintext-ibm
HOST_NAME:BINDING LOCAL_MOUNT_POINT nfs4   defaults,seclabel,vers=4.2,proto=tcp,port=2049  0  0
```

6. On a client host, mount a shared NFS Ceph File System, created with an
`ingress`
service.

```plaintext-ibm
mount -t nfs VIRTUAL_IP_ADDRESS:BINDING LOCAL_MOUNT_POINT
```

Copy to clipboard

- Replace VIRTUAL_IP_ADDRESS with --ingress --virtual-ip IP address used to create the NFS cluster.
- Replace BINDING with the pseudo root path.
- Replace LOCAL_MOUNT_POINT with the mount point to mount the share on.

The following example mounts the share
`nfs-cephfs`
that exists on a NFS cluster created with
`--ingress --virtual-ip 10.10.128.75`
on the
/mnt
mount point .

```
[root@client01 ~]# mount -t nfs 10.10.128.75:/nfs-cephfs /mnt
```

  - Replace VIRTUAL_IP_ADDRESS with --ingress --virtual-ip IP address used to create the NFS cluster.
  - Replace BINDING with the pseudo root path.
  - Replace LOCAL_MOUNT_POINT with the mount point to mount the share on.
