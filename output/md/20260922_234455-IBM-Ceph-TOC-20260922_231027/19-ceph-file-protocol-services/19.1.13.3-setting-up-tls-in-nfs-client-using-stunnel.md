## Setting up TLS in NFS client using Stunnel

Last Updated
: 2026-06-25

Learn how to configure TLS for NFS to protect data in transit and ensure secure communication between NFS clients and servers.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- Install TLS backend library (OpenSSL) based on your build configuration.
- The TLS certificates and keys must be available.

> 📝 **Note:** Note:
You must have access to the following TLS certificates:

- CA certificate (`ca.crt`)
- Server certificate (`ganesha.crt`)
- Private key (`ganesha.key`)

  - CA certificate (`ca.crt`)
  - Server certificate (`ganesha.crt`)
  - Private key (`ganesha.key`)
- Ensure client-side support for TLS or mTLS (NFS client tools that support `xprtsec=tls` or `xprtsec=mtls`).

For more information on configuring the NFS client with TLS or mutual TLS (mTLS) support [How to > Enhancing security > Data encryption in transit > Establishing encryption in transit for regional file share. > Establishing encryption in transit for regional file share](https://cloud.ibm.com/docs/vpc?topic=vpc-file-storage-vpc-eit-tls) in Virtual Private Cloud (VPC) documentation in [IBM Cloud Docs](https://cloud.ibm.com/docs).

### About this task

TLS adds an encryption layer to NFS traffic, safeguarding sensitive information from interception or tampering during transmission. By enabling TLS in NFS, you can enforce secure connections, maintain data integrity, and comply with security best practices.

Use Stunnel to enable TLS in older clients without native TLS support.

### Procedure

1. Install Stunnel on the client side.
2. Configure Stunnel (
`/etc/stunnel/stunnel.conf`
) to forward traffic to the NFS port.
For example,

```
pid = /var/run/stunnel/stunnel.pid
cert = /home/dpp/workspace/TLS_certificates/vm1.crt
key = /home/dpp/workspace/TLS_certificates/vm1.key
CAfile = /home/dpp/workspace/TLS_certificates/ca.crt
socket = r:TCP_NODELAY=1
foreground = yes
debug = 7
output = /var/log/stunnel.log
renegotiation = no
[nfs4]
client = yes
accept = 127.0.0.1:49152
connect = 23.13.161.10:2049
sslVersion = TLSv1.3
ciphers = ALL
verify = 2
```
3. Change the
`verify`
value for TLS or mTLS as needed.

> 📝 **Note:** Note:
Optional: Remove the
`cert`
and
`key`
entries if mTLS is not required on the client.
4. Start Stunnel.

```plaintext-ibm
stunnel /etc/stunnel/stunnel.conf
```

Copy to clipboard
5. Mount NFS through Stunnel.

```plaintext-ibm
mount -vv -t nfs -o rw -o port=49152 127.0.0.1:/exportfs0 /mnt/
```
