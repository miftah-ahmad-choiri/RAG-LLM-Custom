## Disabling Kerberos encryption for Ceph NFS services

Last Updated
: 2026-06-25

Learn to disable Kerberos encryption on an NFS cluster using the command line.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- Running and healthy IBM Storage Ceph  cluster.
- Ceph NFS services is installed and configured on the server.
- Kerberos encryption enabled.

### About this task

To disable Kerberos encryption for the Ceph NFS services, you can configure the cluster to either

- Not use Kerberos at all (falling back to `sec=sys`).
- Use Kerberos authentication (krb5) but disable privacy encryption by not using krb5p.

In both scenarios, changes to the NFS share definition are required. A system administrator must implement these changes, which involve modifying server-side configuration files typically /etc/exports.

An alternative approach is to adjust the mount options on the client side This method is only applicable if the existing share definition on the server already includes the
sys
option under the
sectype
parameter.

### Procedure

1. Unmount the share.

```plaintext-ibm
umount EXPORT_NAME
```

Copy to clipboard

For example,

```
$ umount mnt/nfs
```
2. Modify the configuration file (ganesha.config) to remove encryption. In the
`Export`
section, change
`SecType=sys`
to disable Kerberos encryption.

```plaintext-ibm
SecType=”sys”
```

Copy to clipboard
3. Mount the share again with the updated configuration file.

```plaintext-ibm
mount -t nfs GANESHA_HOST_NAME:PSEUDO_PATHMOUNT_POINT
```

Copy to clipboard

For example,

```
$ mount -t nfs 192.168.10.10:/foo /mnt
```
