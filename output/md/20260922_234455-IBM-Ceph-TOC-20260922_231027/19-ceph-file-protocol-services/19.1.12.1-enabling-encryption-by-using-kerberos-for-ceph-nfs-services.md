## Enabling encryption by using Kerberos for Ceph NFS services

Last Updated
: 2026-06-25

Learn to configure Kerberos encryption with Ceph NFS services by using the command-line interface.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running and IBM Storage Ceph cluster.
- Ceph NFS services are installed and configured on the server.
- A working Kerberos Key Distribution Centre (KDC).
- Ensure that the domain name is present for all the nodes in the Ceph cluster and NFS client nodes. Use the Fully Qualified Domain Name (FQDN).
- The NFS node is time synchronised with KDC

### About this task

Use this procedure to configure the Ceph File System (CephFS) to work with Ceph NFS services using Kerberos-based security. This setup provides strong authentication and protects client/server communication over the network.

Kerberos support in Ceph NFS services is available from version 4.0 onward. Ensure that your Ceph cluster is running a supported version of Ceph NFS services.

### Procedure

1. Set up the Kerberos client.

> 📝 **Note:** Note:
The Kerberos client machine must be time-synchronised with the KDC. It is advised to sync KDC and clients by using NTP. A time difference of 5 minutes or more leads to Kerberos authentication failure and throws a clock skew error.

1. Check whether you have the following RPMs. If not, install them using the
dnf install
command.

```
[root@ceph-host ~]# rpm -qa | grep krb5
krb5-libs-1.20.1-9.el9_2.x86_64
krb5-pkinit-1.20.1-9.el9_2.x86_64
krb5-workstation-1.20.1-9.el9_2.x86_64
```
2. Update the
krb5.conf
file similar to the configuration file on the KDC server.
For example,

```
[root@ceph-host ~]# cat /etc/krb5.conf
# To opt out of the system crypto-policies configuration of krb5, remove the
# symlink at /etc/krb5.conf.d/crypto-policies which will not be recreated.
includedir /etc/krb5.conf.d/
[logging]
    default = [FILE:/var/log/krb5libs.log]
    kdc = [FILE:/var/log/krb5kdc.log]
    admin_server = [FILE:/var/log/kadmind.log]
[libdefaults]
    dns_lookup_realm = false
    ticket_lifetime = 24h
    renew_lifetime = 7d
    forwardable = true
    rdns = false
    pkinit_anchors = [FILE:/etc/pki/tls/certs/ca-bundle.crt](file:///etc/pki/tls/certs/ca-bundle.crt)
    spake_preauth_groups = edwards25519
 dns_canonicalize_hostname = fallback
    qualify_shortname = ""
    default_realm = REALM_NAME.COM
   default_ccache_name = KEYRING:persistent:%{uid}
[realms]
  REALM_NAME.COM = {
     kdc = 10.0.10.222:88
     admin_server = 10.0.10.222:749
  }
[domain_realm]
  .REALM_NAME.COM = NAME.REALM_NAME.COM
  REALM_NAME.COM = NAME.REALM_NAME.COM
```

2. Configure NFS specific Kerberos.

Create service principles for both the NFS server and client. The respective keys are stored in the keytab files. These principles are required to set up the initial security context (required by GSS_RPCSEC). These service principles have a format like `nfs/@REALM`. You can copy the /etc/krb5.conf from the working system to the Ceph nodes.

Perform the following 2 steps on all the Ceph nodes where Ceph NFS services containers are running and on all the NFS clients.

1. Create a service principal for the host.

```
[root@ceph-host ~]# kinit admin/admin

Password for admin/admin@XYZ.ABC.COM:
kadmin:  addprinc -randkey nfs/ceph-host.abc.com

Principal "nfs/ceph-host.abc.com@XYZ.ABC.COM" created.
```

3. Change the Ceph NFS services container settings in the Ceph environment.

1. Get the existing Ceph NFS services container configuration.

```
[ceph: root@ceph-host /]# ceph orch ls --service-type nfs --export
service_type: nfs
service_id: c_ganesha
service_name: nfs.c_ganesha
placement:
  hosts:
  - ceph-host-node1-installer
  - ceph-host-qp49z7-node2
  - ceph-host-qp49z7-node3
spec:
  port: 2049
```
2. Modify the container configuration file
nfs.yaml
to pass the
/etc/krb5.conf
and
/etc/krb5.keytab
files to the container from the host. NFS refers to these files at run time to validate incoming service tickets and secure the communication between NFS and the NFS client (krb5p).

```
[root@ceph-host ~]# cat nfs.yaml
service_type: nfs
service_id: c_ganesha
service_name: nfs.c_ganesha
placement:
  hosts:
  - ceph-host-node1-installer
  - ceph-host-node2
  - ceph-host-node3
spec:
  port: 2049
extra_container_args:
  - "-v"
  - "/etc/krb5.keytab:/etc/krb5.keytab:ro"
  - "-v"
  - "/etc/krb5.conf:/etc/krb5.conf:ro"
```
3. Make the modified
nfs.yaml
file available inside the
`Cephadm`
shell.


### What to do next

You can validate the setup by accessing the share as a normal user `PQR`, without Kerberos tickets. You get a permission denied message.

```
[pqr@ceph-host ~]$ klist
klist: Credentials cache 'KCM:1001' not found
[abc@ceph-host ~]$ cd /mnt
-bash: cd: /mnt: Permission denied
```

Access the share with the Kerberos ticket.

```
[pqr@ceph-host ~]$ kinit pqrabc
Password for pqr@XYZ.ABC.COM:
[pqr@ceph-host ~]$ klist
Ticket cache: KCM:1001
Default principal: pqr@XYZ.ABC.COM

Valid starting     Expires            Service principal
10/27/23 12:57:21  10/28/23 12:57:17  krbtgt/XYZ.ABC.COM@XYZ.ABC.COM
  renew until 10/27/23 12:57:21
[pqr@ceph-host ~]$ cd /mnt
[pqr@ceph-host mnt]$ klist
Ticket cache: KCM:1001
Default principal: pqr@XYZ.ABC.COM

Valid starting     Expires            Service principal
```
