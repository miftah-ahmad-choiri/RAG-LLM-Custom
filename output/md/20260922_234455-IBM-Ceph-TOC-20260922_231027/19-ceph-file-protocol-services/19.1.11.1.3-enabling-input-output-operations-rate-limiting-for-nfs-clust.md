## Enabling input/output operations rate-limiting for NFS cluster

Last Updated
: 2026-06-25

Learn how to enable the input/output operations (IOPS) rate-limiting for NFS cluster by using the command-line.

### About this task

You can set input/output operations (IOPS) limits either per client or per share to ensure an even distribution of workload across the cluster.

> 📝 **Note:** Note:
The limit for IOPS rate-limiting is a minimum of 10 IOPS and a maximum of 16384 IOPS.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A healthy and running IBM Storage Ceph cluster.
- An NFS cluster.

### Procedure

Run the following command to enable bandwidth rate-limiting for an NFS cluster.

```plaintext-ibm
ceph nfs cluster qos enable ops_control CLUSTER_ID qos_type:PerShare|PerClient|PerShare_PerClient [max_export_iops VALUE] [max_client_iops VALUE]
```

Copy to clipboard

Where,

- CLUSTER_ID is the NFS cluster ID.
- qos_type is the type of ops control. It can be PerShare, PerClient or PerShare_PerClient.
- - If PerShare qos_type is selected, then the cluster-level QoS configuration applies to all shares created on that NFS cluster. It requires the export_ops_count parameter.
- If PerClient qos_type is selected, then the cluster-level QoS configuration applies to all clients accessing shares created on that cluster. It requires the client_ops_count parameter.
- If PerShare_PerClient qos_type is selected, then the cluster-level configuration applies to all shares as well as all clients of that NFS cluster. It requires both export_ops_count and client_ops_count parameters.

  - If PerShare qos_type is selected, then the cluster-level QoS configuration applies to all shares created on that NFS cluster. It requires the export_ops_count parameter.
  - If PerClient qos_type is selected, then the cluster-level QoS configuration applies to all clients accessing shares created on that cluster. It requires the client_ops_count parameter.
  - If PerShare_PerClient qos_type is selected, then the cluster-level configuration applies to all shares as well as all clients of that NFS cluster. It requires both export_ops_count and client_ops_count parameters.
- max_export_iops is the count of IOPS operations for a share.
- max_client_iops is the count of IOPS operations for a client of a share.

> 📝 **Note:** Note:
If this command is used to update the
qos_type
, make sure to update all the shares with the required parameters.

Example of IOPS rate-limiting for
PerShare_PerClient
,
clust_nfs
is the NFS cluster ID

```
[ceph: root@ceph-node-0 /]# ceph nfs cluster qos enable ops_control clust_nfs PerShare_PerClient --max_export_iops 2000 --max_client_iops 3000
[ceph: root@ceph-node-0 /]# ceph nfs cluster qos get clust_nfs
{
  "combined_rw_bw_control": true,
  "enable_bw_control": true,
  "enable_iops_control": true,
  "enable_qos": true,
  "max_client_combined_bw": "200.0MB",
  "max_client_iops": 3000,
  "max_export_combined_bw": "200.0MB",
  "max_export_iops": 2000,
  "qos_type": "PerShare_PerClient"
}
```

Example of IOPS rate-limiting for
PerShare

```
[ceph: root@ceph-node-0 /]# ceph nfs cluster qos enable ops_control clust_nfs PerShare --max_export_iops 4000
```
