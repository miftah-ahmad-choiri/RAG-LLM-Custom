## NFSv4 delegation considerations and expected behavior

Last Updated
: 2026-09-06

NFSv4 delegations might not be granted in certain conditions even when a file open operation succeeds. This behavior is expected.

When NFSv4 delegations are enabled, the NFS server might not grant a delegation even though the file open operation succeeds. This behavior is expected. When the condition that prevents the delegation is resolved, subsequent open operations can obtain a delegation.

The NFS server does not grant a delegation in the following situations:

Client and protocol behavior

The NFS client explicitly requests that no delegation be granted.

The client callback channel is unavailable and the NFS server cannot recall an existing delegation.

The client repeatedly fails to return recalled delegations. In this situation, the NFS server temporarily stops granting new delegations until the client establishes a new client ID by remounting the share.

File eligibility and configuration

The object is not a regular file. The NFS server does not grant delegations for directories or special files.

Delegations are disabled in the NFS server, share configuration, or client access rules.

The delegation type requested by the client does not match the delegation types that the share configuration allows.

The NFS server has reached the configured limit for delegated files. Additional files are opened without a delegation until existing delegations are returned.

Conflicts and delegation recall

Another client has a conflicting open request for the file, such as a write open.

An NFSv3 or Network Lock Manager (NLM) lock conflicts with the requested delegation.

The NFS server is recalling an existing delegation because of a conflicting operation. During the recall process, new open requests can be delayed or can succeed without receiving a new delegation.

CephFS temporarily rejects the delegation lease request while file system state is being reconciled after a delegation recall, conflict, or failover event. In this case, the open operation succeeds, but no delegation is granted.

High availability (HA) and failover

After an NFS server failover, the NFS server rejects new open requests with a grace or recovery error until state recovery completes.

After recovery completes, clients reclaim previously established state, including delegations.

Delegations revoked before the failover cannot be reclaimed and must be granted again through subsequent open operations.
