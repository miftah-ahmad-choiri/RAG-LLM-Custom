## Configuring NFSv4 delegations for Ceph NFS shares

Last Updated
: 2026-09-06

Configure NFSv4 delegations for CephFS shares that are served through NFS.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- An NFS cluster is deployed and operational.
- You have administrative privileges to modify NFS configuration settings.
- You are using NFSv4.1 or later.
- You are using NFSv4 shares with a CephFS backend.

> 📝 **Note:** Important:

- Cluster-level delegations must permit delegations before share-level or client-level settings can take effect.

- Delegation behavior follows a hierarchical configuration model. Higher-level settings determine whether lower-level settings can enable delegations.

### About this task

Write delegations in NFSv4 improve performance and scalability by reducing communication between NFS clients and NFS, while also decreasing workload on NFS gateways.

Read delegations in NFSv4 improve performance by allowing an NFS client to cache file data locally, enabling the client to read files without server communication and reducing network message overhead.

Delegation settings are evaluated in the following order:

1. Matching `CLIENT` block
2. `EXPORT` block
3. `EXPORT_DEFAULTS` block

The effective delegation setting is determined as follows:

- A matching `CLIENT` block overrides the parent `EXPORT` setting when Delegations is explicitly configured in the client definition.
- If a `CLIENT` block does not specify Delegations, the client inherits the setting from the parent `EXPORT`.
- If an `EXPORT` does not specify Delegations, it inherits the setting from `EXPORT_DEFAULTS`.
- If an `EXPORT` explicitly specifies Delegations = None, that value is retained and does not inherit a value from `EXPORT_DEFAULTS`.

For example,EXPORT_DEFAULTS { Delegations = RW; } EXPORT { Delegations = None; CLIENT { Clients = 10.0.67.194; Delegations = RW; } }
