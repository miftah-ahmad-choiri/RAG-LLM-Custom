## Update QoS limits in SMB

Last Updated
: 2026-06-25

You can configure and manage IOPS and bandwidth rate limiting for SMB shares in Ceph. This feature provides Quality of Service (QoS) controls to optimize performance and resource usage across clients.

### Before you begin

Before you begin, make sure that you have a healthy and running
IBM Storage Ceph
cluster.

-

### About this task

QoS parameters control read and write operations for SMB shares. You can set limits for IOPS, bandwidth, and delay thresholds.

These limits apply to individual SMB shares and help enforce performance boundaries and optimize workloads.

You can configure QoS using the following methods:

- CLI commands (imperative)
- YAML manifests (declarative)

### Updating QoS limits with the imperative method

Configure and manage IOPS and bandwidth rate limiting for SMB shares in Ceph by using the imperative method.

#### Procedure

1. Log in to the
`cephadm`
shell.
For example,

```
[root@host01 ~]# cephadm shell
```
2. Run the following command to update QoS configuration.

```plaintext-ibm
ceph smb share update cephfs qos <cluster_id> <share_id> [--read-iops-limit=<int>] [--write-iops-limit=<<int>>] [--read-bw-limit=<<int>>] [--write-bw-limit=<<int>>] [--read-delay-max=<<int>>] [--write-delay-max=<<int>>]
```

Copy to clipboard

- cluster_id: replace with the unique identifier for the Ceph cluster.
- share_id: replace with unique identifier for the SMB share within the specified Ceph cluster.
- <int>: replace with the integer values for QoS limits.

For example,

```
ceph smb share update cephfs qos foo bar \
  --read-iops-limit=100 \
  --write-iops-limit=200 \
  --read-bw-limit=1048576 \
  --write-bw-limit=2097152 \
  --read-delay-max=5 \
  --write-delay-max=5
```

  - cluster_id: replace with the unique identifier for the Ceph cluster.
  - share_id: replace with unique identifier for the SMB share within the specified Ceph cluster.
  - <int>: replace with the integer values for QoS limits.

### Updating QoS limits with the declarative method

Configure and manage IOPS and bandwidth rate limiting for SMB shares in Ceph by using the declarative method.

#### Procedure

Update the SMB share resource YAML file with QoS parameters.

```
resource_type: ceph.smb.share
cluster_id: tango
share_id: sp1
name: "Staff Pics"
cephfs:
  volume: cephfs
  path: /pics
  subvolumegroup: smbshares
  subvolume: staff
  qos:
    read_iops_limit: 100      # Max 100 read operations per second
    write_iops_limit: 50      # Max 50 write operations per second
    read_bw_limit: 1048576    # 1 MiB/s read bandwidth limit
    write_bw_limit: 2097152    # 512 KiB/s write bandwidth limit
    read_delay_max: 5         # Max 5 seconds delay for read operations
```

| Parameter | Value | Description |
| --- | --- | --- |
| resource_type | ceph.smb.share | Specifies the resource type as an SMB share in Ceph. |
| cluster_id | tango | Unique identifier for the Ceph cluster. |
| share_id | sp1 | Unique identifier for the SMB share within the cluster. |
| name | "Staff Pics" | Display name for the SMB share. |
| cephfs.volume | cephfs | Name of the CephFS volume associated with the share. |
| cephfs.path | /pics | Path in the CephFS where the share is located. |
| cephfs.subvolumegroup | smbshares | Subvolume group that organizes SMB shares. |
| cephfs.subvolume | staff | Subvolume name within the group for this share. |
| qos.read_iops_limit | 100 | Maximum number of read operations per second. |
| qos.write_iops_limit | 50 | Maximum number of write operations per second. |
| qos.read_bw_limit | 1048576 | Maximum read bandwidth in bytes per second (1 MiB/s). |
| qos.write_bw_limit | 2097152 | Maximum write bandwidth in bytes per second (512 KiB/s). |
| qos.read_delay_max | 5 | Maximum delay for read operations in seconds. |
| qos.write_delay_max | 5 | Maximum delay for write operations in seconds. |

#### Results

The specified QoS limits are applied to the SMB share. Read and write IOPS, bandwidth, and delay settings take effect immediately, ensuring the share operates within the configured performance boundaries.
