## Setting up TLS in NFS clients using tlshd (ktls-utils)

Last Updated
: 2026-06-25

Learn how to use tlshd (ktls-utils) to enable TLS or mutual TLS (mTLS) for NFS clients with native TLS capability.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- Install TLS backend libraries (OpenSSL) based on your build configuration.
- Enable Kernel TLS (KTLS) if you are using OpenSSL and ktls.
- Generate and make accessible the TLS certificates and keys.

> 📝 **Note:** Note:
You must have access to the following TLS certificates:

- CA certificate (`ca.crt`)
- Server certificate (`ganesha.crt`)
- Private key (`ganesha.key`)

  - CA certificate (`ca.crt`)
  - Server certificate (`ganesha.crt`)
  - Private key (`ganesha.key`)
- Set correct file permissions for the certificate and key files so that NFS can access them.
- Ensure client-side support for TLS or mTLS (NFS client tools that support `xprtsec=tls` or `xprtsec=mtls`).

For more information on configuring the NFS client with TLS or mutual TLS (mTLS) support [How to > Enhancing security > Data encryption in transit > Establishing encryption in transit for regional file share. > Establishing encryption in transit for regional file share](https://cloud.ibm.com/docs/vpc?topic=vpc-file-storage-vpc-eit-tls) in Virtual Private Cloud (VPC) documentation in [IBM Cloud Docs](https://cloud.ibm.com/docs).

### About this task

Enable TLS or mutual TLS (mTLS) for NFS clients using tlshd (ktls‑utils). Use this procedure when your environment supports native NFS TLS and you want to secure traffic without relying on external tunneling tools.

### Procedure

1. Install ktls-utils.
2. Configure
`/etc/tlshd.conf`
with TLS settings.
3. Start the tlshd service and mount the file share.

```plaintext-ibm
mount -vv -t nfs -o vers=4 -o xprtsec=mtls -o rw <server_ip>:/exportfs0 /mnt
```

Copy to clipboard

> 📝 **Note:** Note:
For native mount options, update the OS to the latest version because recent RHEL/CentOS kernels include TLS-related fixes.

### Results

When TLS or mTLS is enabled, NFS mounts use encrypted communication between the client and server, ensuring data confidentiality and integrity. TLS secures traffic and validates the server certificate. mTLS adds stronger authentication by validating both client and server certificates.

> 📝 **Note:** Note:
Incorrect settings, such as missing certificates or mismatched
`xprtsec`
options, cause mount failures with
`EACCES`
errors.
