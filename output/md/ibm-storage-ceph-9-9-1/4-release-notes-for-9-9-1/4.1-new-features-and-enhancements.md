## New features and enhancements

Last Updated
: 2026-06-25

This section lists all the major updates, and enhancements introduced in this release of IBM Storage Ceph.

Enhanced cluster-level QoS configuration for NFS services

Previously, cluster-level Quality of Service (QoS) settings for NFS were applied only at the host level, limiting consistency across the cluster.

With this enhancement, QoS settings are now enforced uniformly across all hosts in the NFS cluster. A new cluster_qos_port parameter is added to the NFS specification to define the inter-node communication port required to maintain QoS settings.

Administrators can also adjust the inter-host communication interval by using the following command, providing greater control over QoS synchronization behavior:

```plaintext-ibm
ceph nfs cluster qos set CLUSTER_ID MSG_INTERVAL:INT
```

(IBMCEPH-13145)

New support for NFS daemon colocation with flexible port configuration

Previously, `cephadm` restricted placement of multiple NFS daemons on the same host, limiting deployment flexibility and capacity scaling.

With this enhancement, administrators can enable daemon colocation and configure custom ports. `cephadm` ensures automatic redistribution during node failures, maintaining the desired daemon count and improving resilience.

(IBMCEPH-12830)

Enhanced bind and monitoring address configuration

Previously, bind and monitoring addresses for NFS services were not configurable through `cephadm` CLI or service specifications, limiting deployment flexibility.

With this enhancement, administrators can define bind and monitoring addresses and ports per host using CLI or service specifications. This enables multiple NFS services to run on the same host without conflicts and improves network configuration flexibility.

(IBMCEPH-11486)

Enhanced default NFS ingress mode to haproxy-protocol

Previously, the default ingress mode for NFS clusters was set to haproxy-standard, which was not aligned with recommended configurations.

With this enhancement, the default ingress mode is now haproxy-protocol, providing improved consistency and better alignment with expected deployment configurations.

(IBMCEPH-11823)

New support for NFS share delegation configuration

Previously, Ceph did not allow administrators to configure delegation types (read, write, readwrite, none) for NFS shares through `cephadm`.

With this feature, delegation settings can now be configured using CLI and YAML specifications, enabling better control over client caching behavior and improving performance tuning capabilities.

(IBMCEPH-12332)

Improved
`cephadm`
upgrade workflow with failure-domain scoped OSD upgrades

Previously, OSD upgrades were not aligned with physical failure domains, leading to less controlled upgrade operations.

With this enhancement, `cephadm` supports failure-domain scoped upgrades using CRUSH bucket parameters, enabling controlled, staged upgrades within racks, chassis, or hosts. This improves operational safety and upgrade efficiency.

(IBMCEPH-11980)

Added automated deployment of Ceph Object Gateway D3N/D4N using
`cephadm`

Previously, deploying Ceph Object Gateway D3N/D4N configurations required manual setup and orchestration, increasing complexity and risk of misconfiguration.

With this enhancement, `cephadm` now automates the deployment of Ceph Object Gateway D3N/D4N configurations, simplifying setup and ensuring consistent deployment across clusters. This reduces operational effort and improves reliability for object storage workloads.

(ISCE-773)

Image vendor detection enhancement in cephadm inspect-image

Previously, there was no reliable way to determine whether a Ceph container image was built by IBM or Red Hat when inspecting images at runtime.

With this enhancement, `cephadm inspect-image` now detects and reports the image vendor as either `ibm` or `redhat`. This detection is based on the /etc/redhat-storage-release file inside the container image, enabling `cephadm` to identify the vendor from the release string. As a result, this enhancement provides clearer visibility into container image origin, improving troubleshooting, validation, and operational awareness when working with Ceph images.

(IBMCEPH-13854)

SSH hardening and command execution enhancements for
`cephadm`

Previously, configuring a `cephadm` user required manual steps, including copying SSH public keys and updating the sudoers file. Additionally, `cephadm` executed commands directly over SSH without a centralized control mechanism. Arbitrary command execution paths were not standardized, and SSH hardening was not available.

With this enhancement, new SSH hardening capabilities and supporting commands are introduced:

- Automated SSH user setup.

```plaintext-ibm
cephadm setup-ssh-user --ssh-user SSH_USER --ssh-pub-key SSH_PUB_KEY
```

- Standardized command execution interface.

```plaintext-ibm
cephadm exec --command COMMAND
```

                All bash command execution in `cephadm` now uses this interface, providing consistent handling across the `mgr/cephadm` code.
- SSH hardening enablement.

```plaintext-ibm
ceph cephadm prepare-host-and-enable-ssh-hardening USER [HOST_LABEL]
```

As a result, `cephadm` provides a more secure and consistent SSH execution model, reduces manual configuration steps, and enables hardened command execution paths across managed hosts.

New Ceph Object Gateway multisite archive zone support

Previously, the Ceph Dashboard supported configuration of standard Ceph Object Gateway multisite replication but did not support creating or managing archive zones. As a result, users had to rely on CLI commands to configure archive zones, leading to an inconsistent user experience and more complex day-two operations.

The Dashboard experience remains consistent with the standard multisite UI, requiring minimal changes to existing workflows. In addition, the Dashboard surfaces archive zone information and operational details, enabling monitoring and management similar to standard zones. As a result, users can configure and manage archive zones directly from the Dashboard, improving usability, consistency, and operational efficiency.

### Ceph Block Device

Images can now be added to mirrored Ceph Block Device groups without disabling mirroring

Previously, adding an image to an Ceph Block Device group with mirroring enabled required disabling mirroring, adding the image, and then re-enabling mirroring. As a result, the entire group was resynchronized to the secondary cluster, causing significant network overhead and increased synchronization time.

With this enhancement, images can be added to a mirrored Ceph Block Device group while mirroring remains enabled by using the `rbd group image add` command. Only the newly added image is synchronized to the secondary cluster, while existing images are not resynchronized.

As a result, this reduces unnecessary data transfer, lowers synchronization overhead, and improves operational efficiency.

```plaintext-ibm
rbd group image add POOL/GROUP POOL/IMAGE
```

### Ceph Object Gateway

Enhanced Lua performance using bytecode caching

Previously, Lua scripts were compiled on every execution, leading to unnecessary overhead and reduced performance.

With this enhancement, Lua bytecode is cached in memory, eliminating repeated compilation and improving execution efficiency for both small and large object workloads.

(IBMCEPH-12115)

Enhanced Ceph Object Gateway policy evaluation logging and testing

Previously, visibility into policy evaluation behavior was limited, making it difficult to trace decisions and troubleshoot access issues.

With this enhancement, setting the rgw_copious_policy_logging parameter to true enables detailed tracing of policy evaluation in logs. In addition, the `rgw-policy-test` command provides verbose policy evaluation from the command line, helping administrators analyze and validate policy behavior more effectively.

(IBMCEPH-8459)

Enhanced lifecycle processing efficiency for multi-rule configurations

Previously, lifecycle operations involving multiple overlapping rules required multiple passes over objects, impacting performance in large-scale deployments.

With this enhancement, rules are grouped and evaluated in a single pass, improving performance and scalability for multi-site environments.

(IBMCEPH-12820)

Enhanced support for
`RestrictPublicBuckets`
in PublicAccessBlock configuration

Previously, setting the `RestrictPublicBuckets` option in the PublicAccessBlock configuration had no effect on bucket access behavior because the setting was not implemented.

With this enhancement, support for `RestrictPublicBuckets` is implemented, ensuring that the setting is enforced as expected and improving control over public access restrictions for buckets.

(IBMCEPH-10584)

Enhanced support for Lua-based abort requests

Previously, there was no way to abort a Ceph Object Gateway (`rgw`) request based on the result of a Lua script. If a Lua script encountered a syntax or runtime error, Ceph Object Gateway logged the error but continued processing the request.

With this enhancement, Lua scripts can now return the RGW_ABORT_REQUEST error code to explicitly signal that the request should be aborted. Ceph Object Gateway interprets this return value as `-EPERM` and stops processing the request. This return value is evaluated only in the prerequest context and is ignored in other RGW request-processing contexts. As a result, users can implement more effective request control using Lua scripts, enabling conditional request rejection and improved policy enforcement.

New CephFS subvolume encryption support with FScrypt

### Ceph NVMe-oF gateway

New support for BYOK in NVMe-oF namespaces

Previously, NVMe-oF namespaces did not support user-provided encryption keys, limiting flexibility for secure deployments.

With this feature, Bring Your Own Key (BYOK) support is introduced for NVMe-oF namespaces, enabling users to manage encryption keys and strengthen data security.

(ISCE-3700)

Added support for RADOS namespaces

Previously, NVMe-oF gateways did not support mapping namespaces to RADOS namespaces, limiting flexibility in data organization.

With this enhancement, support for RADOS namespaces is added, enabling improved data isolation and organization within NVMe-oF environments.

(ISCE-3127)

New NVMe-oF gateway locality awareness for stretch clusters

Previously, NVMe‑oF gateways in a gateway group did not account for physical site location when performing failover, failback, or namespace load balancing. As a result, failover operations could select gateways in remote locations, failback could occur automatically before a site was fully recovered, and namespaces could be assigned to gateways outside their primary workload location.

With this enhancement, NVMe‑oF stretch cluster support introduces location‑aware behavior for gateways and namespaces. Gateways can now be assigned a location, which is used by failover and load‑balancing algorithms to prioritize local gateways and reduce cross‑site traffic. In addition, administrators can control failback behavior by setting a site to a disaster state, preventing automatic failback until the site is fully validated. Namespaces can also be assigned a location, enabling placement on gateways in the same site whenever possible and improving I/O locality.

(ISCE-2205)

New automatic NVMe-oF listener configuration

Previously, NVMe-oF subsystems required administrators to manually create and manage listeners for each NVMe‑oF gateway, including updating listeners during scale‑up and scale‑down operations.

With this enhancement, NVMe‑oF listeners can now optionally automatically added when a subsystem is created by using a network subnet. The system automatically adds and removes listeners during scale‑up and scale‑down operations, reducing manual configuration and simplifying NVMe‑oF gateway management.

For more information, see Defining an NVMe-oF subsystem.

(ISCE-2203)

New NVMe‑oF performance monitoring with
`ceph nvmeof top`

IBM Storage Ceph 9.9.1 introduces new real‑time performance monitoring capabilities for NVMe‑oF gateways through the integrated `ceph nvmeof top` commands. You can now monitor:

- Gateway CPU utilization using `ceph nvmeof top cpu`, which displays CPU usage for NVMe‑oF gateway threads.
- Subsystem and namespace I/O performance using `ceph nvmeof top io`, which provides read/write operations, throughput, latency, load‑balancing group, and QoS status.

These commands offer a refresh‑based, `top`‑style view that helps administrators quickly observe gateway and namespace performance directly from the Ceph CLI, without relying on external monitoring tools.

(ISCE-1424)

### NFS service

New NFS server gateway high availability support

This release introduces support for multiple active NFS gateways connected through a Virtual IP (VIP) managed by HAProxy. Previously, only a single active NFS server gateway was supported behind HAProxy, which limited scalability and did not meet customer expectations.

With this enhancement, if a gateway fails, client NFS connections are automatically maintained or re-established with another available gateway, ensuring high availability and minimal disruption.

(ISCE-2041)

New support for NFSv4 write delegations

Ceph NFS now supports NFSv4 write delegations, enabling NFS clients to perform certain write I/O operations locally. This enhancement improves file access efficiency, reduces the load on NFS gateways, and enhances overall write performance and scalability.

To enable write delegations, set the global delegations option in the NFSv4 block to `true`. Once enabled, delegation behavior can be dynamically controlled using configuration options within the `EXPORT`, `EXPORT_DEFAULTS`, and `CLIENT` blocks.

(ISCE-2033)

Added TLS support for NFS services

Previously, NFS communication did not provide built-in TLS encryption, requiring external solutions for secure data transfer.

With this feature, TLS support is introduced for NFS services, enabling secure communication between clients and servers.

(ISCE-1550)

### IBM Call Home

New Call Home awareness through health warnings

With this enhancement, a health warning is raised when Call Home is automatically enabled, ensuring that users are aware of the configuration and can take appropriate action if needed.

(IBMCEPH-13571)

Call Home enabled by default with improved status visibility

Previously, customers had to manually opt in to the Call Home feature, and its status was not prominently visible in the system interfaces.

With this enhancement, Call Home is enabled by default to proactively support customers by automatically reporting relevant environment data to IBM. Customers can disable Call Home if required. The first report is sent 24 hours after installation, allowing administrators time to opt out before any data is transmitted.

This enhancement also introduces improved visibility of Call Home status:

- In the CLI, the ceph -s command now displays an additional line indicating Call Home: activated or deactivated.
- In the Ceph Dashboard, the IBM Call Home option under the Settings menu shows whether the feature is enabled or disabled.

As a result, customers receive proactive support while maintaining clear visibility and control over Call Home behavior.
