## Configuring NFS service daemons

Last Updated
: 2026-06-25

You can configure NFS service on the dashboard for Ceph Object Gateway, CephFS, or both, after their configuration.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph.
- Ceph Object Gateway, CephFS, or both are installed and configured on the dashboard.
- Ceph Object Gateway login credentials are added to the dashboard.
- A dedicated pool enabled and tagged with custom tag of `nfs`.
- A minimum of `ganesha-manager` level of access.

### About this task

NFSv3 (version 3) is supported and enabled for clients that do not yet support NFSv4.2 mounts for CephFS file shares.

> 📝 **Note:** Note:
Mount a file share with NFSv3 only when NFSv4.2 is not supported on the client or server side. Both NFS protocols can be used.

> 📝 **Note:** Important:
When using object storage with the NFS service, object keys that contain or start with
`/`
might not appear as expected in NFS shares. To understand how object keys map to the NFS namespace and why this behavior occurs, see
NFS with Ceph Object Storage
.

For more information, see the following:

- Deploying the Ceph Object Gateway using the command line interface.
- Manually adding Ceph Object Gateway login credentials to the dashboard.
- Creating Ceph Object Gateway users.
- User roles and permissions.
- NFS cluster and share management

### What to do next

1. From the command-line, as a root user, check if the NFS service is active and running.

```plaintext-ibm
systemctl list-units | grep nfs
```

Copy to clipboard

For example,

```
[root@host01 ~]# systemctl list-units | grep nfs
```
2. View the NFS services from Administration
>
Services.

To create an NFS share, see Configuring NFS shares.

> 📝 **Note:** Note:
This documentation uses
*NFS share*
instead of the earlier term
*NFS export*
. In the Ceph Dashboard, labels and controls may still refer to NFS export.
