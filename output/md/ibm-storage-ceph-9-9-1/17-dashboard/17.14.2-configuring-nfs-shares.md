## Configuring NFS shares

Last Updated
: 2026-06-25

You can create, edit, and delete CephFS and Ceph Object Gateway NFS shares from the Ceph Dashboard. You can also share the CephFS namespaces over the NFS protocol.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph cluster.
- Root-level access to the bootstrapped host.
- A minimum of `NFS-manager` level of access on the Ceph dashboard.
- For NFS with Ceph Object Gateway, an existing Ceph Object Gateway bucket. For more information see Managing Ceph Object Gateway buckets.
- For NFS with Ceph File Systems, an existing CephFS volume and subvolume. For more information see Creating CephFS volumes and Creating CephFS subvolume.
- An existing NFS service. For more information, see Configuring NFS service daemons.

### About this task

Create an NFS cluster that creates a common recovery pool for all the NFS service daemons, a new user based on the CLUSTER_ID, and a common NFS service config RADOS objects.

NFSv3 (version 3) is supported and enabled for clients that do not yet support NFSv4.2 mounts for CephFS file shares.

Use NFSv4 for clients and servers that support NFSv4.2 or later.

For information about NFS cluster and share management through the command-line interface, see
NFS cluster and share management
.

*NFS share*

3. As a root user on the client host, create a directory and mount the NFS share.
Syntax:

```plaintext-ibm
mkdir -p /mnt/nfs/
mount -t nfs -o port=2049 HOSTNAME:EXPORT_NAME MOUNT_DIRECTORY
```

Example:


> 📝 **Note:** Important:

Object keys that contain or start with `/` might not appear as expected in an NFS share.

The NFS service interprets `/` as a directory separator. Some objects might be missing, appear as directories, or be inaccessible.

Avoid using
`/`
in object key names when accessing data through NFS shares. Use object storage APIs for consistent access.
