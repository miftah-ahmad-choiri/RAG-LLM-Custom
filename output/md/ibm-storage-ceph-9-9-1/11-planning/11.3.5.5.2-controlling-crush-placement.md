## Controlling CRUSH placement

Last Updated
: 2026-06-25

Learn how to control CRUSH placement.

The default CRUSH rule provides OSDs that are on different hosts. For instance:

```plaintext-ibm
chunk nr    01234567

step 1      _cDD_cDD
step 2      cDDD____
step 3      ____cDDD
```

Copy to clipboard

needs exactly *8* OSDs, one for each chunk. If the hosts are in two adjacent racks, the
first four chunks can be placed in the first rack and the last four in the second rack. Recovering
from the loss of a single OSD does not require using bandwidth between the two racks.

For instance:

```plaintext-ibm
crush-steps='[ [ "choose", "rack", 2 ], [ "chooseleaf", "host", 4 ] ]'
```

Copy to clipboard

creates a rule that selects two crush buckets of type *rack* and for each of them choose
four OSDs, each of them located in a different bucket of type *host*.

The rule can also be created manually for finer control.
