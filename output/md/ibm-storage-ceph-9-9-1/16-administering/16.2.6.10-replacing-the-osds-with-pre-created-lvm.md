## Replacing the OSDs with pre-created LVM

Last Updated
: 2026-06-25

After purging the OSD with the ceph-volume lvm zap command, if the directory is not present, then you can replace the OSDs with the OSD service specification file with the pre-created LVM.

### Prerequisites

- A running IBM Storage Ceph cluster.
- Failed OSD

### Procedure

1. Log into the `cephadm` shell:

Example

```plaintext-ibm
 [root@host01 ~]# cephadm shell
```

Copy to clipboard
2. Set the OSD service to an unmanaged state to prevent `cephadm` from automatically redeploying OSDs during removal.

> 📝 **Note:** Note:
If you skip this step,
`cephadm`
may redeploy OSDs automatically, causing conflicts with the removal operation.

Example

```plaintext-ibm
service_type: osd
service_id: <service_id>
unmanaged: true
```

Copy to clipboard
3. Apply the specification:

Example

```plaintext-ibm
ceph orch apply -i <osds.yaml>
```

Copy to clipboard
4. Run theorch ls cephcommand to confirm that the OSD service is set to the unmanaged state.
5. Remove the OSD:

Syntax

```plaintext-ibm
 ceph orch osd rm OSD_ID [--replace]
```

Copy to clipboard

Example

```plaintext-ibm
 [ceph: root@host01 /]# ceph orch osd rm 8 --replace
 Scheduled OSD(s) for removal
```

7. Zap and remove the OSD using the `ceph-volume` command:

Syntax

```plaintext-ibm
 ceph-volume lvm zap --osd-id OSD_ID
```

Copy to clipboard

Example


8. Check the OSD topology:

Example

```plaintext-ibm
 [ceph: root@host01 /]# ceph-volume lvm list
```

Copy to clipboard
9. Recreate the OSD with a specification file corresponding to that specific OSD topology:

Example

```plaintext-ibm
 [ceph: root@host01 /]# cat osd.yml
 service_type: osd
 service_id: osd_service
 placement:
   hosts:
   - host03
 data_devices:
   paths:
   - /dev/vg1/data-lv2
 db_devices:
   paths:
   - /dev/vg1/db-lv1
```

Copy to clipboard
10. Apply the updated specification file:

Example

```plaintext-ibm
ceph orch apply -i osd.yml
```

Copy to clipboard
11. Set the OSD service specification back to managed state. After you replace the disk, set the OSD service back to a managedstate so that `cephadm` can resume orchestration.

1. Update the OSD service specification.

```plaintext-ibm
unmanaged: false
```

Copy to clipboard
2. Apply the updated specification. This step allows `cephadm` to redeploy the OSD on the new device while reusing the existing OSD ID.

```plaintext-ibm
ceph orch apply -i <osds.yaml>
```

Copy to clipboard




  Copy to clipboard
12. Verify the OSD is back:

Example

```plaintext-ibm
 [ceph: root@host01 /]# ceph -s
 [ceph: root@host01 /]# ceph osd tree
```

Copy to clipboard
