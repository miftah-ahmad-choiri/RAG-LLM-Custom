## Managing data center monitor service hosts in stretch mode

Last Updated
: 2026-06-25

Use this information to add and remove data center monitor service (`mon`)
hosts in stretch mode. Managing data centers can be done by using the specification file or directly
on the Ceph cluster.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph cluster.
- Stretch mode is enabled on a cluster.
- Root-level access to the nodes.

### Managing a mon service with a service specification file

#### About this task

These steps detail how to add a
`mon`
service. To remove the service, use
the same steps of updating the service specification file, with removing the needed
information.

#### Procedure

1. Export the specification file for
`mon`
and save the output to
mon-spec.yaml
.
```plaintext-ibm
ceph orch ls mon --export > mon-spec.yaml
```

Copy to clipboard
After the file is exported, the YAML file can be edited.
2. Add the new host details.In the following example,
`host08`
is being added to the cluster into the DC2 data center bucket.

```
service_type: host

addr: 10.1.172.225

hostname: host08

labels:

- mon

---

service_type: mon

service_name: mon

placement:

label: mon

spec:

crush_locations:

host01:

- datacenter=DC1

host02:

- datacenter=DC1

host04:

- datacenter=DC2

host05:

- datacenter=DC2

host08:

- datacenter=DC2
```
3. Apply the specification file.
```plaintext-ibm
ceph orch apply -i mon-spec.yaml
```

Copy to clipboard
For example,

```
[ceph: root@host01 /]# eph orch apply -i mon-spec.yaml
Added host 'host08' with addr '10.1.172.225'
Scheduled mon update...
```

### Managing a mon with the command-line interface

#### About this task

These steps detail how to add a
`mon`
service. To remove the service, use
the same steps of updating with the CLI, with removing the needed information.

#### Procedure

1. Set the monitor service to
unmanaged
.
```plaintext-ibm
ceph orch set-unmanaged mon
```

Copy to clipboard
2. **Optional:**Use the
ceph orch ls
command to verify that the
service was set, as expected.For
example,

```
[ceph: root@host01 /]# ceph orch host ls
NAME                                 PORTS             RUNNING  REFRESHED  AGE  PLACEMENT
mon                                                        8/8  10m ago    19s  <unmanaged>
```
3. Add a new host with the
`mon`
label.
```plaintext-ibm
ceph orch host add HOST_NAME IP_ADDRESS_OF_HOST [--label=LABEL_NAME_1,LABEL_NAME_2]
```

Copy to clipboard
For
example,

```
[ceph: root@host01 /]# ceph orch host add host08 10.1.172.205 --labels=mon
```
4. Add a monitor service with CRUSH locations.
> 📝 **Note:** Note:
At this point, the
`mon`
is not running and is not managed by
`cephadm`
.

```plaintext-ibm
ceph mon add NODE:IP_ADDRESS datacenter=DC2
```

Copy to clipboard
For
example,

```plaintext-ibm
[ceph: root@host01 /]# ceph mon add host08 10.1.172.205 datacenter=DC2
```

Copy to clipboard
5. Deploy the monitor daemon using
`cephadm`
.
```plaintext-ibm
ceph orch daemon add mon host08
```

Copy to clipboard

For
example,

```
[ceph: root@host01 /]# ceph orch daemon add mon host08
Deployed mon.host08 on host 'host08'
```
6. Enable
`cephadm`
management for the monitor service.
```plaintext-ibm
ceph orch set-managed mon
```

Copy to clipboard
7. Start the newly added
`mon`
daemon.
```plaintext-ibm
ceph orch set-managed mgr
```

Copy to clipboard

#### What to do next
