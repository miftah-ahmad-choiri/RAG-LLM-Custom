## Setting custom NFS service configuration

Last Updated
: 2026-06-25

The NFS service cluster is defined in default configuration blocks. Using Ceph Orchestrator you can customize the configuration and that will have precedence over the default configuration blocks.

### Prerequisites

- A running IBM Storage Ceph cluster.
- Hosts are added to the cluster.
- All manager, monitor and OSD daemons are deployed.
- NFS service cluster created using the `mgr/nfs` module.

### Procedure

1. Log into the `cephadm` shell:

Example

```plaintext-ibm
[root@host01 ~]# cephadm shell
```

Copy to clipboard
2. The following is an example of the default configuration of NFS service cluster:

Example

```plaintext-ibm
# {{ cephadm_managed }}
NFS_CORE_PARAM {
        Enable_NLM = false;
        Enable_RQUOTA = false;
        Protocols = 4;
}

MDCACHE {
        Dir_Chunk = 0;
}

EXPORT_DEFAULTS {
        Attr_Expiration_Time = 0;
}

NFSv4 {
        Delegations = false;
        RecoveryBackend = 'rados_cluster';
        Minor_Versions = 1, 2;
}

RADOS_KV {
        UserId = "{{ user }}";
        nodeid = "{{ nodeid}}";
        pool = "{{ pool }}";
        namespace = "{{ namespace }}";
}

RADOS_URLS {
        UserId = "{{ user }}";
        watch_url = "{{ url }}";
}

RGW {
        cluster = "ceph";
        name = "client.{{ rgw_user }}";
}

%url    {{ url }}
```

Copy to clipboard
3. Customize the NFS service cluster configuration. The following are two examples for customizing the configuration:

- Change the log level:

Example

```plaintext-ibm
LOG {
 COMPONENTS {
     ALL = FULL_DEBUG;
 }
}
```

Copy to clipboard
- Add custom share block:

1. Create the user:

> 📝 **Note:** Note:
User specified in FSAL blocks should have proper caps for NFS service daemons to access the Ceph cluster.

Syntax

```plaintext-ibm
ceph auth get-or-create client.USER_ID mon 'allow r' osd 'allow rw pool=.nfs namespace=NFS_CLUSTER_NAME, allow rw tag cephfs data=FS_NAME mds' allow 'rw path=EXPORT_PATH'
```

Copy to clipboard

Example

```plaintext-ibm
[ceph: root@host01 /]# ceph auth get-or-create client.f64f341c-655d-11eb-8778-fa163e914bcc mon 'allow r' osd 'allow rw pool=.nfs namespace=nfs_cluster_name, allow rw tag cephfs data=fs_name' mds 'allow rw path=export_path'
```

Copy to clipboard
2. Navigate to the following directory:

Syntax

```plaintext-ibm
cd /var/lib/ceph/DAEMON_PATH/
```

Copy to clipboard

Example

```plaintext-ibm
[ceph: root@host01 /]# cd /var/lib/ceph/nfs/
```

Copy to clipboard

If the `nfs` directory does not exist, create a directory in the path.
3. Create a new configuration file:

Syntax

```plaintext-ibm
touch PATH_TO_CONFIG_FILE
```

Copy to clipboard

Example

```plaintext-ibm
[ceph: root@host01 nfs]#  touch nfs-ganesha.conf
```

Copy to clipboard
4. Edit the configuration file by adding the custom share block. It creates a single share and that is managed by the Ceph NFS share interface.

Syntax

```plaintext-ibm
EXPORT {
  Export_Id = NUMERICAL_ID;
  Transports = TCP;
  Path = PATH_WITHIN_CEPHFS;
  Pseudo = BINDING;
  Protocols = 4;
  Access_Type = PERMISSIONS;
  Attr_Expiration_Time = 0;
  Squash = None;
  FSAL {
    Name = CEPH;
    Filesystem = "FILE_SYSTEM_NAME";
    User_Id = "USER_NAME";
    Secret_Access_Key = "USER_SECRET_KEY";
  }
}
```

Copy to clipboard

Example

```plaintext-ibm
EXPORT {
  Export_Id = 100;
  Transports = TCP;
  Path = /;
  Pseudo = /ceph/;
  Protocols = 4;
  Access_Type = RW;
  Attr_Expiration_Time = 0;
  Squash = None;
  FSAL {
    Name = CEPH;
    Filesystem = "filesystem name";
    User_Id = "user id";
    Secret_Access_Key = "secret key";
  }
}
```

Syntax

Example

```plaintext-ibm
[ceph: root@host01 /]# ceph orch ls
```

Copy to clipboard
- List the hosts, daemons, and processes:

Syntax

```plaintext-ibm

```

Copy to clipboard

Example

Syntax
