## Powering down and rebooting with Ceph Orchestrator

Last Updated
: 2026-06-25

Use the Ceph Orchestrator to shut down and restart the IBM Storage Ceph cluster. In most cases, logging in to a single system is sufficient to power off the cluster.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph cluster.
- Root-level access to the node.

### About this task

The Ceph Orchestrator supports `start`, `stop`, and `restart` operations for powering down or rebooting the cluster.

Alternatively, use `systemctl` commands for powering down and rebooting the Ceph cluster. For more information, see Powering down and rebooting by using systemctl commands.

Use the following basic flow to power down an IBM Storage Ceph cluster. The procedure provides full in-depth information and commands for each step.

1. Stop all clients from using the Block Device image and Ceph Object Gateway on this cluster and on any other clients.
2. Stop the Ceph File System (CephFS) cluster and the MDS service.
3. Stop all component gateways related to block and file.These include: NFS, SMB, and NVMe-oF gateways.
4. Stop all ingress services and RADOS gateways.
5. If mirror dameons are used, stop all mirror daemons.
6. Stop the monitoring service components.
7. Set the noout flag.
8. Shut down all nodes.

### Powering down the IBM Storage Ceph cluster

#### Procedure

1. Stop all clients from using user Block Device images, CephFS volumes, and Ceph Object Gateways.
2. Log in to the
cephadm
shell.
For example,

```
[root@host01 ~]# cephadm shell
```

Before proceeding, the cluster must be in healthy state (
Health_OK
and all PGs
active+clean
). View the cluster state by using the
ceph -s
command.
3. When using CephFS, bring down the CephFS cluster.

```plaintext-ibm
ceph fs fail FS_NAME
 ceph status
 ceph fs set FS_NAME joinable false
 ceph mds fail FS_NAME:N
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph fs fail cephfs
[ceph: root@host01 /]# ceph status
[ceph: root@host01 /]# ceph fs set cephfs joinable false
[ceph: root@host01 /]# ceph mds fail cephfs:1
```

### Rebooting the IBM Storage Ceph cluster

#### Before you begin

Before you begin rebooting the cluster, power on and stabilize any network equipment before powering on the Ceph hosts and nodes.

#### Procedure

1. Power on all the Ceph hosts.
2. Log in to the administration node from the
`cephadm`
shell.
For example,

```
[root@host01 ~]# cephadm shell
```
3. Verify that all services are in the
running
state.

```plaintext-ibm
ceph orch ls
```

Copy to clipboard
4. Ensure that the cluster health is in the
Health_OK
status, by running the
ceph -s
command.
5. Unset the
noout
flag that was set in
Powering down the IBM Storage Ceph cluster
.

```plaintext-ibm
ceph osd unset noout
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph osd unset noout
```
6. When using Ceph File System (CephFS), make the CephFS cluster available by setting the
joinable
flag to
true
.

```plaintext-ibm
ceph fs set FS_NAME joinable true
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph fs set cephfs joinable true
```

#### What to do next

Verify that the cluster is in healthy state (Health_OK and all PGs active+clean). Run the ceph -s status command on a node with the client keyrings, for example, the Ceph Monitor or OpenStack controller nodes, to ensure that the cluster is healthy.
