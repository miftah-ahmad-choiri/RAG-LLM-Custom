## Deploying Ceph OSDs using advanced service specifications

Last Updated
: 2026-09-09

An OSD service specification describes a cluster storage layout by using disk properties, allowing you to define OSD configurations without specifying exact device names and paths.

You can deploy the OSD for each device and each host by defining a YAML or JSON file.

For command-based OSD deployment without a service specification, see Adding OSDs.

### Prerequisites

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph cluster.
- Hosts are added to the cluster.
- All manager and monitor daemons are deployed.

### Procedure

1. List the available devices:

Example

```plaintext-ibm
[ceph: root@host01 /]# ceph orch device ls --wide --refresh
```

Copy to clipboard
2. On the monitor node, create the osd_spec.yaml file:

Example

```plaintext-ibm
[root@host01 ~]# touch osd_spec.yaml
```

Copy to clipboard
3. Edit the osd_spec.yaml file to include the following details:

```plaintext-ibm
service_type: osd
service_id: SERVICE_ID
placement:
  host_pattern: '*' # optional
data_devices: # optional
  model: DISK_MODEL_NAME # optional
  paths:
  - /DEVICE_PATH
osds_per_device: NUMBER_OF_DEVICES # optional
db_devices: # optional
  size: # optional
  all: true # optional
  paths:
   - /DEVICE_PATH
encrypted: true
```

Copy to clipboard

> 📝 **Note:** Note:
Use a unique
service_id
for each OSD service specification.

The following examples start with common deployment scenarios and then progress to advanced deployment layouts.

**Common customer scenarios**

1. Deploy OSDs on all available devices:

Use this scenario when all hosts use the same storage layout and all available devices must be deployed as OSDs.

Example

```plaintext-ibm
service_type: osd
service_id: all-available-devices
placement:
  host_pattern: '*'
data_devices:
  all: true
encrypted: true
```

Copy to clipboard
2. Deploy OSDs on a specific host and device:

Use this scenario to deploy an OSD on a specific device on a single host.

Example

```plaintext-ibm
service_type: osd
service_id: osd_spec_host01
placement:
  hosts:
    - host01
data_devices:
  paths:
    - /dev/sdb
```

Copy to clipboard
3. Deploy OSDs using HDD data devices with SSD or NVMe DB devices:

Use this scenario to assign dedicated solid-state drives (SSDs) or NVMe devices for BlueStore DB/WAL while using HDDs for data storage.

Example

```plaintext-ibm
service_type: osd
service_id: osd_spec_hdd
placement:
  host_pattern: '*'
data_devices:
  rotational: 1
db_devices:
  model: Model-name
  limit: 2
---
service_type: osd
service_id: osd_spec_ssd
placement:
  host_pattern: '*'
data_devices:
  model: Model-name
db_devices:
  vendor: Vendor-name
```

Copy to clipboard
4. Deploy OSDs by using size filters:

Use this scenario when devices are filtered based on disk capacity.

Example

```plaintext-ibm
service_type: osd
service_id: osd_spec_size
placement:
  host_pattern: '*'
data_devices:
  size: '80G'
db_devices:
  size: '40G:'
  paths:
   - /dev/sdc
```

Copy to clipboard

**Advanced scenarios**

1. Advanced scenario with non-uniform nodes: This applies different OSD specs to different hosts depending on the host_pattern key.

Example

```plaintext-ibm
service_type: osd
service_id: osd_spec_node_one_to_five
placement:
  host_pattern: 'node[1-5]'
data_devices:
  rotational: 1
db_devices:
  rotational: 0
---
service_type: osd
service_id: osd_spec_six_to_ten
placement:
  host_pattern: 'node[6-10]'
data_devices:
  model: Model-name
db_devices:
  model: Model-name
```

Copy to clipboard
2. Advanced scenario with dedicated WAL and DB devices:

Example

```plaintext-ibm
service_type: osd
service_id: osd_using_paths
placement:
  hosts:
    - host01
    - host02
data_devices:
  paths:
    - /dev/sdb
db_devices:
  paths:
    - /dev/sdc
wal_devices:
  paths:
    - /dev/sdd
```

Copy to clipboard
3. Advanced scenario with multiple OSDs per device:

> 📝 **Note:** Note:
Deploy multiple OSDs per device only for supported and validated configurations.

Example

```plaintext-ibm
service_type: osd
service_id: multiple_osds
placement:
  hosts:
    - host01
    - host02
osds_per_device: 4
data_devices:
  paths:
    - /dev/sdb
```

Copy to clipboard
4. Advanced scenario: Deploy OSDs by using pre-created logical volumes:

```plaintext-ibm
 service_type: osd
 service_id: SERVICE_ID
 placement:
   hosts:
     - HOSTNAME
 data_devices: # optional
   model: DISK_MODEL_NAME # optional
   paths:
   - /DEVICE_PATH
 db_devices: # optional
   size: # optional
   all: true # optional
   paths:
   - /DEVICE_PATH
```

Copy to clipboard

Example

```plaintext-ibm
 service_type: osd
 service_id: osd_spec
 placement:
   hosts:
     - machine1
 data_devices:
   paths:
     - /dev/vg_hdd/lv_hdd
 db_devices:
   paths:
     - /dev/vg_nvme/lv_nvmes
```

4. Mount the YAML file under a directory in the container:

Example

```plaintext-ibm
[root@host01 ~]# cephadm shell --mount osd_spec.yaml:/var/lib/ceph/osd/osd_spec.yaml
```

Copy to clipboard
5. Navigate to the directory:

Example

```plaintext-ibm
[ceph: root@host01 /]# cd /var/lib/ceph/osd/
```

Copy to clipboard
6. Before deploying OSDs, do a dry run:

> 📝 **Note:** Note:
Always run a dry run before applying an OSD service specification. This step previews the deployment without deploying any daemons.

Example

```plaintext-ibm
[ceph: root@host01 osd]# ceph orch apply -i osd_spec.yaml --dry-run
```

Copy to clipboard
7. Deploy OSDs using service specification:

```plaintext-ibm
ceph orch apply -i _FILE_NAME_.yml
```

Copy to clipboard

Example

```plaintext-ibm
[ceph: root@host01 osd]# ceph orch apply -i osd_spec.yaml
```

Copy to clipboard
