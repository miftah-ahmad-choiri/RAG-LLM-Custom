## Setting the CRUSH location during bootstrap

Last Updated
: 2026-06-25

For hosts with multiple public networks, update the public networks in CIDR format, within the configuration file. Enhance the specification file by setting the monitor CRUSH location. Set this information during the bootstrap procedure.

### Before you begin

Before you begin, be sure that you have root-level access to the nodes.

### About this task

For more information about Ceph bootstrapping and different
cephadm bootstrap
command options, see
Bootstrapping a new storage cluster
.

### Procedure

1. Create a
cluster-spec.yaml
file.
The specification file adds the nodes to the
IBM Storage Ceph
cluster and also sets specific labels for where the services run.
For example,

```plaintext-ibm

hostname: host03

 - osd
 - mds
 - rgw

 root: default

 datacenter: DC2

 - osd
 - mds
 - rgw
---
service_type: host
addr: <host07 address>
hostname: host07

 - mon
------
service_type: mon
spec:
 crush_locations:
   host01:
     - datacenter=DC1
   host02:
     - datacenter=DC1
   host04:
     - datacenter=DC2
   host05:
     - datacenter=DC2

  label: mon
---

 label: "mgr"
---

 data_devices:
   all: true
---
service_type: rgw
service_id: objectgw
service_name: rgw.objectgw
placement:
 count: 2
 label: "rgw"
spec:
 rgw_frontend_port: 8080
```

2. Run the
cephadm bootstrap
command as the root user on the node that will serve as the initial Monitor node in the cluster.
The
`MONITOR_IP_ADDRESS`
value is the node’s IP address that you are using to run the
cephadm bootstrap
command. Run one of the following commands, based on your configuration needs.

- For hosts that are present on the same network.

```plaintext-ibm
cephadm bootstrap --apply-spec CONFIGURATION_FILE_NAME --mon-ip MONITOR_IP_ADDRESS --ssh-private-key PRIVATE_KEY --ssh-public-key PUBLIC_KEY --registry-url REGISTRY_URL --registry-username USER_NAME --registry-password PASSWORD
```

Copy to clipboard
- For hosts that are present on different networks.

```plaintext-ibm
cephadm bootstrap --apply-spec CONFIGURATION_FILE_NAME --mon-ip MONITOR_IP_ADDRESS --ssh-private-key PRIVATE_KEY --ssh-public-key PUBLIC_KEY --registry-url REGISTRY_URL --registry-username USER_NAME --registry-password PASSWORD --config ceph.conf
```

Copy to clipboard

The following configuration in the
ceph.conf
file defines the public network settings for the cluster:

```plaintext-ibm
[global]
public_network = 10.1.172.0/23,10.0.64.0/22
```

### What to do next

1. Verify the network configuration.

```plaintext-ibm
ceph config dump | grep network
```

Copy to clipboard

In the following example, the output confirms that there are multiple networks and that
`10.1.172.0/23`
and
`10.0.64.0/22`
are properly configured.

```
[ceph: root@host01 /]#  ceph config dump | grep network
global   advanced   public_network   10.1.172.0/23,10.0.64.0/22   *
```
