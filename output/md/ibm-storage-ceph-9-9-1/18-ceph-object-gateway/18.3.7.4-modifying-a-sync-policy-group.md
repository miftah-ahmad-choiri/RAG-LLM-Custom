## Modifying a sync policy group

Last Updated
: 2026-06-25

You can modify an existing sync policy group for the current zone group, or for a
specific bucket.

### Before you begin

- A running IBM Storage Ceph cluster.
- Root or `sudo` access.
- The Ceph Object Gateway is installed.
- When creating for an archive zone, be sure that the archive zone is created before the sync
policy group.

### About this task

When creating a sync policy for bucket granular replication for a sync policy group that has
changed from forbidden to enabled, a manual update might be
necessary to complete the sync process.

For example, if any data is written to `bucket1` when its policy is
forbidden, the data might not sync properly across zones after the policy is
changed to enabled. To properly sync the changes, run the bucket sync
run command on the sync policy. This step is also necessary if the bucket is resharded
when the policy is forbidden. In this case the bucket sync run
command must also be used after enabling the policy.

For more information about configuring an archive zone and bucket granular replication, see Configuring the archive zone.

### Procedure

1. Modify the sync policy group or a bucket policy, using the
--bucket
option.
```plaintext-ibm
radosgw-admin sync group modify --bucket=BUCKET_NAME --group-id=GROUP_ID --status=enabled | allowed | forbidden
```

Copy to clipboard
For
example,

```
[ceph: root@host01 /]# radosgw-admin sync group modify --group-id=mygroup1 --status=forbidden
```
2. **Optional:**Manually complete the sync process for bucket granular
replication.
> 📝 **Note:** Note:
This step is mandatory when using as part of an archive zone with bucket granular replication
if the policy has data written or the bucket was resharded when the policy was
forbidden
.

```plaintext-ibm
radosgw-admin bucket sync run
```

Copy to clipboard
For
example,

```
[ceph: root@host01 /]# radosgw-admin bucket sync run
```
