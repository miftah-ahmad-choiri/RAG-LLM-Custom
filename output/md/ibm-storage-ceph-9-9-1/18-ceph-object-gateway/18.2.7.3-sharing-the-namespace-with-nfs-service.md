## Sharing the namespace with NFS service

Last Updated
: 2026-06-25

Configure and manage NFS service shares for use with the Ceph Object Gateway.

### Before you begin

- A running IBM Storage Ceph cluster.
- A user created. For more information, see Create a user.

### About this task

You can manage the NFS service shares that use Ceph Object Gateway as the backend with the IBM Storage Ceph Dashboard. See Managing NFS service shares for more information.

> 📝 **Note:** Note:

- IBM supports only NFS version 4 shares using the Ceph Object Gateway.

You can only create user-level NFS service shares by using the command-line-interface (CLI).

> 📝 **Note:** Note:
This documentation uses
*NFS share*
instead of the earlier term
*NFS export*
. In the Ceph Dashboard, labels and controls may still refer to NFS export.

### Procedure

1. Log in to the
`cephadm`
shell.

Syntax

```plaintext-ibm
[root@host01 ~]# cephadm shell
```

Copy to clipboard
2. Create the user-level share in the root directory.

Syntax

```plaintext-ibm
ceph nfs export create rgw --cluster-id NFS_CLUSTER_NAME --pseudo-path PATH_FROM_ROOT --user-id USER_ID
```

Copy to clipboard

Example

```
[ceph:root@host01 /]# ceph nfs export create rgw --cluster-id cluster1 --pseudo-path root/testnfs1/ --user-id nfsuser
```
3. Mount the NFS.

Syntax

```plaintext-ibm
mount -t nfs IP_ADDRESS:PATH_FROM_ROOT -osync MOUNT_POINT
```

Copy to clipboard

Example

```
[ceph:root@host01 /]# mount -t nfs 10.0.209.0:/root/testnfs1 -osync /mnt/mount1
```

> 📝 **Note:** Important:
For large uploads >200 GB, mounting with
`-osync`
might affect the input/output operations. Use S3 with multi-part to upload such objects.

> 📝 **Note:** Note:
If you run
`setattr`
on the buckets, it silently prevents setting attributes on paths representing buckets.
