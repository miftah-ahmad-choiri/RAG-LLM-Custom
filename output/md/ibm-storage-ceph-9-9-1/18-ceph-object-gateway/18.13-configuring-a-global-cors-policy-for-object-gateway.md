## Configuring a global CORS policy for Object Gateway

Last Updated
: 2026-06-25

Configure a global Cross-Origin Resource Sharing (CORS) policy to control browser-based access across the Object Gateway.

Cross-Origin Resource Sharing (CORS) allows web applications running in a browser to access resources from a different domain. Bucket-level CORS does not apply to gateway-level operations such as listing or creating buckets. A global CORS policy enables consistent cross-origin behavior across all operations.

### Procedure

1. Define the required CORS configuration options.
2. Apply the configuration settings:

```plaintext-ibm
ceph config set client rgw_cors_allowed_origins "*"
ceph config set client rgw_cors_allowed_methods "GET, PUT, POST"
ceph config set client rgw_cors_allowed_headers "*"
ceph config set client rgw_cors_expose_headers "ETag"
ceph config set client rgw_cors_max_age 3600
```

Copy to clipboard
3. Verify the configuration using a browser or an OPTIONS request.

### Result

The global CORS policy is applied to gateway-level operations and to requests that do not have bucket-specific rules.

### CORS configuration options

**Allowed origins** — Domains that can access the gateway.

```plaintext-ibm
rgw_cors_allowed_origins = https://example.com
```

Copy to clipboard

**Allowed methods** — Permitted HTTP methods.

```plaintext-ibm
rgw_cors_allowed_methods = GET, PUT, POST, DELETE
```

Copy to clipboard

**Allowed headers** — Allowed request headers.

```plaintext-ibm
rgw_cors_allowed_headers = *
```

Copy to clipboard

**Exposed headers** — Response headers visible to clients.

```plaintext-ibm
rgw_cors_expose_headers = ETag
```

Copy to clipboard

**Maximum age** — Cache duration for preflight responses.

```plaintext-ibm
rgw_cors_max_age = 3600
```
