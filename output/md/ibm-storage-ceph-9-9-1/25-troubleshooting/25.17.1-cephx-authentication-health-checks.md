## CephX authentication health checks

Last Updated
: 2026-09-09

Identify, understand, and resolve CephX authentication health checks related to insecure cipher types.

### Problem

The ceph health detail health check command can report one or more of the following CephX authentication health warnings and errors:

- AUTH_INSECURE_CLIENT_KEY_TYPE
- AUTH_INSECURE_ROTATING_SERVICE_KEY_TYPE
- AUTH_INSECURE_KEYS_ALLOWED
- AUTH_INSECURE_KEYS_CREATABLE

### Explanation

During a Ceph upgrade, a new cipher type such as `aes256k` is introduced to replace older cipher types.

Service daemon keys are rotated automatically as part of the upgrade process. However, client CephX keys are not rotated automatically and might continue to use older cipher types.

The cluster temporarily allows both old and new cipher types so that upgrade operations can complete without disrupting authentication.

Some services require additional actions after key rotation. For example, NFS deployments can contain NFS cluster keys, NFS daemon Ceph Object Gateway keys, and NFS share keys.

NFS cluster keys and NFS daemon Ceph Object Gateway keys are rotated as part of CephX remediation. NFS share keys do not need to be rotated to address the security issue and are typically rotated only if it is necessary to clear reported warnings.

CephX authentication health warnings and errors include the following:

> 📝 **Note:** Note:
For more information about general Ceph cluster health messages, see
Health messages of a Ceph cluster
.

AUTH_INSECURE_CLIENT_KEY_TYPE
The cluster reports that one or more CephX keys use an insecure cipher type, such as
`aes`
.
For example,

```
[ceph: root@host01 /]# ceph health detail

[WRN] AUTH_INSECURE_CLIENT_KEY_TYPE:
entity client.admin using insecure key type: aes
entity client.storage-user using insecure key type: aes
```

AUTH_INSECURE_ROTATING_SERVICE_KEY_TYPE
The cluster reports that rotating service keys use an insecure cipher type, such as
`aes`
.
For example,

```
[ceph: root@host01 /]# ceph health detail

[ERR] AUTH_INSECURE_ROTATING_SERVICE_KEY_TYPE:
rotating service keys for mon using insecure key type: aes
rotating service keys for osd using insecure key type: aes
```

### Additional CephX authentication warnings

During the CephX key rotation process, the cluster can report additional authentication-related warnings. These warnings indicate the current upgrade state and help identify any remaining remediation actions.

For example:

```
[WRN] AUTH_INSECURE_KEYS_ALLOWED:
Monitors are configured to allow auth using insecure key types
  insecure cipher aes allowed for auth

[WRN] AUTH_INSECURE_KEYS_CREATABLE:
Monitors are configured to allow creation of insecure key types
```

AUTH_INSECURE_KEYS_ALLOWED
The monitors are configured to allow authentication using older cipher types such as
`aes`
.

This warning is expected while client key rotation is in progress and before the old cipher is disabled.

After all required keys are rotated, disable the old cipher by running:

```plaintext-ibm
ceph mon set auth_allowed_ciphers aes256k
```

AUTH_INSECURE_KEYS_CREATABLE
The monitors are still configured to allow creation of authentication entities that use older cipher types.

This warning indicates that new entities can still be created with the legacy cipher.

The warning clears after monitors are configured to stop creating authentication entities that use the older cipher types.

AUTH_INSECURE_CLIENT_KEY_TYPE
One or more client authentication entities still use an older cipher type such as
`aes`
.

Rotate every client entity reported by the warning.

For more about rotating CephX keys, see Rotating CephX keys.

AUTH_INSECURE_ROTATING_SERVICE_KEY_TYPE
Service daemon key rotation is still in progress and temporary service keys continue to use the older cipher type.

This health error is typically expected during upgrade and key rotation.

The health error clears automatically after service key rotation completes and the previous keys expire.

### Resolution

- The AUTH_INSECURE_ROTATING_SERVICE_KEY_TYPE health error typically resolves automatically after service key rotation completes and the previous keys expire.
- To resolve AUTH_INSECURE_CLIENT_KEY_TYPE, rotate each affected client key. For more information, see Rotating CephX keys.
- If NFS share entities continue to appear in AUTH_INSECURE_CLIENT_KEY_TYPE warnings after completing key rotation, the NFS share keys might still use the old cipher type.

> 📝 **Note:** Note:
Rotating NFS share keys is optional and is required only if you want to clear remaining NFS share warnings.
- If the cluster reports AUTH_INSECURE_KEYS_ALLOWED or AUTH_INSECURE_KEYS_CREATABLE, verify that all affected client entities have been rotated before disabling the older cipher type.

> 📝 **Note:** Important:
Do not disable the
`aes`
cipher while any entities reported by
AUTH_INSECURE_CLIENT_KEY_TYPE
still use the older key type.

### NFS authentication warnings

NFS deployments can contain NFS cluster keys, NFS daemon Ceph Object Gateway keys, and NFS share keys.

Use the following command to rotate the NFS keys:

```plaintext-ibm
ceph nfs cluster rotate-key CLUSTER_NAME --key-type aes256k
```

Copy to clipboard

By default, the command rotates all keys that are associated with the specified NFS cluster, including cluster keys, daemon keys, and share keys.

The command also updates the required NFS configuration and redeploys the NFS service when necessary.

After the command completes, verify that the related AUTH_INSECURE_CLIENT_KEY_TYPE warning is no longer reported.
