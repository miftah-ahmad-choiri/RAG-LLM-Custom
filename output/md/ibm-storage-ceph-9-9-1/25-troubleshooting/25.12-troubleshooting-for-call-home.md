## Troubleshooting for Call Home

Last Updated
: 2026-06-25

Use this information to learn how to fix the most common errors and retrieve information that is not properly giving output that is related to Call Home.

### About this task

You can check the Call Home status at any time by using the `ceph mgr module ls` command.

For general troubleshooting of Call Home and Call Home errors, start by identifying any possible causes of errors for Call Home, by using one of the following procedures:

- Using the Ceph Manager log
- Reproducing the problem

For troubleshooting related to specific issues with communication errors, command content errors, or firewall and proxy, see:

- Resolving Call Home communication errors
- Troubleshooting command content errors
- Call Home firewall and proxy troubleshooting

### Using the Ceph Manager log

#### Before you begin

- A running IBM Storage Ceph cluster.
- Root-level access to the node.

#### Procedure

Use the Ceph Manager log, filtered for Call Home.

1. Log in to the
`cephadm`
shell.
For example,

```
[root@host01 ~]# cephadm shell
```
2. Locate the active manager, by using the
ceph -s
command.
For example,

```
[ceph: root@host01 /]# ceph -s
```

Only proceed to step
4
after knowing which host is running the active manager.
3. Exit the
`cephadm`
shell, by using the
exit
command.
For example,

```
[ceph: root@host01 /]# exit
[root@host01 ~]#
```
4. Log into the host running the active manager, found in step
2
and retrieve the name of the manager service in the node.

```plaintext-ibm
systemctl list-units | grep @mgr
```

Copy to clipboard

```
[ceph: root@host01 /]# systemctl list-units | grep @mgr
```
5. Check the log for Call Home errors, using the
journalctl
command.
Use the
MANAGER_SERVICE
retrieved in step
4
.

```plaintext-ibm
journalctl -f -u CLUSTER_ID@MANAGER_SERVICE | greg call_home_agent
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# journalctl -f -u ceph-c549a36a-b377-11ed-b55e-525400bfa136@mgr.ceph-node-00.doxgmi.service | grep call_home_agent
```

### Reproducing the problem

#### About this task

Most actions that are automatically run by the Call Home manager module can be reproduced using the command-line interface (CLI).

Use the CLI to run Call Home commands to see what happened within the command-line and through the log files.

#### Procedure

1. Open two terminals on a host with an active manager.
On both terminals, use the
cephadm shell
command on the node to open the
`cephadm`
shell.
For example,

```
[root@host01 ~]# cephadm shell
```
2. From the
`cephadm`
shell terminal of the first terminal, view active manager logs.
For more information, see
Using the Ceph Manager log
.
3. From the
`cephadm`
shell of the second terminal, run the CLI command you want to debug. Simultaneously watch the output in the log terminal.
Check both the log and the CLI output after running each command.

> 📝 **Note:** Note:
Be sure to open the log on the first terminal before running the CLI command on the second terminal to be able to see all output.

1. Run the CLI command you want to debug.
Example of running a command to send a Call Home inventory report for debugging,

```
[ceph: root@host01 /]# ceph callhome send inventory
```
2. Watch the log output terminal.
Example of log output terminal,

```
# journalctl -f -u ceph-aa091236-b135-11ee-8bb7-525400ee9df3@mgr.chatest-node-00.anxrcb.service
...
Jan 12 12:34:42 chatest-node-00.cephlab.com ceph-mgr[68305]: [call_home_agent INFO root] Sending <inventory> report to <https://esupport.ibm.com/connect/api/v1>
...
Jan 12 12:34:45 chatest-node-00.cephlab.com ceph-mgr[68305]: [call_home_agent INFO root] Successfully sent <inventory> report(1705062882183) to <https://esupport.ibm.com/connect/api/v1>
....
```
