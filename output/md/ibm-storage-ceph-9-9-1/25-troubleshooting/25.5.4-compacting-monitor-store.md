## Compacting Monitor store

Last Updated
: 2026-06-25

Compact a Monitor store when it has grown too large.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph cluster.
- Root-level access to the Ceph Monitor node.

### About this task

The Monitor store can be compacted in any of the following ways:

- Dynamically by using the ceph tell command.
- Upon the start of the `ceph-mon` daemon.
- By using the `ceph-monstore-tool` when the `ceph-mon` daemon is
not running. Use this method when the other methods fail to compact the Monitor store or when the
Monitor is out of quorum and its log contains the Caught signal (Bus error) error
message.

> 📝 **Note:** Important:
Monitor store size changes when the cluster is not in the
active+clean
state or during the rebalancing process. For this reason,
compact the Monitor store when rebalancing is completed. Also, ensure that the placement groups are
in the
active+clean
state.

For more information, see Ceph Monitor store is getting too big and
Ceph Monitor is out of quorum.

### Procedure

1. While the
`ceph-mon`
daemon is running, compact the
Monitor
store.
```plaintext-ibm
ceph tell mon.HOST_NAME compact
```

Copy to clipboard

Replace
HOST_NAME
with the short hostname of the host where the
`ceph-mon`
is running.

> 📝 **Note:** Note:
If the hostname is not known, use the
hostname -s
command.
For
example,

```
[ceph: root@host01 /]# ceph tell mon.host01 compact
```
2. Add the
mon_compact_on_start = true
parameter to the Ceph
configuration under the
`[mon]`
section.For
example,

```
[mon]
mon_compact_on_start = true
```
3. Restart the
`ceph-mon`
daemon.
```plaintext-ibm
systemctl restart ceph-mon@HOST_NAME
```

Copy to clipboard

Replace
HOST_NAME
with the short name of the host where the daemon is running.

> 📝 **Note:** Note:
If
the hostname is not known, use the
hostname -s
command.
For
example,

```
[root@mon ~]# systemctl restart ceph-mon@host01
```
4. Ensure that Monitors have formed a quorum.
```plaintext-ibm
ceph mon stat
```

Copy to clipboard
For example,

```
[ceph: root@host01 /]# ceph mon stat
```
5. **Optional:**If needed, repeat steps
1
through
4
on any other Monitors.
> 📝 **Note:** Note:
Before starting, be sure that the
`ceph-test`
package is installed.
6. Verify that the
`ceph-mon`
daemon with the large store is not
running.If needed, stop the
daemon.

```plaintext-ibm
systemctl status ceph-mon@HOST_NAME
```

Copy to clipboard

```plaintext-ibm
systemctl stop ceph-mon@HOST_NAME
```

Copy to clipboard

Replace
HOST_NAME
with the short name of the host where the daemon is running.

> 📝 **Note:** Note:
If
the hostname is not known, use the
hostname -s
command.
For
example,

```
[root@mon ~]# systemctl status ceph-mon@host01
[root@mon ~]# systemctl stop ceph-mon@host01
```
7. Compact the Monitor
store.
```plaintext-ibm
ceph-monstore-tool /var/lib/ceph/mon/mon.HOST_NAME compact
```

Copy to clipboard

Replace
HOST_NAME
with a short hostname of the Monitor host.For
example,

```
[ceph: root@host01 /]# ceph-monstore-tool /var/lib/ceph/mon/mon.host01 compact
```
8. Start
`ceph-mon`
again.
```plaintext-ibm
systemctl start ceph-mon@HOST_NAME
```

Copy to clipboard
For
example,

```
[root@mon ~]# systemctl start ceph-mon@host01
```
