## NVMe-oF in a stretch cluster

Last Updated
: 2026-06-25

When NVMe-oF gateways are deployed across multiple sites, stretch cluster support introduces location-aware failover, failback control, and namespace placement to optimize performance and resilience.

Deploying NVMe-oF gateways across multiple sites can lead to inefficient failover selection, uncontrolled failback behavior, and suboptimal namespace placement. Stretch cluster support enhances IBM Storage Ceph capabilities by introducing location-aware behavior for gateways and namespaces, enabling more predictable failover and improved I/O locality.

Location-aware failover selection
NVMe-oF gateways can be assigned a
location
attribute that represents their physical site or region.

Failover and failback algorithms use this attribute to prioritize gateways in the same location, ensuring that NVMe-oF traffic remains local whenever possible and avoiding cross-site failover to remote gateways when a local gateway is available.

Controlled failback behavior
Stretch cluster support introduces a
disaster state
for each location, allowing administrators to control failover and failback behavior.

When a location is marked as in a disaster state, it is excluded from failover decisions and automatic failback is prevented until the state is cleared, avoiding premature failback to a location that is not yet ready for service.

Location-aware namespace placement
Namespaces can be assigned a
location
attribute to define their preferred site.

The enhanced load-balancing algorithm uses this attribute to place namespaces on gateways in the same location whenever possible, improving I/O locality and avoiding unnecessary cross-site traffic for active workloads.

Automatic namespace relocation and validation
Namespace location assignments are validated against configured gateway locations to ensure consistency.

Invalid location assignments are rejected, and if a namespace becomes orphaned, it is automatically relocated to a valid gateway, preventing loss of access due to location inconsistencies.
