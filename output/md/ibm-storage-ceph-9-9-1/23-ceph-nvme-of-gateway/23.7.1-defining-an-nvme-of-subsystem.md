## Defining an NVMe-oF subsystem

Last Updated
: 2026-06-25

Define an NVMe-oF subsystem. Defining the NVMe subsystem includes creating an NVMe subsystem, configuring the IP port for communication, and enabling hosts to use the subsystem.

### Before you begin

> 📝 **Note:** Important:
To use the
ceph nvmeof
commands, the latest Ceph Dashboard must be installed. If the Ceph Dashboard is not available, go to
Using the nvmeof-cli utility for configuring and managing NVMe-oF gateways
.

Before you begin, make sure that you have the following prerequisites in place:

- The latest Ceph Dashboard installed. For more information, see Bootstrap storage cluster along with Dashboard .
- To use in-band authentication, an RSA encryption key must be created and placed in the specification file.

For more information, see Deploying by using a service specification file.
- Generate a DH-HMAC-CHAP key with the Linux command line.

> 📝 **Note:** Important:
In-band authentication is supported on an initiator with Red Hat Enterprise Linux 9.5 or later. ESX is not supported.

This is required for using both bidirectional and unidirectional in-band authentication.

```plaintext-ibm
nvme gen-dhchap-key
```

Copy to clipboard

For example,

```
$ nvme gen-dhchap-key
DHHC-1:00:abEcb12F100FNlZkIOkv37idpu/notvalid!!si1VQ09KhKv2g:
```

> 📝 **Note:** Note:
This prerequisite is only required if defining in-band authentication during the subsystem creation or while adding a host to a subsystem. The in-band authentication can also be defined later.

- For more information about in-band authentication, see NVMe-oF gateway in-band authentication.
- For more information about adding in-band authentication to a subsystem after creation, see Changing a subsystem authentication key.

  - For more information about in-band authentication, see NVMe-oF gateway in-band authentication.
  - For more information about adding in-band authentication to a subsystem after creation, see Changing a subsystem authentication key.

### About this task

Use this procedure to configure the Ceph NVMe-oF gateway with the command-line interface. To configure the gateway with the dashboard, see Managing NVMe-oF subsystems.

When creating a subsystem, you can optionally configure NVMe‑oF listeners automatically. Automatic listeners are created on all gateways whose IP addresses fall within the specified network subnet. To enable automatic listener creation, use the
--network-mask
parameter with the
subsystem add
command.

> 📝 **Note:** Note:
Configure NVMe‑oF listeners automatically by using the
--network-mask
parameter. This approach simplifies listener management and ensures that listeners are automatically added or removed during scale‑up and scale‑down operations.

### Procedure

1. Create an NVMe subsystem.
The
NQN
is a required parameter when creating a subsystem.
NQN
is a user-defined string. By default, the gateway appends a group name to the NQN and the subsystem includes the group name. The group name is automatically appended to prevent one or more subsystems from being created with the same NQN in different groups.

> 📝 **Note:** Note:
A group name is not appended if the
--no-group-append
parameter is used when adding the subsystem.

In this example, NQN is defined as nqn.2016-06.io.spdk:cnode1 and `group1` is appended after the subsystem add command.

> 📝 **Note:** Note:

- The actual created subsystem name is returned with the subsystem add command. Use the returned subsystem name for all subsequent subsystem operations.
- Up to 128 subsystems are supported.

```plaintext-ibm
ceph nvmeof subsystem add --nqn NQN [--enable-ha] [--network-mask IP_SUBNET] [--max_namespaces MAX_NAMESPACES ] [--no-group-append] [--serial_number SERIAL_NUMBER ] [--dhchap-key KEY_VALUE]
```

Copy to clipboard

> 📝 **Note:** Important:

- NQN and gateway name values must not contain an underscore character.
- Do not use the same NQN for two different gateway groups. Namespaces might not be visible if an initiator is connected to two different gateway groups with the same NQN.

For extra input, the following parameters can be added to the command:
--enable-ha
Use to enable High Availability (HA), if HA was previously not enabled. For more information, see
Ceph NVMe-oF gateway
.
--network-mask
Use to enable automatic listener creation.
When you specify a network mask:

- Listeners are created automatically on all gateways with IP addresses within the subnet.
- Listeners are automatically added when gateways are scaled up.
- Listeners are automatically removed when gateways are scaled down.
- Manual creation of listeners is not required.

--max-namespaces
The maximum namespaces per subsystem default is 256.

Input type: Number

--no-group-append
Use this flag to not append a group name to the subsystem NQN.

> 📝 **Note:** Important:
Use this flag with extreme caution. When using this flag, if an initiator is connected to two different gateway groups with the same subsystem NQNs, not all NVMe-oF devices are listed with the
nvme list
command.

> 📝 **Note:** Note:
A group name is not appended to the subsystem NQN only if this option is not used.

Input type: Boolean

--serial-number
If the serial number is not specified, the number is randomly generated.

Input type: String

--dhchap-key
Use this flag to add a generated DH-HMAC-CHAP key for use with bidirectional in-band authentication.

> 📝 **Note:** Note:
Use this flag to define in-band authentication during the subsystem creation. The in-band authentication can also be defined later. For more information, see
Changing a subsystem authentication key
.

Input type: String

For example,

```
[root@host01 ~]# ceph nvmeof subsystem add --nqn nqn.2016-06.io.spdk:cnode1 --network-mask 10.243.64.0/24 --dhchap-key DHHC-1:00:abEcb12F100FNlZkIOkv37idpu/notvalid!!si1VQ09KhKv2g:
Success
```

  - The actual created subsystem name is returned with the subsystem add command. Use the returned subsystem name for all subsequent subsystem operations.
  - Up to 128 subsystems are supported.
2. Add a listener to define the IP port on the gateway that is to process NVMe/TCP commands and I/O operations.

> 📝 **Note:** Important:

- Listeners must be added to all subsystems for all gateways in the gateway group for High Availability and auto load balancing of namespaces.
- NQN and gateway name values must not contain an underscore character.
- If a subsystem is already enabled with auto-listeners, do not manually add a listener.

```plaintext-ibm
ceph nvmeof listener add --nqn NQN --host-name HOST_NAME [--traddr LISTENER_ADDRESS] [--server-address SERVER_ADDRESS] [--trsvcid:int PORT] [--adrfam:int IPV_TYPE] [--gw_group GW_GROUP]
```

Copy to clipboard

For example,

```
[root@host01 ~]# ceph nvmeof listener add --nqn nqn.2016-06.io.spdk:cnode1.group1 --host-name host02 --server-address 10.172.19.01 --trsvcid:int 5500 --adrfam:int 0 --gw_group GW_GROUP
Success
```

For extra input, the following flags can optionally be added to the command:

- TRADDR
- TRSVCID

> 📝 **Note:** Note:
To define the IP port on the gateway, be sure to include the
TRSVCID:INT
information.
- ADRFAM:INT
- GW_GROUP

  - Listeners must be added to all subsystems for all gateways in the gateway group for High Availability and auto load balancing of namespaces.
  - NQN and gateway name values must not contain an underscore character.
  - If a subsystem is already enabled with auto-listeners, do not manually add a listener.
3. Get the host NVMe Qualified Name (NQN) for each host.
For Red Hat Enterprise Linux initiators

```plaintext-ibm
cat /etc/nvme/hostnqn
```

Copy to clipboard

For example,

```
# cat /etc/nvme/hostnqn
nqn.2014-08.org.nvmexpress:uuid:950ddadf-f995-47b7-9416-b9bb233f66e3
```

In this example
`950ddadf-f995-47b7-9416-b9bb233f66e3`
is the UUID.
For VMware ESXi initiators

```plaintext-ibm
esxcli nvme info get
```

Copy to clipboard

For example,

```
esxcli nvme info get
Host NQN: nqn.2014-08.com.ibm.ceph:nvme:host01
```
4. Allow the NVMe initiator host to run NVMe/TCP commands to the newly created NVMe subsystem.

1. Add the host.

> 📝 **Note:** Important:
To add a secured DH-HMAC-CHAP host, use the
--dhchap-key
parameter to add the
DHCHAP_KEY
to the host.

`--host-nqn "*"` is not supported with DH-HMAC-CHAP host.

> 📝 **Note:** Note:
A specific host can be selected, as in the following example. To specify all hosts, use
`--host-nqn "*"`
.

To add multiple specific hosts, separate them by using a space. Do not use commas between host NQNs or quotes (") around the multiple host NQNs. Use the following example format:

--host-nqn
HOST01_NQN
HOST02_NQN

```plaintext-ibm
ceph nvmeof host add --nqn NQN [--host_nqn HOST_NQN] [--dhchap_key KEY_VALUE] [--psk PSK] [--gw_group GW_GROUP] [--server-address SERVER_ADDRESS]
```

Copy to clipboard

For example,

```
[root@host01 ~]# ceph nvmeof host add --nqn nqn.2016-06.io.spdk:cnode1.group1 --host_nqn nqn.2014-08.org.nvmexpress:uuid:950ddadf-f995-47b7-9416-b9bb233f66e3 nqn.2014-08.org.nvmexpress:uuid:123ddadf-f456-47b7-9416-b9bb233f67f4
Success
```
2. Verify the hosts defined on the subsystem.

```plaintext-ibm
ceph nvmeof host list --nqn NQN [--clear-alerts] [--gw_group GW_GROUP] [--server-address SERVER_ADDRESS]
```

Copy to clipboard

- Use the --clear-alerts parameter to clear host alert signals after retrieving the values.
- Use the optional --gw_group and --server-address to specify specific gateway group, gateway IP address, or both in the host list.

For example,


  - Use the optional --gw_group and --server-address to specify specific gateway group, gateway IP address, or both in the host list.
