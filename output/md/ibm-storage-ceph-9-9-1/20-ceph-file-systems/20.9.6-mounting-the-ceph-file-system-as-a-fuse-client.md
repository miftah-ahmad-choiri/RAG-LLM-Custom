## Mounting the Ceph File System as a FUSE client

Last Updated
: 2026-06-25

The Ceph File System (CephFS) can be mounted as a FUSE client, either manually or automatically on system start.

### Before you begin

Before mounting a Ceph File System as a FUSE client, be sure that you have:

- Root-level access to a Linux-based client node.
- Root-level access to a Ceph Monitor node.
- An existing Ceph File System.

### About this task

- For more information, see the `ceph-fuse(8)` manual page.
- For more information about creating a Ceph user, see Ceph user management.
- For more information about creating Ceph File Systems, see Creating Ceph File Systems.

### Procedure

Configure the client node to use the Ceph storage cluster.

1. Enable the
IBM Storage Ceph
9.9.0
Tools repository.

```plaintext-ibm
curl https://public.dhe.ibm.com/ibmdl/export/pub/storage/ceph/ibm-storage-ceph-9-rhel-9.repo | sudo tee /etc/yum.repos.d/ibm-storage-ceph-9-rhel-9.repo
```

Copy to clipboard

Repeat on client nodes of the IBM Storage Ceph storage cluster.
2. Install the
`ceph-fuse`
package.

```plaintext-ibm
dnf install ceph-fuse
```

Copy to clipboard
3. Copy the Ceph client keyring from the Ceph Monitor node to the client node.

> 📝 **Note:** Note:
The client user must already be created.

```plaintext-ibm
scp /etc/ceph/ceph.client.admin.keyring root@CLIENT_NODE_NAME:/etc/ceph/ceph.client.admin.keyring
```

Copy to clipboard

Replace CLIENT_NODE_NAME with the Ceph client host name or IP address.

For example,

```
[ceph: root@host01 ~]# scp /etc/ceph/ceph.client.admin.keyring root@client01:/etc/ceph/ceph.client.admin.keyring
```
4. Copy the Ceph configuration file from a Ceph Monitor node to the client node.

```plaintext-ibm
scp /etc/ceph/ceph.conf root@CLIENT_NODE_NAME:/etc/ceph/ceph.conf
```

Copy to clipboard

Replace CLIENT_NODE_NAME with the Ceph client host name or IP address.

For example,

```
[ceph: root@host01 ~]# scp /etc/ceph/ceph.conf root@client01:/etc/ceph/ceph.conf
```
5. From the client node, set the appropriate permissions for the configuration file.

```plaintext-ibm
chmod 644 /etc/ceph/ceph.conf
```

Copy to clipboard
6. Choose either
`automatically`
or
`manually`
.

- For automatic mounting, continue to Mounting automatically.
- For manual mounting, continue to Mounting manually.

  - For automatic mounting, continue to Mounting automatically.
  - For manual mounting, continue to Mounting manually.

### Mounting automatically

#### Procedure

1. On the client node, create a directory for the mount point.

> 📝 **Note:** Note:
If you used the
`path`
option with MDS capabilities, then the mount point must be within what is specified by the
`path`
.

```plaintext-ibm
mkdir PATH_TO_MOUNT_POINT
```

Copy to clipboard

For example,

```
[root@client01 ~]# mkdir /mnt/mycephfs
```
2. Edit the
/etc/fstab
file.

```plaintext-ibm
DEVICE                 PATH           TYPE          OPTIONS                  DUMP  FSCK
HOST_NAME:PORT,     MOUNT_POINT fuse.ceph     ceph.id=CLIENT_ID,        0     0
HOST_NAME:PORT,                                  ceph.client_mountpoint=/VOL/SUB_VOL_GROUP/SUB_VOL/UID_SUB_VOL,
HOST_NAME:PORT:/                                 ceph.client_fs=FILE_SYSTEM_NAME,ceph.name=USERNAME,ceph.keyring=/etc/ceph/KEYRING_FILE,
                                                     [ADDITIONAL_OPTIONS]
```

Copy to clipboard

In the
/etc/fstab
file,

- The first column (`#DEVICE`) sets the Ceph Monitor host names and the port number.
- The second column (`PATH`) set the mount point.
- The third column (`TYPE`) sets the file system type. In this case, `fuse.ceph`, for CephFS.
- The fourth column (`OPTIONS`) sets the various options. These include the user name and the keyring that use the `ceph.name` and `ceph.keyring` options. You can also set specific volumes, subvolume groups, and subvolumes that use the `ceph.client_mountpoint` option.

To specify which Ceph File System to access, use the `ceph.client_fs` option. Set the `_netdev` option to ensure that the file system is mounted after the networking subsystem starts to prevent hanging and networking issues. If you do not need access time information, then setting the `noatime` option can increase performance. If you want to automatically reconnect after an eviction, then set the `client_reconnect_stale=true` option.
- Set the fifth and sixth columns (`DUMP` and `FSCK`) to 0.

For example,

```
# DEVICE         PATH              TYPE         OPTIONS         DUMP  FSCK
 mon1:6789,      /mnt/mycephfs       fuse.ceph    ceph.id=1,         0     0
 mon2:6789,                                     ceph.client_mountpoint=/my_vol/my_sub_vol_group/my_sub_vol/0,
 mon3:6789:/                                    ceph.client_fs=cephfs01,ceph.name=client.1,ceph.keyring=/etc/ceph/client1.keyring,
                                               _netdev,defaults
```

The Ceph File System is mounted on the next system start.

  - The first column (`#DEVICE`) sets the Ceph Monitor host names and the port number.
  - The second column (`PATH`) set the mount point.
  - The third column (`TYPE`) sets the file system type. In this case, `fuse.ceph`, for CephFS.
  - The fourth column (`OPTIONS`) sets the various options. These include the user name and the keyring that use the `ceph.name` and `ceph.keyring` options. You can also set specific volumes, subvolume groups, and subvolumes that use the `ceph.client_mountpoint` option.

  To specify which Ceph File System to access, use the `ceph.client_fs` option. Set the `_netdev` option to ensure that the file system is mounted after the networking subsystem starts to prevent hanging and networking issues. If you do not need access time information, then setting the `noatime` option can increase performance. If you want to automatically reconnect after an eviction, then set the `client_reconnect_stale=true` option.
  - Set the fifth and sixth columns (`DUMP` and `FSCK`) to 0.

### Mounting manually

#### Procedure

1. On the client node, create a directory for the mount point.

> 📝 **Note:** Note:
If you used the
`path`
option with MDS capabilities, then the mount point must be within what is specified by the
`path`
.

```plaintext-ibm
mkdir PATH_TO_MOUNT_POINT
```

Copy to clipboard

For example,

```
[root@client01 ~]# mkdir /mnt/mycephfs
```
2. Use the
`ceph-fuse`
utility to mount the Ceph File System.

```plaintext-ibm
ceph-fuse -n client.CLIENT_ID --client_fs FILE_SYSTEM_NAME MOUNT_POINT
```

Copy to clipboard

For example,

```
[root@client01 ~]# ceph-fuse -n client.1 --client_fs cephfs01 /mnt/mycephfs
```

> 📝 **Note:** Note:

- If you do not use the default name and location of the user keyring (`/etc/ceph/ceph.client.CLIENT_ID.keyring`) then use the --keyring option to specify the path to the user keyring. For example,

```
[root@client01 ~]# ceph-fuse -n client.1 --keyring=/etc/ceph/client.1.keyring /mnt/mycephfs
```
- Use the -r option to instruct the client to treat that path as its root.

```plaintext-ibm
ceph-fuse -n client.CLIENT_ID MOUNT_POINT -r PATH
```

Copy to clipboard

                  For example,

```
[root@client01 ~]# ceph-fuse -n client.1 /mnt/cephfs -r /home/cephfs
```
- If you want to automatically reconnect an evicted Ceph client, then add the --client_reconnect_stale=true option.
                  For example,

```
[root@client01 ~]# ceph-fuse -n client.1 /mnt/cephfs --client_reconnect_stale=true
```

```plaintext-ibm
stat -f MOUNT_POINT
```

```
[root@client01 ~]# stat -f /mnt/cephfs
```
