## Snapshot visibility for CephFS and NFS clients

Last Updated
: 2026-06-25

CephFS controls snapshot (.snap) directory visibility for subvolumes and NFS shares, and how clients enforce visibility rules.

CephFS supports snapshots at the subvolume level. Snapshots are stored inside the special directory named .snap, which is visible to clients by default. Administrators can control whether this directory is visible to clients by configuring:

- Subvolume‑level snapshot visibility flag
- Client‑side adherence to visibility rules
- Share‑level snapshot visibility toggle for NFS

These controls allow administrators to hide or expose snapshots to specific NFS clients or subvolumes.

### How snapshot visibility works at subvolume, client, and share levels

Snapshot visibility in CephFS is determined by the interaction of three mechanisms: the subvolume‑level visibility flag, client‑side enforcement, and the NFS share‑level toggle.

Subvolume‑level visibility
Each CephFS subvolume maintains a visibility attribute.

```
ceph.subvolume.snaps.visible = {0|1}
```

- 1 (true) — the .snap directory is visible.
- 0 (false) — the .snap directory is hidden.

> 📝 **Note:** Note:
When the flag is set to 0, clients that enforce visibility rules cannot view or access the .snap directory. These clients are also blocked from performing snapshot operations such as creation, deletion, cloning, or scheduling.

Client‑side visibility enforcement
Clients enforce the subvolume visibility flag when the below configuration is enabled.

```
client_respect_subvolume_snapshot_visibility = true
```

> 📝 **Note:** Note:
This setting must be applied to the specific CephX identity used by the CephFS or NFS client.

Share‑level snapshot visibility (NFS)
For NFS clients, Ceph offers an additional share‑level toggle that controls .snap directory visibility on a per‑share basis.

> 📝 **Note:** Note:
Administrators can configure this toggle using:

- Ceph Dashboard (UI)
- Ceph NFS API

This share‑level setting works in combination with:

- the subvolume visibility flag,
- the client‑side enforcement configuration.

> 📝 **Note:** Note:
All three mechanisms must align for NFS clients to observe the intended snapshot visibility behavior.
