## Removing a CephFS client from the blocklist

Last Updated
: 2026-06-25

In some situations, it can be useful to allow a previously blocklisted Ceph File System
(CephFS) client to reconnect to the storage cluster.

### Before you begin

Before removing a Ceph File System client, be sure that you have root-level access to the
Ceph Monitor node.

### About this task

> 📝 **Note:** Important:
Removing a CephFS client from the blocklist puts data integrity at risk, and
does not guarantee a fully healthy, and functional CephFS client as a result. The best way to get a
fully healthy CephFS client back after an eviction, is to unmount the CephFS client and do a fresh
mount. If other CephFS clients are accessing files that the blocklisted CephFS client was buffering
I/O to, it can result in data corruption.

### Procedure

1. Review the blocklist.For
example:

```
[ceph: root@host01 /]# ceph osd blocklist ls

listed 1 entries
127.0.0.1:0/3710147553 2022-05-09 11:32:24.716146
```
2. Remove the CephFS client from the blocklist.
```plaintext-ibm
ceph osd blocklist rm CLIENT_NAME_OR_IP_ADDR
```

Copy to clipboard
For
example:

```
[ceph: root@host01 /]# ceph osd blocklist rm 127.0.0.1:0/3710147553

un-blocklisting 127.0.0.1:0/3710147553
```
3. **Optional:**Set kernel-based CephFS clients automatically to reconnect when
removing them from the blocklist.On the kernel-based CephFS client, set the following
option to
`clean`
either when doing a manual mount, or automatically mounting with an
entry in the
/etc/fstab
file.

```plaintext-ibm
recover_session=clean
```

Copy to clipboard
4. **Optional:**Set FUSE-based CephFS clients automatically to reconnect when
removing them from the blocklist.On the FUSE client, set the following option to
`true`
either when doing a manual mount, or automatically mounting with an entry in
the
/etc/fstab
file.

```plaintext-ibm
client_reconnect_stale=true
```
