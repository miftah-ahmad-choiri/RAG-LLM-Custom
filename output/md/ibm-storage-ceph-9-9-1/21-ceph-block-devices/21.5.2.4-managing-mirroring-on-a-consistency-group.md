## Managing mirroring on a consistency group

Last Updated
: 2026-06-25

Learn to enable and disable mirroring on Ceph Block Device consistency group by using the
command-line interface. You can also get the mirroring status for the group. Also, learn to promote,
demote, and resynchronize the group. The commands in the following section supports the optional
namespace parameter and you can use this parameter in the command as POOL_NAME/NAMESPACE/GROUP_NAME.

### Before you begin

> 📝 **Note:** Note:
You can mirror a maximum of 100 images in total per cluster and a maximum of 50 images per
group.

- Make sure that you have root-level access to the node.
- Pool mirroring is enabled in the `image` mode. For more information, see step 5
in Configuring two-way Ceph device block mirroring.

### Enabling mirroring on a group

#### About this task

> 📝 **Note:** Note:

- Group mirroring works with `image` mode only.
- Consistency group mirroring only supports `snapshot` mirroring mode and
`journal` mode is not supported.

Enable mirroring for a group within the pool, by using the
mirror group
enable
command.

#### Procedure

Run the following command to enable mirroring on a group.
Syntax

```plaintext-ibm
rbd mirror group enable POOL_NAME/GROUP_NAME
```

Copy to clipboard

The
following example enables mirroring for the
`test_group`
group in the
`test_pool`
pool.

```
[root@rbd-client ~]# rbd mirror group enable test_pool/test_group
```

> 📝 **Note:** Note:

- After you enable mirroring for a group, you cannot add or remove new images from  that group. If
you want to add images, disable group mirroring and add the images. You can then re-enable
mirroring.
- Images in the group cannot be enabled for mirroring.

### Promoting a group

#### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph cluster with snapshot-based group
mirroring is configured.
- Root-level access to the node.

#### About this task

Promote a group by using the command in the procedure.

#### Procedure

- Promote a group to primary, by using the
mirror group promote
command.Syntax

```plaintext-ibm
rbd mirror group promote POOL_NAME/GROUP_NAME
```

Copy to clipboard
The
following example promotes the group
`test_group`
in the
`test_pool`
pool to
primary.

```
[root@rbd-client ~]# rbd mirror group promote test_pool/test_group
```
- Use forced promotion when the demotion cannot be propagated to the peer Ceph storage
cluster because of cluster failure or communication outage.
> 📝 **Note:** Important:

Before executing the mirror group promote command with **--force** flag,
ensure that the secondary mirror daemon is stopped. This step is a temporary workaround for known
issues and may not be necessary once those issues are resolved.

1. Run the command to stop and kill the secondary mirror
daemon.
```plaintext-ibm
ceph orch stop rbd-mirror

kill -SIGKILL PID_OF_SECONDARY_RBD_MIRROR
```

Copy to clipboard
2. Execute the mirror group promote command with the **--force** flag and
restart the mirror daemon after the mirror group promote command completes
execution.
```plaintext-ibm
rbd mirror group promote --force POOL_NAME/GROUP_NAME

ceph orch start rbd-mirror
```

Copy to clipboard
Example

```
[root@rbd-client ~]# rbd mirror group promote --force test_pool/test_group
```

### Resynchronizing a group

#### About this task

You can resynchronize a group if an inconsistency occurs between the two peer clusters.
When a group enters an inconsistent state, the `rbd-mirror` daemon skips mirroring
for that group until the issue is resolved.

Resynchronize a group by using the command in the
procedure.

#### Procedure

Resynchronize to the primary group, by using the
mirror group resync
command.
Syntax

```plaintext-ibm
rbd mirror group resync POOL_NAME/GROUP_NAME
```

Copy to clipboard

The
following example requests resynchronization of
`test_group`
in the
`test_pool`
pool.

```
[root@rbd-client ~]# rbd mirror group resync test_pool/test_group
```
