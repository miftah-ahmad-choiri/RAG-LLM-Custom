## Preparing for fail back

Last Updated
: 2026-06-25

If two storage clusters were originally configured only for one-way mirroring, in order
to fail back, configure the primary storage cluster for mirroring in order to replicate the images
in the opposite direction.

During failback scenario, the existing peer that is inaccessible must be removed before adding a
new peer to an existing cluster.

### Prerequisites

- A running IBM Storage Ceph cluster.
- Root-level access to the client node.

### Procedure

1. Log into the `cephadm` shell:

Example

```plaintext-ibm
[root@rbd-client ~]# cephadm shell
```

Copy to clipboard
2. On the `site-a` storage cluster , run the following command:

Example

```plaintext-ibm
[ceph: root@rbd-client /]# ceph orch apply rbd-mirror --placement=host01
```

Copy to clipboard
3. Remove any inaccessible peers.
> 📝 **Note:** Important:
This step must be run on the peer site
which is up and running.

> 📝 **Note:** Note:
Multiple peers are supported only for one way
mirroring.

1. Get the pool UUID:Syntax

```plaintext-ibm
rbd mirror pool info POOL_NAME
```

Copy to clipboard
Example

```plaintext-ibm
[ceph: root@host01 /]# rbd mirror pool info pool_failback
```

Copy to clipboard
2. Remove the inaccessible peer:Syntax

```plaintext-ibm
rbd mirror pool peer remove POOL_NAME PEER_UUID
```

Copy to clipboard
Example

```plaintext-ibm
[ceph: root@host01 /]# rbd mirror pool peer remove pool_failback f055bb88-6253-4041-923d-08c4ecbe799a
```

Copy to clipboard

5. On a Ceph client node, bootstrap the storage cluster peers.

1. Create Ceph user accounts, and register the storage cluster peer to the pool:

Syntax

```plaintext-ibm
rbd mirror pool peer bootstrap create --site-name LOCAL_SITE_NAME POOL_NAME > PATH_TO_BOOTSTRAP_TOKEN
```

Copy to clipboard

Example

```plaintext-ibm
[ceph: root@rbd-client-site-a /]# rbd mirror pool peer bootstrap create --site-name site-a data > /root/bootstrap_token_site-a
```

Copy to clipboard

> 📝 **Note:** Note:
This example bootstrap command creates the
`client.rbd-mirror.site-a`
and the
`client.rbd-mirror-peer`
Ceph users.
2. Copy the bootstrap token file to the `site-b` storage cluster.
3. Import the bootstrap token on the `site-b` storage cluster:

Syntax

```plaintext-ibm
rbd mirror pool peer bootstrap import --site-name LOCAL_SITE_NAME --direction rx-only POOL_NAME PATH_TO_BOOTSTRAP_TOKEN
```

Copy to clipboard

Example

```plaintext-ibm
[ceph: root@rbd-client-site-b /]# rbd mirror pool peer bootstrap import --site-name site-b --direction rx-only data /root/bootstrap_token_site-a
```

Copy to clipboard

> 📝 **Note:** Note:
For one-way RBD mirroring, you must use the
`--direction rx-only`
argument, as
two-way mirroring is the default when bootstrapping peers.
