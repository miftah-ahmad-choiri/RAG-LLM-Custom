## Preparing import-only migration

Last Updated
: 2026-09-09

You can initiate the import-only live migration process by running the rbd migration prepare command with the --import-only flag and either the --source-spec or --source-spec-path options. The import-only process is implemented by passing a JSON document that describes how to access the source image data directly on the command line or from a file.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running IBM Storage Ceph cluster.
- The destination pool exists.
- A bucket and an S3 object are created.

### Procedure

1. Create a JSON file.
For example,

```
[ceph: root@rbd-client /]# cat testspec.json
 {
   "type": "raw",
    "stream": {
        "type": "s3",
        "url": "http:10.74.253.18:80/testbucket1/image.raw",
       "access_key": "RLJOCP6345BGB38YQXI5",
       "secret_key": "oahWRB2ote2rnLy4dojYjDrsvaBADriDDgtSfk6o"
  }
```
2. Prepare the import-only live migration process.

```plaintext-ibm
rbd migration prepare --import-only --source-spec-path "JSON_FILE" TARGET_POOL_NAME/SOURCE_IMAGE_NAME
```

Copy to clipboard

For example,

```
[ceph: root@rbd-client /]# rbd migration prepare --import-only --source-spec-path "testspec.json" targetpool1/sourceimage1
```
3. Create a JSON file that describes the source image.

To import data from an S3 source:

```
{
  "type": "raw",
  "stream": {
    "type": "s3",
    "url": "http://10.74.253.18:80/testbucket1/image.raw",
    "access_key": "RLJOCP6345BGB38YQXI5",
    "secret_key": "oahWRB2ote2rnLy4dojYjDrsvaBADriDDgtSfk6o"
  }
}
```

To import data from an image in another Ceph cluster by using a cluster configuration file:

```
{
  "cluster_name": "c1",
  "type": "native",
  "pool_name": "pool1",
  "image_name": "image1",
  "snap_name": "snap1"
}
```

Alternatively, specify monitor endpoints and authentication credentials directly in the source-spec file:

```
{
  "type": "native",
  "mon_host": "10.0.0.11,10.0.0.12,10.0.0.13",
  "client_name": "client.migration",
  "key": "AQAz7EVWygILFRAAdIcuJ12opU/JKyfFmxhuaw==",
  "pool_name": "pool1",
  "image_name": "image1",
  "snap_name": "snap1"
}
```

To avoid storing authentication credentials directly in the source-spec file, store the key in the MON config-key store and reference it by using the `config://` prefix.

Store the key:

```
[ceph: root@rbd-client /]# ceph config-key set rbd/native/my_key AQAz7EVWygILFRAAdIcuJ12opU/JKyfFmxhuaw==
```

Reference the stored key in the source-spec file:

```
{
  "type": "native",
  "mon_host": "10.0.0.11,10.0.0.12,10.0.0.13",
  "client_name": "client.migration",
  "key": "config://rbd/native/my_key",
  "pool_name": "pool1",
  "image_name": "image1",
  "snap_name": "snap1"
}
```

> 📝 **Note:** Important:

- Specify mon_host and key together.
- The cluster_name parameter is mutually exclusive with mon_host and key.
- If client_name is not specified, the default value is `client.admin`.

  - Specify mon_host and key together.
  - The cluster_name parameter is mutually exclusive with mon_host and key.
  - If client_name is not specified, the default value is `client.admin`.
4. Prepare the import-only migration process.

```plaintext-ibm
rbd migration prepare --import-only --source-spec-path JSON_FILE TARGET_POOL_NAME/SOURCE_IMAGE_NAME
```

Copy to clipboard

For example,

```
[ceph: root@rbd-client /]# rbd migration prepare \
--import-only \
--source-spec-path /tmp/native_spec \
c2pool1/c2image1 \
--cluster c2
```
5. Run the migration.

```
[ceph: root@rbd-client /]# rbd migration execute c2pool1/c2image1 --cluster c2
Image migration: 100% complete...done.
```
6. Commit the migration.

```
[ceph: root@rbd-client /]# rbd migration commit c2pool1/c2image1 --cluster c2
Commit image migration: 100% complete...done.
```

### What to do next

1. Check the current state of the import-only live migration process.

```plaintext-ibm
rbd status TARGET_POOL_NAME/SOURCE_IMAGE_NAME
```

Copy to clipboard

For example,

```
[ceph: root@rbd-client /]# rbd status targetpool1/sourceimage1
Watchers: none
Migration:
source: {"stream":{"access_key":"RLJOCP6345BGB38YQXI5","secret_key":"oahWRB2ote2rnLy4dojYjDrsvaBADriDDgtSfk6o","type":"s3","url":"http://10.74.253.18:80/testbucket1/image.raw"},"type":"raw"}
destination: targetpool1/sourceimage1 (b13865345e66)
state: prepared
```

The following example shows migrating data from Ceph cluster
`c1`
to Ceph cluster
`c2`
:

```
[ceph: root@rbd-client /]# cat /tmp/native_spec
{
  "cluster_name": "c1",
  "type": "native",
  "pool_name": "pool1",
  "image_name": "image1",
  "snap_name": "snap1"
}
ceph: root@rbd-client /]# rbd migration prepare --import-only --source-spec-path /tmp/native_spec c2pool1/c2image1 --cluster c2
ceph: root@rbd-client /]# rbd migration execute c2pool1/c2image1 --cluster c2
Image migration: 100% complete...done.
ceph: root@rbd-client /]# rbd migration commit c2pool1/c2image1 --cluster c2
Commit image migration: 100% complete...done.
```

> 📝 **Note:** Note:
Use either the
cluster_name
parameter or the
mon_host and key
parameters to connect to the source cluster.
2. Run the live migration. For more information, see Running the live migration.
