## Upgrading the IBM Storage Ceph cluster

Last Updated
: 2026-09-09

Use the ceph orch upgrade command to upgrade an IBM Storage Ceph cluster. Alternatively, update the cluster through the dashboard.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A supported IBM Storage Ceph cluster version. For more information, see Table 1.
- Root-level access to all the nodes.
- At least two Ceph Manager nodes in the storage cluster: one active and one standby.

> 📝 **Note:** Note:
IBM Storage Ceph
includes a health check function that returns a
DAEMON_OLD_VERSION
warning if it detects daemons in the storage cluster are running multiple versions of
IBM Storage Ceph
. The warning is triggered when the daemons continue to run multiple versions of
IBM Storage Ceph
beyond the time value set in the
`mon_warn_older_version_delay`
option. By default, the
`mon_warn_older_version_delay`
option is set to 1 week. This setting allows most upgrades to proceed without falsely seeing the warning.
If the upgrade process is paused for an extended time period, you can mute the health warning by using the
ceph health mute
command.

```plaintext-ibm
ceph health mute DAEMON_OLD_VERSION --sticky
```

Copy to clipboard

After the upgrade has finished, unmute the health warning, by using the
ceph health unmute
command.

```plaintext-ibm
ceph health unmute DAEMON_OLD_VERSION
```

Copy to clipboard

### About this task

Use either the command-line interface (CLI) or the Ceph Dashboard to upgrade a cluster. To update the cluster through the dashboard, see
Upgrading a cluster
. To upgrade through the CLI, continue with the instructions provided here.

The Ceph Orchestrator coordinates cluster upgrades by upgrading daemons in a controlled sequence while ensuring service availability. For OSD upgrades, the Orchestrator can limit upgrades to specific CRUSH failure domains, such as a rack, chassis, or host, enabling phased upgrades aligned with physical infrastructure boundaries.

For more information, see
Troubleshooting upgrade error messages
.

> 📝 **Note:** Important:
It is required to apply a gateway group name to the
`nvmeof`
service that doesn't have a group name. To define a group name for the NVMe-oF service that was upgraded from
IBM Storage Ceph
7.1
, see
Updating an NVMe-oF service with a gateway group name
.

If a cluster host is or becomes unavailable the upgrade will be paused until it is restored.

> 📝 **Note:** Note:
Starting from
IBM Storage Ceph
9.9.1
, license acceptance is required as part of the upgrade process. When the license is accepted, Call Home is enabled automatically.

When upgrading from a version earlier than 9.9.1 and the license is not accepted, the upgrade proceeds but a health warning is displayed and Call Home is not enabled.

When upgrading from IBM Storage Ceph 9.9.1 or later:

- You must accept the license before starting the upgrade.
- If the license is not accepted, the upgrade is blocked until acceptance is completed.

You can view and accept the license before starting the upgrade. When the license is accepted, Call Home is enabled automatically.

For more information about Call Home behavior, status, and configuration, see Call Home.

To run a staggered upgrade, see Running a staggered upgrade.

### What to do next

To complete the upgrade, rotate CephX keys. For more information, see Rotating CephX keys.

After the upgrade, a health warning might be displayed to indicate that Call Home is enabled.

Use Ceph Orchestrator commands to clear the health warning emitted by Call Home.

- Clear the health warning and allow the module to remain active.

```plaintext-ibm
ceph orch accept call-home-enabled
```

Copy to clipboard
- Clear the health warning and turn off the Call Home module.

```plaintext-ibm
ceph orch deny call-home-enabled
```

Copy to clipboard

Automatic service events are not enabled automatically. To enable service events, see
Enabling service events
.
