## Upgrading to 9.9.1 with RHEL 10 with stretch mode enabled from previous versions

Last Updated
: 2026-09-06

You can perform an upgrade from IBM Storage Ceph 7.1.0 or 8.1.0 to IBM Storage Ceph 9.9.1 involving Red Hat Enterprise Linux 9 to Red Hat Enterprise Linux 10 with the stretch mode enabled.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- IBM Storage Ceph on Red Hat Enterprise Linux 9 with necessary hosts and daemons that run with stretch mode enabled.
- Backup of Ceph binary (/usr/sbin/cephadm), ceph.pub (/etc/ceph), and the Ceph cluster’s public SSH keys from the admin node.

### About this task

> 📝 **Note:** Important:
Upgrade to the latest version of
IBM Storage Ceph
7.1.0 or 8.1.0 before upgrading to the latest version of
IBM Storage Ceph
9.9.1
.

### Procedure

1. Log in to the
`cephadm`
shell.

```plaintext-ibm
cephadm shell
```

Copy to clipboard
2. Label a second node as the admin in the cluster to manage the cluster when the admin node is reprovisioned.

```plaintext-ibm
ceph orch host label add HOSTNAME_admin
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph orch host label add host02_admin
```
3. Set the
`noout`
flag.

```plaintext-ibm
ceph osd set noout
```

Copy to clipboard
4. Drain all daemons from the host.

```plaintext-ibm
ceph orch host drain HOSTNAME --force
```

Copy to clipboard

The `_no_schedule` label is automatically applied to the host that blocks deployment.
5. Verify that all daemons are removed from the storage cluster.

```plaintext-ibm
ceph orch ps HOSTNAME
```

Copy to clipboard
6. Zap the devices.
Zapping the devices helps ensure that the hosts being drained have OSDs present. After the hosts are drained, they can be used to redeploy OSDs when the host is added back.

```plaintext-ibm
ceph orch device zap HOSTNAME DISK --force
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph orch device zap ceph-host02 /dev/vdb --force

zap successful for /dev/vdb on ceph-host02
```
7. Verify the status of the OSD removal.

```plaintext-ibm
ceph orch host rm HOSTNAME --force
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph orch host rm host02 --force
```
8. Reprovision the respective hosts from RHEL 9 to RHEL 10.
Use the instructions, as detailed in
[Upgrading from RHEL 9 to RHEL 10](https://www.ibm.com/links?url=https%3A%2F%2Fdocs.redhat.com%2Fen%2Fdocumentation%2Fred_hat_enterprise_linux%2F9%2Fhtml%2Fupgrading_from_rhel_8_to_rhel_9%2Findex)
, on
[Red Hat Documentation](https://www.ibm.com/links?url=https%3A%2F%2Fdocs.redhat.com%2Fen%2Fdocumentation%2F)
.
9. Go to the
/usr/share/cephadm-ansible/
directory.

```plaintext-ibm
cd /usr/share/cephadm-ansible
```

Copy to clipboard
10. Run the preflight playbook with the
`--limit`
option.

```plaintext-ibm
ansible-playbook -i INVENTORY_FILE cephadm-preflight.yml --limit NEW_HOSTNAME
```

Copy to clipboard

For example,

```
[ceph: root@host01 cephadm ansible]# ansible-playbook -i hosts cephadm-preflight.yml --extra-vars "ceph_origin={storage-product}" --limit host02
```

The preflight playbook installs
`podman`
,
`lvm2`
,
`chrony`
, and
`cephadm`
on the new host. After installation is complete,
`cephadm`
is found in the
`/usr/sbin/`
directory.
11. Extract the cluster’s public SSH keys to a folder.

```plaintext-ibm
ceph cephadm get-pub-key ~/PATH
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph cephadm get-pub-key ~/ceph.pub
```
12. Copy the Ceph cluster public SSH keys to the reprovisioned node.

```plaintext-ibm
ssh-copy-id -f -i ~/PATH root@HOSTNAME_2
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ssh-copy-id -f -i ~/ceph.pub root@host02
```
13. **Optional:**
If the removed host has a monitor daemon, before adding the host to the cluster, add the
`--unmanaged`
flag to monitor deployment.

```plaintext-ibm
ceph orch apply mon PLACEMENT --unmanaged
```

Copy to clipboard
14. Re-add the host to the cluster and re-add the labels that were present earlier.

```plaintext-ibm
ceph orch host add HOSTNAME IP_ADDRESS --labels=LABELS
```

Copy to clipboard

The following examples give different ways to re-add the host to the cluster.

- ```plaintext-ibm
ceph mon add HOSTNAME IP_LOCATION
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph mon add ceph-host02 10.0.211.62 datacenter=DC2
```
- ```plaintext-ibm
ceph orch daemon add mon HOSTNAME
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph orch daemon add mon ceph-host02
```

  - ```plaintext-ibm
  ceph mon add HOSTNAME IP_LOCATION
  ```



  Copy to clipboard

  For example,

  ```
  [ceph: root@host01 /]# ceph mon add ceph-host02 10.0.211.62 datacenter=DC2
  ```
  - ```plaintext-ibm
  ceph orch daemon add mon HOSTNAME
  ```



  Copy to clipboard

  For example,

  ```
  [ceph: root@host01 /]# ceph orch daemon add mon ceph-host02
  ```
15. Verify the daemons on the reprovisioned host running successfully with the same Ceph version.

```plaintext-ibm
ceph orch ps
```

Copy to clipboard
16. Set the monitor daemon placement to
`managed`
.

```plaintext-ibm
ceph orch apply mon managed
```

Copy to clipboard
17. Repeat all previous steps for each host.
18. Reprovision the arbiter monitor.
The arbiter monitor cannot be drained or removed from the host. As a result, the arbiter monitor must be reprovisioned to another tie-breaker node, and then drained or removed from host. For more information, see
Replacing a tiebreaker with a new monitor
.
19. Reprovision the administrator nodes.
Use a second administrator node to manage clusters. For more information, see
Replacing a tiebreaker with a new monitor
.
20. Re-add the backup files to the node.
21. Re-add the administrator noes to the cluster, by using the second administrator node.
Set the
`mon`
deployment to
`unmanaged`
.

```plaintext-ibm
ceph orch apply mon unmanaged
```

Copy to clipboard
22. Re-add the original arbiter monitor and remove the temporary monitor that was created in step
18
.
For more information, see
Replacing a tiebreaker with a new monitor
.
23. Unset the
`noout`
flag.

```plaintext-ibm
ceph osd unset noout
```

Copy to clipboard

### What to do next

1. Verify the Ceph version and the cluster status to help ensure that all demons are working as expected after the OS upgrade.
2. Follow the Upgrading an IBM Storage Ceph cluster using cephadm to upgrade from IBM Storage Ceph 7.1.0 or 8.1.0 to 9.9.1.
