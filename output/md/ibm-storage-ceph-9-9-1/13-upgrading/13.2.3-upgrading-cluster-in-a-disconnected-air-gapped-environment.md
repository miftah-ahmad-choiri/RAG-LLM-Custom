## Upgrading cluster in a disconnected (air-gapped) environment

Last Updated
: 2026-09-09

Upgrade the IBM Storage Ceph cluster in a disconnected environment.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- Supported version of IBM Storage Ceph cluster. For more information, see Supported upgrade paths.
- Root-level access to all the nodes.
- At least two Ceph Manager nodes in the storage cluster: one active and one standby.
- Register the nodes to CDN and attach subscriptions.
- Check for the customer container images in a disconnected environment and change the configuration, if required. For more information, see Changing configurations of custom container images for disconnected installations.

### About this task

Upgrade the storage cluster in a disconnected environment by using the
--image
tag.

By default, the monitoring stack components are deployed based on the primary Ceph image. For disconnected environment of the storage cluster, you have to use the latest available monitoring stack component images.

> 📝 **Note:** Important:
Call Home is enabled automatically when the license is accepted, including in disconnected environments. If your environment requires disabling outbound communication, disable Call Home after the upgrade is complete.

For more information, see Call Home.

### Procedure

1. Add the license to install
IBM Storage Ceph
and click
Accept
on all nodes.

```plaintext-ibm
dnf install ibm-storage-ceph-license
```

Copy to clipboard
2. Accept the provisions.

```plaintext-ibm
sudo touch /usr/share/ibm-storage-ceph-license/accept
```

Copy to clipboard
3. Update the
`cephadm`
and
`cephadm-ansible`
package.

```plaintext-ibm
dnf update cephadm
dnf update cephadm-ansible
```

Copy to clipboard

For example,

```
[root@admin cephadm-ansible]# dnf update cephadm
 [root@admin cephadm-ansible]# dnf update cephadm-ansible
```
4. Navigate to the
`/usr/share/cephadm-ansible/`
directory.

```plaintext-ibm
cd /usr/share/cephadm-ansible
```

Copy to clipboard
5. Run the preflight playbook with the
upgrade_ceph_packages
parameter set to
true
and the
ceph_origin
parameter set to
custom
on the bootstrapped host in the storage cluster.

```plaintext-ibm
ansible-playbook -i INVENTORY_FILE cephadm-preflight.yml --extra-vars "ceph_origin=custom upgrade_ceph_packages=true"
```

Copy to clipboard

For example,

```
[ansible@admin cephadm-ansible]$ ansible-playbook -i /etc/ansible/hosts cephadm-preflight.yml --extra-vars "ceph_origin=custom upgrade_ceph_packages=true"
```

This package upgrades
`cephadm`
on all the nodes.
6. Log into the
`cephadm`
shell.

```plaintext-ibm
cephadm shell
```

Copy to clipboard
7. Ensure all the hosts are online and that the storage cluster is healthy.

```plaintext-ibm
ceph -s
```

Copy to clipboard
8. Check service versions and the available target containers.

```plaintext-ibm
ceph orch upgrade check IMAGE_NAME
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph orch upgrade check LOCAL_NODE_FQDN:5000/ibm-ceph/ceph-9-rhel9:latest
```
9. Set the OSD
`noout`
,
`noscrub`
, and
`nodeep-scrub`
flags to prevent OSDs from getting marked out during upgrade and to avoid unnecessary load on the cluster.

```plaintext-ibm
ceph osd set noout
ceph osd set noscrub
ceph osd set nodeep-scrub
```

Copy to clipboard

```
[ceph: root@host01 /]# ceph osd set noout
 [ceph: root@host01 /]# ceph osd set noscrub
 [ceph: root@host01 /]# ceph osd set nodeep-scrub
```
10. Upgrade the storage cluster.

> 📝 **Note:** Note:
You can optionally accept the license before upgrading the storage cluster.

```plaintext-ibm
ceph orch accept-license
```

Copy to clipboard

You can include the --automatically-accept-license flag with the ceph orch upgrade start command to accept the license during the upgrade.

> 📝 **Note:** Note:
The following procedure provides syntax and examples for installing with Red Hat Enterprise Linux
9.8
. For installing with Red Hat Enterprise Linux
10.2
, replace
`rhel-9`
with
`rhel-10`
, in each instance.

```plaintext-ibm
ceph orch upgrade start --image IMAGE_NAME [--automatically-accept-license]
```

Copy to clipboard

For staggered upgrades where OSDs can be upgraded efficiently at specific CRUSH bucket scopes (such as rack, chassis, or host), see Running a staggered upgrade.

You can scope OSD upgrades to a specific failure domain, such as a rack. For more information, see Upgrading OSDs by rack.

For example,

```
ceph orch upgrade start --image cp.icr.io/cp/ibm-ceph/ceph-9-rhel9:latest
```

While the upgrade is underway, a progress bar appears in the
ceph status
command output. For example,

```
[ceph: root@host01 /]# ceph status
[...]
progress:
    Upgrade to 20.1.0-145.el9cp (1s)
      [............................]
```

For more information about monitoring the upgrade status, see Monitoring and managing upgrade.
11. Verify the new
IMAGE_ID
and
VERSION
of the cluster.

```plaintext-ibm
ceph version
ceph versions
ceph orch ps
```

Copy to clipboard

For example,

```
[ceph: root@host01 /]# ceph version
[ceph: root@host01 /]# ceph versions
[ceph: root@host01 /]# ceph orch ps
```
12. When the upgrade is complete, unset the
`noout`
,
`noscrub`
, and
`nodeep-scrub`
flags.

```plaintext-ibm
ceph osd unset noout
ceph osd unset noscrub
ceph osd unset nodeep-scrub
```

Copy to clipboard

```
[ceph: root@host01 /]# ceph osd unset noout
[ceph: root@host01 /]# ceph osd unset noscrub
[ceph: root@host01 /]# ceph osd unset nodeep-scrub
```

### What to do next

To complete the upgrade, rotate CephX keys. For more information, see Rotating CephX keys.

After the upgrade, a health warning might be displayed to indicate that Call Home is enabled.

Use Ceph Orchestrator commands to clear the health warning emitted by Call Home.

- Clear the health warning and allow the module to remain active.

```plaintext-ibm
ceph orch accept call-home-enabled
```

Copy to clipboard
- Clear the health warning and turn off the Call Home module.

```plaintext-ibm
ceph orch deny call-home-enabled
```

Copy to clipboard

Automatic service events are not enabled automatically. To enable service events, see
Enabling service events
.
