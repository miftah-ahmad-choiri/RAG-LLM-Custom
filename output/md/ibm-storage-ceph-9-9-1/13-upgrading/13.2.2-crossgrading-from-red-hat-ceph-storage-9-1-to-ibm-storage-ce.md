## Crossgrading from Red Hat Ceph Storage 9.1 to IBM Storage Ceph 9.9.1

Last Updated
: 2026-09-09

Crossgrade from a Red Hat Ceph Storage 9.1 to IBM Storage Ceph 9.9.1 cluster with the ceph orch upgrade command.

### Before you begin

- Latest version of Red Hat Ceph Storage cluster 9.1.
- Root-level access to all the nodes.
- Ansible user with `sudo` and passwordless `ssh` access to all nodes in the storage cluster.
- At least two Ceph Manager nodes in the storage cluster, one active and one on standby.

### About this task

You can use ceph orch upgrade command to upgrade to an IBM Storage Ceph 9.9.1 cluster.

> 📝 **Note:** Important:
IBM Storage Ceph
9.9.1
also includes a health check function that returns a
`DAEMON_OLD_VERSION`
warning if it detects that any of the daemons in the storage cluster are running multiple versions of
IBM Storage Ceph
. The warning is triggered when the daemons continue to run multiple versions of
IBM Storage Ceph
beyond the time value set in the
mon_warn_older_version_delay
option. By default, the
mon_warn_older_version_delay
option is set to 1 week. This setting allows most upgrades to proceed without falsely seeing the warning.
If the upgrade process is paused for an extended time period, you can mute the health warning:

```plaintext-ibm
ceph health mute DAEMON_OLD_VERSION --sticky
```

Copy to clipboard

After the upgrade, unmute the health warning:

```plaintext-ibm
ceph health unmute DAEMON_OLD_VERSION
```

Copy to clipboard

> 📝 **Note:** Note:
Starting from
IBM Storage Ceph
9.9.1
, license acceptance is required as part of the upgrade process. When the license is accepted, Call Home is enabled automatically.

When upgrading from a version earlier than 9.9.1 and the license is not accepted, the upgrade proceeds but a health warning is displayed and Call Home is not enabled.

When upgrading from IBM Storage Ceph 9.9.1 or later:

- You must accept the license before starting the upgrade.
- If the license is not accepted, the upgrade is blocked until acceptance is completed.

You can view and accept the license before starting the upgrade. When the license is accepted, Call Home is enabled automatically.

For more information about Call Home behavior, status, and configuration, see Call Home.

> 📝 **Note:** Note:
The following procedure provides syntax and examples for installing with Red Hat Enterprise Linux
9.8
. For installing with Red Hat Enterprise Linux
10.2
, replace
`rhel-9`
with
`rhel-10`
, in each instance.

### Procedure

1. Enable the Red Hat Enterprise Linux baseos and appstream repositories.

```plaintext-ibm
subscription-manager repos --enable=rhel-9-for-x86_64-baseos-rpms
subscription-manager repos --enable=rhel-9-for-x86_64-appstream-rpms
```

Copy to clipboard

For example,

```
[root@admin ~]# subscription-manager repos --enable=rhel-9-for-x86_64-baseos-rpms
[root@admin ~]# subscription-manager repos --enable=rhel-9-for-x86_64-appstream-rpms
```

Repeat this step on all the nodes of the storage cluster.
2. Disable the Red Hat Ceph Storage
`ceph-tools`
repository (
`/etc/yum.repos.d/`
).

> 📝 **Note:** Important:
This step must be performed to avoid upgrade failures of
`cephadm`
and
`ceph-ansible`
packages.

```plaintext-ibm
subscription-manager repos --disable=rhceph-9-tools-for-rhel-9-x86_64-rpms
```

Copy to clipboard

For example,

```
[root@host01 yum.repos.d]# subscription-manager repos --disable=rhceph-9-tools-for-rhel-9-x86_64-rpms
```

Repeat this step on all the nodes of the storage cluster.
3. Enable the
IBM Storage Ceph
`ceph-tools`
repository (
`/etc/yum.repos.d/`
) for Red Hat Enterprise Linux 9 or 10.

```plaintext-ibm
curl https://public.dhe.ibm.com/ibmdl/export/pub/storage/ceph/ibm-storage-ceph-9-rhel-9.repo | sudo tee /etc/yum.repos.d/ibm-storage-ceph-9-rhel-9.repo
```

Copy to clipboard

Repeat this step on all the nodes of the storage cluster.
4. Add license to install
IBM Storage Ceph
and click
Accept
on all nodes.

```plaintext-ibm
dnf -y install ibm-storage-ceph-license
```

Copy to clipboard
5. Accept these provisions.

```plaintext-ibm
sudo touch /usr/share/ibm-storage-ceph-license/accept
```

Copy to clipboard
6. Reinstall
`cephadm`
and
`cephadm-ansible`

```plaintext-ibm
dnf -y reinstall cephadm
dnf -y reinstall cephadm-ansible
```

Copy to clipboard
7. Navigate to the
/usr/share/cephadm-ansible/
directory.

```plaintext-ibm
cd /usr/share/cephadm-ansible
```

Copy to clipboard
8. Run the preflight playbook with the
upgrade_ceph_packages
parameter set to
`true`
on the bootstrapped host in the storage cluster.

```plaintext-ibm
ansible-playbook -i INVENTORY_FILE cephadm-preflight.yml --extra-vars "ceph_origin=ibm upgrade_ceph_packages=true"
```

Copy to clipboard

```
[ansible@admin cephadm-ansible]$ ansible-playbook -i /etc/ansible/hosts cephadm-preflight.yml --extra-vars "ceph_origin=ibm upgrade_ceph_packages=true"
```

This package upgrades
`cephadm`
on all the nodes.
9. Log in to the
`cephadm`
shell.

```plaintext-ibm
cephadm shell
```

Copy to clipboard
10. Ensure all the hosts are online and that the storage cluster is healthy.

```plaintext-ibm
ceph -s
```

Copy to clipboard
11. Set the OSD
`noout`
,
`noscrub`
, and
`nodeep-scrub`
flags to prevent OSDs from getting marked out during upgrade and to avoid unnecessary load on the cluster.

```plaintext-ibm
ceph osd set noout
ceph osd set noscrub
ceph osd set nodeep-scrub
```

Copy to clipboard
12. Log in to registry.

```plaintext-ibm
ceph cephadm registry-login cp.icr.io USERNAME PASSWORD
```

Copy to clipboard

or log in with the
`json`
file.

```plaintext-ibm
cat mylogin.json
{ "url":"REGISTRY_URL",
"username":"USER_NAME",
"password":"PASSWORD" }
ceph cephadm registry-login -i mylogin.json
```

Copy to clipboard
13. Check service versions and the available target containers.

```plaintext-ibm
ceph orch upgrade check IMAGE_NAME
```

Copy to clipboard

```
[ceph: root@host01 /]# ceph orch upgrade check cp.icr.io/cp/ibm-ceph/ceph-9-rhel9:latest
```
14. Upgrade the storage cluster.
Optionally, accept the license before upgrading the storage cluster.

```plaintext-ibm
ceph orch accept-license
```

Copy to clipboard

Alternatively, include the --automatically-accept-license flag with the ceph orch upgrade start command to accept the license during the upgrade.

```plaintext-ibm

ceph orch upgrade start --image IMAGE_NAME [--automatically-accept-license]
```

Copy to clipboard

```
[ceph: root@host01 /]# ceph orch upgrade start cp.icr.io/cp/ibm-ceph/ceph-9-rhel9:latest
```
15. While the upgrade is underway, a progress bar appears in the
ceph status
command output.

```
[ceph: root@host01 /]# ceph status
[...]
progress:
    Upgrade to 18.2.1-10.el9cp (1s)
 [............................]
```

For more information about monitoring the upgrade status, see
Monitoring and managing upgrade
.
16. Verify the new
IMAGE_ID
and
VERSION
of the Ceph cluster.

```plaintext-ibm
ceph versions
ceph orch ps
```

Copy to clipboard
17. If you are not using the
`cephadm-ansible`
playbooks, after upgrading your Ceph cluster, you must upgrade the
`ceph-common`
package and client libraries on your client nodes.

```plaintext-ibm
dnf -y reinstall ceph-common
```

Copy to clipboard
18. Verify that you have the latest version.

```plaintext-ibm
ceph --version
```

Copy to clipboard
19. When the upgrade is complete, unset the
`noout`
,
`noscrub`
, and
`nodeep-scrub`
flags.

```plaintext-ibm
ceph osd unset noout
ceph osd unset noscrub
ceph osd unset nodeep-scrub
```

Copy to clipboard

### What to do next

After the upgrade, a health warning might be displayed to indicate that Call Home is enabled.
Use Ceph Orchestrator commands to clear the health warning emitted by Call Home.

- Clear the health warning and allow the module to remain active.

```plaintext-ibm
ceph orch accept call-home-enabled
```

Copy to clipboard
- Clear the health warning and turn off the Call Home module.

```plaintext-ibm
ceph orch deny call-home-enabled
```

Copy to clipboard

Automatic service events are not enabled automatically. To enable service events, see
Enabling service events
.
