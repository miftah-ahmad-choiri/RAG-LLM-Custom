## Configuring RDMA support in NFS

Last Updated
: 2026-06-25

Enable RDMA transport in the NFS configuration.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- Ensure RDMA adapters are properly configured on both the client and the server.
- RDMA stack and drivers are installed and loaded successfully.

```
[root@host01:~]# rdma link show
link bnxt_re0/1 state ACTIVE physical_state LINK_UP netdev eno12399np0
```
- NFS is installed

### About this task

RDMA transport can be enabled on both new and existing NFS clusters managed by `cephadm`.

- For new clusters, RDMA is configured at creation time.
- For existing clusters, RDMA is enabled by updating the service specification and redeploying the NFS daemons.

### Enabling RDMA on newly deployed NFS Clusters.

#### Procedure

1. Create a new NFS cluster with RDMA enabled using the `--enable-rdma` flag:

```plaintext-ibm
ceph nfs cluster create cluster_name
"counthost1host2..." \

--enable-rdma \

--rdma_port port \

--port nfs_tcp_port
```

Copy to clipboard

For example,

Active-active cluster (no VIP)

```
ceph nfs cluster create nfs-rdma1 "2 host01 host02" \

--enable-rdma --rdma_port 20049 --enable-nfsv3 --port 2049
```

> 📝 **Note:** Note:
The above command enables the following:

- NFSv3
- NFSv4 with all minor versions (.0, .1, .2)
- NFS over RDMA transport on port 20049
- NFS over TCP transport on port 2049

For example,

HA cluster with VIP

```
ceph nfs cluster create nfs-rdma-ha "2 host03 host04" \

--enable-rdma --rdma_port 20050 \

--enable-nfsv3 --port 2050 \

--ingress --virtual_ip 10.64.66.99
```

> 📝 **Note:** Note:
The above command enables the following:

- NFSv3
- NFSv4 with all minor versions (.0, .1, .2)
- NFS over RDMA transport on port 20050
- NFS over TCP transport on port 2050 (proxied through haproxy/keepalived via VIP)
- HA with VIP failover (RDMA connects directly to Ganesha; TCP is proxied through ingress)

  - NFSv3
  - NFSv4 with all minor versions (.0, .1, .2)
  - NFS over RDMA transport on port 20049
  - NFS over TCP transport on port 2049
2. Verify the cluster is running after a few seconds:

```plaintext-ibm
ceph nfs cluster ls

ceph orch ps --daemon-type nfs
```

Copy to clipboard

### Enabling RDMA on existing NFS clusters

#### About this task

For an NFS cluster that was originally deployed without RDMA, export the current service specification, add the RDMA parameters, and re-apply it.

#### Procedure

1. Export the current service spec from admin client:

```plaintext-ibm
ceph orch ls --service-name nfs.cluster_name--export nfs-spec.yaml
```

Copy to clipboard
2. Edit the spec to add RDMA parameters under the `spec:` block:
yaml

```plaintext-ibm

service_type: nfs
service_id: nfs-existing
placement:
count: 2
hosts:
- host01
- host02
spec:
port: 2049
enable_rdma: true # Add this
rdma_port: 20049 # Add this
```

Copy to clipboard
3. Apply the updated spec;

```plaintext-ibm
ceph orch apply -i nfs-spec.yaml
```

Copy to clipboard

> 📝 **Note:** Note:
This enables the following:

- NFS over RDMA transport on port 20049 (new)
- NFS over TCP transport on port 2049 (unchanged, existing clients unaffected)
- All previously configured NFS protocol versions remain active
- All existing exports are preserved

  - NFS over RDMA transport on port 20049 (new)
  - NFS over TCP transport on port 2049 (unchanged, existing clients unaffected)
  - All previously configured NFS protocol versions remain active
  - All existing exports are preserved
4. Verify the NFS daemons redeploy with RDMA enabled:

```plaintext-ibm
ceph orch ps --daemon-type nfs

ceph orch ls --service-name nfs.cluster_name
```

Copy to clipboard

The daemons will be redeployed automatically by `cephadm`. Clients using TCP connections are not affected. New RDMA clients can connect once the daemons are back.

> 📝 **Note:** Note:
During redeployment, there is a brief NFS service interruption while daemons restart.

> 📝 **Note:** Note:
Only new exports created after enabling RDMA on the cluster will include RDMA in the transport layer. Existing exports will continue to use TCP only. To enable RDMA on existing exports, you must update them manually. For more information, see
Configuring RDMA transport for NFS shares
.
