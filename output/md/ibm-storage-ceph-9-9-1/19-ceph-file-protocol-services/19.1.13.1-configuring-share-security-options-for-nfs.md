## Configuring share security options for NFS

Last Updated
: 2026-06-25

Set share security (XprtSec) options in NFS to control how clients connect using TLS or mTLS and understand the expected behavior for different configurations.

### About this task

Share security options determine whether NFS traffic uses plaintext or encrypted (TLS or mTLS) . These settings affect client mount behavior and enforce encryption policies for secure communication.

### Procedure

Share security options.

```plaintext-ibm
ceph nfs export create cephfs mynfs /export3 myfs --xprtsec tls
```

Copy to clipboard

The expected behavior based on server share security and client mount options are listed in Table 1.

| Server share security | Client mount option | Expected behavior |
| --- | --- | --- |
| XprtSec=none | (no xprtsec) | Mount succeeds in plaintext (unencrypted TCP/UDP). |
| XprtSec=none | xprtsec=tls | Mount succeeds over TLS; encryption used even though not required. |
| XprtSec=none | xprtsec=mtls | Mount succeeds over TLS; encryption used even though not required. |
| XprtSec=tls | (no xprtsec) | Mount fails with EACCES ("Permission denied") - server rejects non-TLS connections. |
| XprtSec=tls | xprtsec=tls | Mount succeeds over TLS; server certificate validated by client. |
| XprtSec=tls | xprtsec=mtls | Mount succeeds over TLS; client certificate validation is not enforced. |
| XprtSec=mtls | (no xprtsec) | Mount fails with EACCES - client not attempting mTLS. |
| XprtSec=mtls | xprtsec=tls | Mount fails with EACCES - mTLS required; client must provide valid certificate. |
| XprtSec=mtls | xprtsec=mtls | Mount succeeds only if client presents a valid certificate trusted by the server; otherwise fails with EACCES. |

You can specify share security options manually. For more information, see
Manually specify share security options for NFS
.
