## Rate-limiting (QoS) in SMB

Last Updated
: 2026-09-10

You can configure throughput or Quality of Service (QoS) settings for Ceph File System (CephFS) SMB shares to control performance. QoS settings optimize share performance and improve task execution speed.

You can update QoS limits to apply per-share rate limits on SMB input/output (I/O) operations. These limits include IOPS (Input/Output Operations per Second) and bandwidth (in bytes per second) for both read and write operations. Additionally, burst multipliers can be configured to allow temporary bursts above the configured limits.

Supported QoS limits are:

- IOPS (Input/Output Operations per Second)
- Bandwidth (bytes per second)
- Burst multipliers (for temporary spikes above configured limits)

### Methods for updating QoS limits

You can update QoS limits using one of the following approaches:

Imperative
Set bandwidth limits using CLI commands or API calls for a specific queue.
Declarative
Define the desired QoS state, for example, in a Kubernetes YAML manifest. The system automatically reconciles the current state to match the desired configuration.

### Bandwidth rate-limiting

SMB bandwidth rate limiting controls how much bandwidth SMB clients use when accessing or transferring data from an SMB server. This feature operates at both export and client levels, managing read/write requests and IOPS.

The supported QoS parameters and their valid ranges are listed in Table 1.

| Option | Description | Valid Range |
| --- | --- | --- |
| read_iops_limit | Maximum number of read operations per second (0 = disabled). | 0 to 1,000,000 |
| write_iops_limit | Maximum number of write operations per second (0 = disabled). | 0 to 1,000,000 |
| read_bw_limit | Maximum allowed bandwidth for read operations (0 = disabled). Can be specified as bytes per second or human-readable string (e.g., "10M"). | 0 to 1 << 40 (≈1 TB/s) |
| write_bw_limit | Maximum allowed bandwidth for write operations (0 = disabled). Can be specified as bytes per second or human-readable string (e.g., "20M"). | 0 to 1 << 40 (≈1 TB/s) |
| read_burst_mult | Burst multiplier for read operations (value ÷ 10 = multiplier). Allows temporary bursts above configured limit. Example: 20 = 2× limit. | 10 to 100 (1× to 10×), default: 15 (1.5×) |
| write_burst_mult | Burst multiplier for write operations (value ÷ 10 = multiplier). Allows temporary bursts above configured limit. Example: 20 = 2× limit. | 10 to 100 (1× to 10×), default: 15 (1.5×) |
| cluster_mode | Controls whether rate limiting is enforced cluster-wide (true) or per-node (false) when using SMB clustering (CTDB). | true or false, default: true when clustering active |

### Specifying bandwidth limits using human-readable units

You can specify bandwidth limits using human-readable units instead of raw byte values. Supported units include:

- K (kilobytes) = 1024 bytes
- M (megabytes) = 1024² bytes
- G (gigabytes) = 1024³ bytes

This enhancement simplifies configuration and removes the need for manual byte conversion.

For example,

```
--read-bw-limit=100M
--write-bw-limit=1G
```

> 📝 **Note:** Note:
Specifying bandwidth limits using raw byte values is still supported for backward compatibility.

### Burst behavior

The burst multiplier allows short-term I/O bursts above your configured limits. For example, if you set `read_iops_limit = 1000` and `read_burst_mult = 20`, your share can handle bursts up to 2000 read operations per second for short periods, while maintaining an average of 1000 IOPS over time.

This is useful for workloads that have occasional spikes in activity. The appropriate burst multiplier depends on your workload - higher values allow larger bursts but may temporarily consume more resources.

> 📝 **Note:** Note:
The burst multiplier only affects short-term spikes. The long-term average throughput remains limited by your configured IOPS and bandwidth limits.

### Rate-limiting behaviour

The following rules define how QoS limits behave when configured for SMB shares:

- All limits are optional.
- Setting a limit to `0` disables that specific QoS limit.
- Setting all four limits (IOPS and bandwidth) to `0` completely removes QoS configuration.
- Burst multipliers only apply when their corresponding limit is enabled (non-zero).
- Bandwidth limits can be specified with human-readable units (e.g., "10M", "5G").
- Burst multipliers are expressed in tenths (e.g., 15 = 1.5×, 20 = 2×, 30 = 3×).
- `cluster_mode` only affects behavior when SMB clustering (CTDB) is enabled.

For example, set QoS limits with burst multipliers:

```
ceph smb share update cephfs qos foo bar \
  --read-iops-limit=100 \
  --write-iops-limit=200 \
  --read-bw-limit="10M" \
  --write-bw-limit="20M" \
  --read-burst-mult=20 \
  --write-burst-mult=15 \
  --cluster-mode=true
```

In this example:

- Read burst multiplier of 20 means 2× the read IOPS limit (allowing bursts up to 200 read IOPS)
- Write burst multiplier of 15 means 1.5× the write IOPS limit (allowing bursts up to 300 write IOPS)
- Cluster-wide enforcement is enabled, so limits are aggregated across all nodes

### Cluster-wide rate-limiting behaviour

The `cluster_mode` parameter controls whether rate limiting is enforced cluster-wide or per-node when using SMB clustering (CTDB). When set to `true`, limits are enforced across all nodes in the cluster. When set to `false`, each node enforces limits independently. If not specified, SMB defaults to cluster-wide enforcement when clustering is active.

Previously, rate limiting was applied per node. Each node could consume the full configured limit independently, which could result in higher-than-expected aggregate usage across the cluster.

With cluster-wide rate limiting:

- IOPS and bandwidth limits are enforced globally across the cluster
- Limits are distributed fairly among active SMB connections
- All nodes coordinate to maintain consistent enforcement

This ensures predictable performance and prevents resource overconsumption in multi-node environments.

> 📝 **Note:** Important:
Use cluster-wide enforcement (
`cluster_mode=true`
) for clustered deployments. This is the default and recommended configuration. Use
`cluster_mode=false`
only as a temporary fallback if cluster-wide enforcement fails due to bugs or operational issues. Per-node rate limits can cause inconsistent QoS enforcement.

To disable QoS for a share:

```
ceph smb share update cephfs qos foo bar \
  --read-iops-limit=0 \
  --write-iops-limit=0 \
  --read-bw-limit=0 \
  --write-bw-limit=0
```
