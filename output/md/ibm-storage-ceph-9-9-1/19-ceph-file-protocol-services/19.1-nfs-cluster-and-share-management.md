## NFS cluster and share management

Last Updated
: 2026-09-06

As a storage administrator, you can create an NFS cluster, customize it, and export Ceph File System namespace over the NFS protocol.

Before you begin, make sure that you have the following prerequisites in place:

- A running, and healthy IBM Storage Ceph cluster.
- Installation and configuration of the Ceph Metadata Server daemons (`ceph-mds`).
- Create and mount a Ceph File System.

> 📝 **Note:** Note:
This documentation uses
*NFS share*
instead of the earlier term
*NFS export*
. In the Ceph Dashboard, labels and controls may still refer to NFS export.

When using object storage with the NFS service, the system maps object keys to a hierarchical namespace.

> 📝 **Note:** Important:

When you access object storage buckets through the NFS service, the system presents a hierarchical file system view instead of the native object key namespace.

The `/` character acts as a directory separator in the NFS protocol. Object keys that contain or start with `/` might not appear or behave as expected in an NFS share.

The NFS service can interpret these keys as directory paths instead of individual objects. As a result, some objects might not be visible, might appear as nested directories, or might be inaccessible through the NFS share.

Avoid creating object keys that start with
`/`
or depend on
`/`
in key names when accessing data through NFS shares. Use object storage APIs to access keys that require full namespace fidelity.
