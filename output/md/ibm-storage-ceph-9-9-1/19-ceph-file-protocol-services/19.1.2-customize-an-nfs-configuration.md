## Customize an NFS configuration

Last Updated
: 2026-06-25

Customize a Ceph‑managed NFS cluster by supplying a user configuration file. The user configuration is stored and managed by `cephadm` and is merged with the generated defaults at runtime. The user configuration takes precedence only for supported parameters.

### Before you begin

Before you begin, make sure that you have the following prerequisites in place:

- A running, and healthy IBM Storage Ceph cluster.
- Root-level access to a Ceph Metadata Server (MDS) node.
- An NFS cluster created using the `ceph nfs cluster create` command.

### About this task

Use this procedure to add or update supported NFS settings, such as logging, export defaults, and selected TLS policies for an existing NFS cluster. The configuration is stored by Ceph (in RADOS) and overlaid at runtime on the container‑generated base configuration.

### Procedure

1. Create a nfs-ganesha.conf file with custom parameters.

```plaintext-ibm
[root@ceph8-node1 ~]# cat ganesha2.conf
NFS_CORE_PARAM {
 Enable_NLM = true
 NFS_Protocols = 3,4;
NFS_Port = 2050;
 MNT_Port = 4048;
 mount_path_pseudo = true;
}
```

Copy to clipboard
2. Apply the custom conf using below command.

```plaintext-ibm
$ ceph nfs cluster config set singletest -i PATH_TO_CONFIG_FILE
```

Copy to clipboard

For example,

```
$ ceph nfs cluster config set nfs-cephfs -i ganesha2.conf
```
3. Get the custom config, check port in netstat and check Ganesha.conf inside container.

```plaintext-ibm
[root@ceph8-node1 ~]# ceph nfs cluster config get singletest
NFS_CORE_PARAM {
 Enable_NLM = true
 NFS_Protocols = 3,4;
NFS_Port = 2050;
 MNT_Port = 4048;
 mount_path_pseudo = true;
}
[root@ceph8-node1 ~]# netstat -tnlp | grep -i nfs
tcp6    0   0 :::2049         :::*          LISTEN   1476200/ganesha.nfs
tcp6    0   0 :::50051        :::*          LISTEN   1476200/ganesha.nfs
tcp6    0   0 :::9587         :::*          LISTEN   1476200/ganesha.nfs
tcp6    0   0 :::46089        :::*          LISTEN   1476200/ganesha.nfs
[root@ceph8-node1 ~]# cephadm shell
[ceph: root@ceph8-node1 /]# /bin/rados -p .nfs -N singletest get userconf-nfs.singletest -
NFS_CORE_PARAM {
 Enable_NLM = true
 NFS_Protocols = 3,4;
NFS_Port = 2050;
 MNT_Port = 4048;
 mount_path_pseudo = true;
}
```

Copy to clipboard

| Parameter | Default/Value | Description |
| --- | --- | --- |
| Enable_NLM | true | Enables Network Lock Manager to support NFSv3 locking semantics; set to true when NFSv3 clients require file locks. |
| NFS_Protocols | 3,4 | Specifies the NFS protocol versions the server supports and listens for. |
| NFS_Port | 2050 | Intended TCP service port for NFS. In Ceph-managed NFS, port binding is controlled at the service layer (for example, during cluster creation with a service port) and this overlay value does not change the listening socket. |
| MNT_Port | 4048 | Intended mountd port. Not applied via the user configuration overlay when the service is managed by cephadm. |
| mount_path_pseudo | true | Enables pseudo-path mounting for NFSv3, aligning its behavior with NFSv4-style pseudo roots. |

### Results

The NFS cluster applies the user‑defined configuration successfully, and the updated settings can be verified through the ceph nfs cluster config getcommand and functional validation.
