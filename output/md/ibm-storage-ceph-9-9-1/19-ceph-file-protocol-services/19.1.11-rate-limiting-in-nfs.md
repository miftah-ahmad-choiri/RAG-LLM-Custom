## Rate-limiting in NFS

Last Updated
: 2026-06-25

With the rate-limiting or QoS (quality of service) feature in NFS you can control the client’s read/write bandwidth and rate-limiting of the client's input/output operations (IOPS). This function operates at share and client levels, controlling read/write requests and IOPS. QoS helps ensures that all clients accessing backend storage receives a fair share of resources.

You can enable QoS for a single node NFS server and multiple instances of NFS servers.

The QoS configuration must be stored in the RADOS object and be accessible by any NFS server within the server group. Also, each share must reside on only one NFS server within the group.

The QoS function in NFS supports both bandwidth control and IOPS control.

> 📝 **Note:** Note:
The rate-limiting feature is supported only for NFS version 4 and later.

### Bandwidth rate-limiting

NFS bandwidth rate limiting allows administrators to control the amount of bandwidth that NFS clients use when accessing or transferring data from an NFS server. This helps prevent excessive network congestion, ensures fair bandwidth distribution, and optimizes network performance for all users and applications.

The following are supported options in bandwidth rate-limiting:

Per share
(export)
bandwidth control
Use this option to configure the maximum bandwidth that is allowed per share
(export)
. In this case, QoS makes sure that the cumulative bandwidth of all clients accessing this share does not exceed the set bandwidth. For example, if the bandwidth limit for a share is set to 100 Mbps, any client running any operation on this share is given only 100 Mbps speed.
Per client bandwidth control
Use this option to configure the maximum bandwidth that is allowed per client. In this case, even if the client accesses more than one share, the total bandwidth that is given to the client will not exceed the set limit. For example, if the client bandwidth is set to 100 Mbps, this client can perform operations on any share with only 100 Mbps speed.
Per share
(export)
-per client bandwidth control
Use this option to configure both per share maximum bandwidth and per client maximum bandwidth. In this case, the maximum client bandwidth is controlled to the set limit, while the maximum per share bandwidth is also maintained.

For example, if the per share bandwidth is set to 200 Mbps and the bandwidth per client is set to 100 Mbps, client A writing to this share will have a speed of 100 Mbps. If client B writes to the same share, client B will have a rate limit of 100 Mbps, as 100 Mbps is already in use by client A.

In bandwidth rate-limiting, you can configure the maximum read and write bandwidth individually. For example, you can set the maximum write bandwidth to 100 Mbps and the read bandwidth to 200 Mbps.

### Input/output operations (IOPS) rate-limiting

IOPS rate-limiting is a feature that controls the number of input/output operations per second that NFS clients can run on an NFS server. This helps prevent performance degradation, ensures fair resource allocation, and optimizes storage system efficiency.

Read and write operations consist of multiple underlying tasks. For example, a write operation includes four tasks: get file, open file, write file, and put file. If you set the IOPS limit to 20, only 5 IOPS allowed for each of these tasks.

The following are supported options in IOPS rate-limiting are:

Per share operations control
Use this option to configure the maximum number of IOPS allowed per share. In this case, QoS makes sure that the cumulative number of operations that are performed by all clients accessing this share will not exceed the given limit. For example, if the IOPS limit is set to 20, then any client accessing this share can run only 5 IOPS.
Per client operations control
Use this option to configure the maximum number of operations that are allowed per client. Regardless of the number of shares that the client is accessing, the total number of operations that are performed by the client will not exceed this limit. For example, if the IOPS limit for a client is set to 20, then this client can perform only 5 IOPS, irrespective of the number of shares it is accessing.
Per share-per client operations control
Use this option to configure the maximum that is allowed per share and maximum that is allowed per client operations. The total number of operations that are run by the client is controlled to the set limit. Simultaneously, QoS helps ensure the maximum operations per share limit is kept within the limits. For example, if the IOPS limit for share is set to 20 and the client limit is set to 40, then this client can run only 5 operations on the share as its limit is set to 20. The client can run the remaining 3 operations on other shares.

For IOPS rate-limiting, all operations that the client runs are counted together as a single unit.
