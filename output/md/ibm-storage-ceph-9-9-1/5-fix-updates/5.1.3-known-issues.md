## Known issues

Last Updated

This section documents known issues found in this release of IBM Storage Ceph.

Upgrade to
IBM Storage Ceph
9.9.1.1
or later can take longer than expected

When upgrading from IBM Storage Ceph 7.x, 8.x, 9.9.0.x, or 9.9.1.0, to IBM Storage Ceph 9.9.1.1 or later, the upgrade process can take significantly longer than in previous releases. In some environments, upgrade duration can increase by more than 100%.

This behavior occurs because `cephadm` rotates authentication keys for core Ceph services during the upgrade, migrating from the older `aes` CephX encryption scheme to the more secure `aes256k` scheme. The upgrade eventually completes successfully, but customers should plan for additional maintenance time.

Currently there is no workaround. For more information, see the [[Ceph] An upgrade to IBM Storage Ceph 9.9.1.1 is taking an extended time form completion](https://www.ibm.com/support/pages/node/7284989) [IBM Support](https://www.ibm.com/mysupport/) article.

(IBMCEPH-17825)

`cephadm`
host checks fail in FIPS mode when using ED25519 SSH keys

When FIPS mode is enabled on cluster nodes, `cephadm` host checks can fail if the stored cephadm SSH identity uses an ED25519 key. Because ED25519 keys are not supported in FIPS mode, `cephadm` cannot import the SSH private key and reports a KeyImportError('Unknown OpenSSH private key algorithm') error. As a result, managed hosts are marked Offline and the cluster raises a CEPHADM_HOST_CHECK_FAILED health warning.

As a workaround, replace the `cephadm` ED25519 SSH identity with a FIPS-compatible RSA key.

Verify whether
`cephadm`
is using an ED25519 key.

```plaintext-ibm
ceph cephadm get-pub-key
```

Copy to clipboard

If the output starts with
`ssh-ed25519`
, continue with the following steps.

1. Generate an RSA key pair on the administration host.

```plaintext-ibm
ssh-keygen -t rsa -b 4096 -f /root/cephadm_rsa -N ''
```

Copy to clipboard
2. Install the RSA public key on all Ceph hosts.

1. On the administration host, run the following commands:

```plaintext-ibm
mkdir -p /root/.ssh
chmod 700 /root/.ssh
cat /root/cephadm_rsa.pub >> /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys
```

Copy to clipboard
2. Copy the key to each Ceph host.

```plaintext-ibm
ssh-copy-id -f -i /root/cephadm_rsa.pub root@HOST_IP
```

(IBMCEPH-16272)

`ceph nvmeof`
commands can fail with
--server_address
when mTLS is enabled

When you run `ceph nvmeof` commands with the optional --server_address parameter against a gateway group that has mTLS enabled (`enable_auth: true`), the command can fail if the specified server address differs from the address that the Dashboard uses to connect to the gateway group. As a result, `ceph nvmeof` operations might not complete successfully when a non-default server address is specified.

As a workaround, do not use the --server_address parameter unless it is required. If you must connect to a specific server address, use the container-based NVMe-oF CLI instead of the `ceph nvmeof` command-line interface. This avoids the address validation issue and allows the operation to complete successfully.

(IBMCEPH-14168)

### Ceph NVMe-oF gateway

Using both
`ceph nvmeof`
and deprecated
`nvmeof-cli`
command parameters causes operation failure

When you use deprecated parameters together with the current `ceph nvmeof` command parameters in the same command, the operation fails and an error is returned. For example:

```
[root@host01 ~]# ceph nvmeof namespace add --nqn nqn.2025-09.io.ceph:baremetal-subsys-s1.group01 --gw-group group01 --rbd_pool replica3 --size 3 --rbd_image_name testimage --create-image --rbd_image_size 500G --trash-image

Error EINVAL: Can use size or rbd_image_size but not both
```

As a result, the operation is not completed.

To avoid this issue, use only parameters that are supported by the command that you are running. For example, use --rbd_image_size and do not use the deprecated --size parameter. For more information, see [Deprecated functionality in the IBM Storage Ceph 9.1 Release Notes](https://www.ibm.com/docs/en/storage-ceph/9.9.1?topic=991-deprecated-functionality).

(IBMCEPH-16419)
